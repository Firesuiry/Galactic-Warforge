# 多代理同阵营

同一个玩家（同一个 player key）可以有多个代理同时操作。每个代理绑一台机甲；背包、施工额度、手搓作业都按机甲各算各的。契约原文见 `docs/guide/多机甲协作.md`。

## 1. 身份

- 每个代理用自己的名字发令：`SW_ISSUER=builder-a scripts/sw <命令>`。命令会以 `issuer_type=agent`、`issuer_id=builder-a` 发出。
- 名字规则：`[A-Za-z0-9_.:-]`，1–64 位，**不能和玩家 ID 相同**（例如不能叫 `p1`）。
- 不设 `SW_ISSUER` 时，就是玩家本人（`p1`）在发令，和网页端是同一个身份。

## 2. 机甲

| 操作 | 命令 |
| --- | --- |
| 看所有机甲 | `mecha list`：操作者为 `(idle)` 的是空闲机甲 |
| 接管空闲机甲 | `mecha assign <机甲ID>`（操作者缺省为自己） |
| 替别人绑定 | `mecha assign <机甲ID> builder-b` |
| 解绑 | `mecha assign <机甲ID> --release` |
| 造新机甲 | 先把铁块 16、齿轮 8、磁线圈 8、电路板 8 装进基站：`transfer <基站ID> iron_ingot 16`，其余三样同理；再 `produce <基站ID> executor`。600 tick 后出厂，状态是空闲 |

- 一个发令者同一时间只绑一台机甲。绑新机甲时，旧的那台会自动变成空闲。
- 需要机甲的命令（build、transfer、craft_item 等）一律由**自己的机甲**执行，不用写机甲 ID。
- 命令不写 `--planet` 时，默认落在**自己机甲所在的星球**。
- 别人绑定的机甲你移动不了（`NOT_OPERATOR`）；空闲机甲谁都能移动。
- 机甲阵亡后会在基站复活，背包保留。

## 3. 互不干扰的约定（实测得出）

1. **分区**：每个代理在自己的区域里建，不碰别人的建筑。区域由主控方事先分好（坐标框）。
2. **共用仓库只取当下要用的量**：上一轮试玩中，铁块补给站被反复取空，有个代理之后长期只能取到 3–5 个。可以的话，给每个代理配一个专属补给点，或者让它先建自己的原料线。
3. **不要 `advance`**：快进是全局的，会让所有人的时间一起跳。
4. **对账只看自己的**：
   - `audit`：默认只看自己发的命令；
   - `planet_runtime --mine`：只看自己机甲的施工任务；
   - `briefing` / `mecha list`：显示的是自己机甲的背包。
5. **施工额度各算各的**：每台机甲同时 2 个施工；区域上限是 8×8 格内 4 个，这是全玩家共享的。两个代理不要挤在同一块 8×8 区域里同时施工。

## 4. 主控方怎么起一组代理

1. 准备 N 台机甲：用 `mecha list` 数一下，不够就到基站 `produce executor`。
2. 给每个代理分配：名字、机甲、施工区域坐标、目标产线、专属原料来源。
3. 用 `mecha assign <机甲ID> <名字>` 事先绑好，或者让代理自己接管指定的那台。
4. 代理之间不直接通信。冲突（例如共用仓库被取空）记在各自的报告里，由主控方协调。

agent-gateway 里的智能体会自动用 agentId 作为发令者。由 manager 用 `assign_mecha` 给下级分配机甲，详见 `docs/dev/agent-gateway.md`「发令者与机甲」。
