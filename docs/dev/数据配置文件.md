# 游戏数据配置

游戏目录以 `server/data/*.yaml` 为唯一数值来源，通过 `go:embed` 编入服务端。修改内置文件后须重新构建；客户端仍通过 `/catalog` 读取权威目录。

## 启动与覆盖

`config.yaml` 的 `server.game_data_dir` 可指定一套完整的外部游戏数据目录。为空时使用内置数据；非空时须提供下表全部七个文件，加载或引用校验失败会阻止启动，不做部分覆盖。相对路径以进程工作目录为准。

`server.data_dir` 是对局存档目录，不能用于覆盖游戏数值。两者用途不同。数据只在服务端启动时安装，不支持运行中热更新。

`server.checkpoint_dir` 是命名存档点根目录（试玩读档用，见 [服务端 API](服务端API.md) 6.9）；留空时 `/checkpoints` 系列接口返回 503，不影响启动。存档点目录只读，服务端只往 `data_dir` 写当前局存档。

```yaml
server:
  data_dir: ./runtime
  game_data_dir: ./my-game-data
```

## 文件结构

| 文件 | 顶层字段 | 内容 |
| --- | --- | --- |
| items.yaml | items、form_containers | 物品、堆叠上限、物质形态与容器映射 |
| recipes.yaml | recipes | 输入输出物品清单、生产时间、生产建筑与解锁科技 |
| techs.yaml | techs、pending_recipe_unlocks | 科技前置、研究成本、效果与解锁目标 |
| buildings.yaml | buildings | 血量、占地、物料造价、建造时间与 runtime 功能模块 |
| units.yaml | units、logistics_units | 世界单位战斗数值、造价、目录元数据与机甲参数 |
| combat.yaml | damage_coefficients | 武器类别 × 护甲类别的伤害系数 |
| war.yaml | base_frames、base_hulls、components、public_blueprints | 战争蓝图及其运行时档案 |

以仓库自带文件为完整模板；条目 `id` 必须唯一。YAML 未声明的字段会被拒绝，不能靠拼错字段静默使用默认值。物品、建筑、科技、配方及蓝图的引用均在启动时校验。

建筑条目直接包含建筑定义，可选 `runtime` 内含 `params` 与 `functions`；省略 runtime 时仅保留占地，不会自动附加生产能力。单位 `mecha` 段只用于玩家执行体，定义能量、背包、移动/攻击耗能与被动回能（`energy_regen_ticks`：每多少 tick 自动回 1 点核心，0/缺省为不回能；遭遇战默认 4）。`public` 决定世界单位是否出现在公共目录。

`pending_recipe_unlocks` 仅声明尚未实现的配方解锁并附理由，加载后从可用科技解锁中剔除。配方实现时应删除对应声明，否则校验报错。

战争蓝图（war.yaml）不再有 `producer_recipes`：单位不经配方生产，蓝图可见性由 `visible_tech_id` 门控；科技用 `special` 解锁 `blueprint_prototype/corvette/destroyer` 仅作面板展示。

## 验证

在 `server/` 执行 `go test ./internal/model ./internal/startup ./internal/query`。加载器测试覆盖内置数据、完整目录替换、未知字段与断裂引用；DSP 对齐测试直接针对加载后的注册表运行。
