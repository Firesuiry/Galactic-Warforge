## 2. 手动启动

### 服务端

```bash
cd server
PATH=$GO:$PATH go run ./cmd/server -config config-dev.yaml -map-config map.yaml   # 普通新局，端口 18080
```

| 场景 | 配置 | 用途 |
| --- | --- | --- |
| 普通新局 | `config-dev.yaml + map.yaml` | 从零开局 |
| 官方中后期 | `config-midgame.yaml + map-midgame.yaml` | 戴森、射线接收站、高阶建筑直测；`active_planet_id = planet-1-2` |
| 官方战争 | `config-war.yaml + map-war.yaml` | 预置军工底座，验证蓝图→量产→舰队→战区→封锁 |
| 遭遇战 | `config-skirmish.yaml + map-skirmish.yaml` | p2 为 bot，同面双出生点 |

`server.data_dir` 是单局存档目录：为空则新建一局，存在完整 `meta.json + save.json` 则续档，半残目录拒绝启动。重开新局可删目录或调用 `POST /games/new`（CLI `game_new`）。

### client-web

```bash
cd client-web && npm install
npm run dev                                     # http://localhost:5173，代理到 18080 / 18180
VITE_SW_PROXY_TARGET=http://localhost:5677 npm run dev -- --host 0.0.0.0 --port 5678
```

代理变量：`VITE_SW_PROXY_TARGET`（游戏服务端，默认 `http://localhost:18080`）、`VITE_SW_AGENT_PROXY_TARGET`（gateway，默认 `http://localhost:18180`，前端经 `/agent-api` 访问）。

### client-cli

```bash
cd client-cli && npm install
npm run dev                                     # 默认连 http://localhost:18080
SW_SERVER=http://localhost:5677 npm run dev
```

### agent-gateway

```bash
cd agent-gateway && npm install
npm run dev                                     # 端口 SW_AGENT_GATEWAY_PORT，默认 18180
```

## 3. 健康检查

```bash
curl http://localhost:5677/health
curl http://localhost:18180/health
curl http://localhost:5678/agent-api/health
```

三条都应返回 `{"status":"ok"...}`。第三条失败通常是 gateway 没启动，不是前端问题。

## 4. 客户端怎么选

- 推进科技、建造、排查命令链路：优先 CLI（命令见 [客户端CLI](客户端CLI.md)）。
- 看地图、详情、物流配置和操作回显：用 Web，**必须进浏览器实看**（建造、调兵、局势显示）。
- 常见组合：CLI 推玩法，Web 看局势。

试玩路径与勾选项见 [试玩验收清单](../player/试玩验收清单.md)。

## 5. 测试命令

```bash
# 服务端
cd server && PATH=$GO:$PATH GOCACHE=/tmp/gw-go-cache GOTOOLCHAIN=local go test ./...

# client-web：类型检查 + 单测 + 浏览器回归（Playwright，用例在 tests/*.spec.ts）
cd client-web && npx tsc --noEmit && npm test
cd client-web && npm run test:visual            # 更新截图基线：npm run test:visual:update

# client-cli / agent-gateway
cd client-cli && npm test
cd agent-gateway && npm test

# 命令覆盖门禁（server / shared / CLI / agent / GUI 指令面 + 命令文档是否过期）
python3 scripts/command_coverage.py --check
python3 scripts/command_coverage.py             # 打印覆盖矩阵

# 重新生成 服务端API.md / 客户端CLI.md 的命令一览
python3 scripts/gen_command_docs.py
python3 scripts/gen_command_docs.py --check
```

改了 server API 或 CLI 指令后，先改代码与目录，再跑 `gen_command_docs.py` 刷新文档，最后用 `command_coverage.py --check` 兜底。
