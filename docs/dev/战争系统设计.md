# 战争系统设计

本文描述战争系统**当前的实现**和**已拍板的设计**。设计依据见 [对局设计决策](../guide/对局设计决策.md)（重点 D7 与“单位系统合并方案”），阶段计划见 [整体规划](../guide/整体规划.md)，剩余缺口见 [缺失内容清单](../guide/缺失内容清单.md)。接口细节见 [服务端API](服务端API.md)。

## 1. 目标手感

- **戴森球的工厂 + RTS 大混战**：只借红警/星际的手感，不照搬内容。不做超级武器、EVA 播报、英雄/空降、防御墙；阵营不对称暂缓（D4）。
- **战斗力 = 产能 × 补给**：单位和弹药都由产线实物生产；单位自带弹药，打空且身边无补给就停火。补给线、弹药厂本身就是战场。
- **少而精的兵种，指挥军团**：一局几百个单位同时交战；玩家主要操作军团，必要时点单个单位。
- **先地面，后舰队**：第一阶段只做行星内地面战；舰队战、跨星远征属第二阶段。
- **数据驱动**：单位、建筑、弹药、克制系数都写在 `server/data/*.yaml`（格式见 [数据配置文件](数据配置文件.md)），Go 代码只保留类型和逻辑。
- **可解释、可代理**：所有战争操作都是标准命令，AI（bot / agent-gateway）与玩家走同一接口；蓝图校验、补给缺口、战报以结构化数据返回。

## 2. 两条单位线

| 线 | 运行时 | 用途 | 状态 |
| --- | --- | --- | --- |
| 世界单位（主线） | `model.Unit`，行星 `WorldState.Units` | 地面大混战的全部主力兵种 | 第一阶段主线，已实现 |
| 战争蓝图（后期改型） | 蓝图 → 军工队列 → 部署枢纽 → 小队 / 舰队 | 定制化后期单位、太空舰队 | 最小闭环已实现，降为后期内容 |

### 2.1 世界单位（`server/data/units.yaml`）

| 单位 | 职能 | 生产建筑 | 弹种 |
| --- | --- | --- | --- |
| `worker` | 工程兵 | `barracks` | 子弹 |
| `soldier` | 步兵，便宜量大、反步兵 | `barracks` | 子弹 |
| `scout` | 侦察车，快、视野大、弱 | `barracks` | 子弹 |
| `mecha` | 重装机甲，前排反装甲 | `vehicle_factory` | 炮弹 |
| `artillery` | 火炮，超远射程、有最小射程 | `vehicle_factory` | 炮弹 |
| `missile_vehicle` | 导弹车，防空兼反装甲 | `vehicle_factory` | 导弹 |
| `repair_vehicle` | 维修车，修复友军 | `vehicle_factory` | 无 |
| `supply_truck` | 补给车，随军补弹，可被截杀 | `vehicle_factory` | 无（自带弹药库存） |
| `attack_drone` | 攻击无人机，空中单位，只有导弹/防空能打 | `airfield` | 子弹 |

另有 `executor`（玩家机甲 / 执行体，英雄单位，可采集、手搓、战斗、在 HQ 复活）与 `dark_fog`（黑雾，不耗弹）。

每个条目定义血量、攻防、射程、移速、视野、冷却、`armor_class` / `weapon_class`、`ammo_class` / `ammo_capacity`、生产建筑、生产时间和**实物造价**（钢材、电路板、电动机等）。`produce` 从生产建筑自身库存扣料（皮带、分拣器或手动 `transfer_item` 供料），不再花 minerals/energy。生产建筑支持集结点（`set_rally_point`），出厂单位自动走向集结点。

### 2.2 移动与交战

- 实时移动：`move` 只下达路径，单位每 tick 沿路径推进；占位不重叠、侧移绕行，寻路预算上限 800 格。
- 自动交战：单位在射程内按冷却开火，对指定目标追击至射程内。
- 指令集（`unit_order`）：`attack_move` / `patrol` / `guard` / `hold` / `follow` / `retreat` / `stop`，支持框选批量。
- 结算顺序（所有已加载行星的 `planetary_runtime` 阶段）：单位移动 → 单位交战 → 炮塔。

### 2.3 克制系数（`server/data/combat.yaml`）

伤害 = 基础伤害 × `damage_coefficients[weapon_class][armor_class]` × 弹药档位倍率。武器类 `gun` / `cannon` / `missile` / `laser`，护甲类 `light` / `heavy` / `air` / `ship` / `structure`。例如 `gun` 打轻甲 ×1.25、打建筑 ×0.5；`missile` 打空中 ×1.5；`cannon` 打建筑 ×1.5。

## 3. 弹药与补给

### 3.1 三类弹药，类内分档

| 类别 | 物品（档位 → 增伤倍率） | 使用者 |
| --- | --- | --- |
| 子弹 `bullet` | `ammo_bullet` 1 → 1.0，`titanium_ammo` 2 → 1.25 | 步兵、轻载具、无人机 |
| 炮弹 `shell` | `shell_set` 1 → 1.0，`crystal_shell_set` 2 → 1.4 | 机甲、火炮、远程火炮 |
| 导弹 `missile` | `ammo_missile` 1 → 1.0，`supersonic_missile_set` 2 → 1.3，`gravity_missile` 3 → 1.6 | 导弹车、防空炮 |

补弹时优先装高档弹。燃料、备件、护盾电池、维修无人机已删除，不再是补给维度。

### 3.2 随身弹药

- 单位出厂带满 `ammo_capacity`（约够持续交战 30–60 秒），每发扣 1。
- 打空后状态为 `no_ammunition`：停火、只能移动；回到补给范围自动补满。
- 炮塔同样吃这三类弹药（端口装弹）；黑雾不耗弹。

### 3.3 前线补给

- **补给站** `supply_station`：建筑，库存由皮带或物流供给，按 `supply_radius` / `supply_rate` 给光环内的己方单位补弹（`settleAmmunitionSupply`）。
- **补给车** `supply_truck`：单位，自带弹药库存，在补给站自动装货，给附近友军补弹，可编入军团随行。
- 物流站、部署枢纽**不**参与补弹；只有补给站和补给车。
- 两者都是袭扰目标：攻击移动会优先打补给站、补给车和弹药厂。

## 4. 军团

- `form_squad` 把选中单位（可含补给车）编成军团；`dissolve_squad` 解散，单位保留当前指令。
- 军团（`model.CombatSquad`）**只是命令容器**：没有共享血条，血量、弹药、移动都属于成员单位；容器被移除不会杀死单位。
- `squad_order`：`attack` / `defend` / `retreat` / `resupply`（自动前往最近补给站）；按兵种和射程自动站位（炮在后、前排在前）。
- 旧的 HP 池小队字段仅为旧存档与战争蓝图运行态保留（P3 计划删除）。

## 5. 防御与防空

- 炮塔：`gauss_turret`、`laser_turret`、`plasma_turret`、`sr_plasma_turret`、`missile_turret`、`anti_air_turret`（只打空中，吃导弹）、`artillery_turret`（远程，吃炮弹）；`planetary_shield_generator` 提供行星护盾。
- 防空可击落敌方飞行中的物流无人机（`air_defense.go`）。
- 不做墙。

## 6. 对手

- **黑雾**：地图常驻第三方压力源，所有模式都存在，强度按难度参数；威胁随时间增长。
- **遭遇战 bot**：`players[].bot: easy|normal|hard`，服务端确定性 AI，走与玩家相同的命令队列（可重放、可审计）。会采矿、发电、建产线与弹药线、建补给站、出多兵种、编军团、带补给车出击并袭扰补给。
- **PvP**：同一套规则。三者可同时存在。

## 7. 战争蓝图线（后期改型）

蓝图把单位拆成 **底盘/船体 + 组件**，经校验、定型、量产、部署形成小队或舰队。数据在 `server/data/war.yaml`。

### 7.1 底盘与组件

- 地面底盘 `base_frames`：`light_frame` / `medium_frame` / `heavy_frame` / `assault_frame`。
- 舰船船体 `base_hulls`：`corvette_hull` / `destroyer_hull` / `cruiser_hull` / `carrier_hull` / `siege_hull`。
- 组件 `components`：动力（`micro_reactor`、`naval_fission_core`）、推进（`servo_drive`、`vector_thrusters`）、防御（`reactive_armor`、`escort_shield`、`point_defense_grid`、`ecm_suite`）、感知（`tactical_radar`、`battle_link_array`）、武器（`plasma_lance`、`swarm_missile_pod`、`coilgun_battery`）、功能（`field_repair_pack`、`drone_bay`）。
- 公开预置蓝图 `public_blueprints`：`prototype`、`precision_drone`（地面），`corvette`、`destroyer`（太空）。

### 7.2 校验约束

`blueprint_validate` 返回结构化问题列表，问题码：`unknown_base`、`unknown_component`、`required_slot_missing`、`hardpoint_mismatch`、`domain_mismatch`、`power_budget_exceeded`、`volume_budget_exceeded`、`mass_budget_exceeded`、`rigidity_budget_exceeded`、`heat_dissipation_insufficient`、`signature_budget_exceeded`、`maintenance_budget_exceeded`、`variant_slot_locked`、`invalid_state_transition`。即功率、体积、质量、刚性、热、信号、维护七类预算加挂点/域匹配。

### 7.3 生命周期与改型

状态机：`draft → validated → prototype → field_tested → adopted → obsolete`（`blueprint_finalize` 推进到下一态或指定态）。`blueprint_variant` 从预置或已定型蓝图派生改型，只允许修改 `allowed_slot_ids` 列出的槽位，其余继承父蓝图。

### 7.4 量产与部署

1. `queue_military_production`：在军工建筑排产，成品载荷进入部署枢纽（`/world/warfare/industry.ready_payloads`）。
2. `deploy_squad`：消耗地面载荷生成小队；`commission_fleet`：消耗太空载荷创建或增援舰队。
3. `refit_unit`：把小队或舰队送去翻修为目标蓝图。

`battlefield_analysis_base` 兼任最小部署枢纽。

## 8. 编组、战区与太空层

- **任务群**：`task_force_create` / `task_force_assign`（成员为小队或舰队）/ `task_force_set_stance` / `task_force_deploy`。姿态：`hold`、`patrol`、`escort`、`intercept`、`harass`、`siege`、`bombard`、`retreat_on_losses`。部署可带地面指令（`occupy` / `advance` / `hold` / `clear_obstacles` / `escort_supply`）和轨道支援模式（`none` / `fire_support` / `strike`）。
- **指挥带宽**：由指挥中心、指挥舰、战场分析基站、军事 AI 核心提供；超编带来惩罚。
- **战区**：`theater_create` / `theater_define_zone`（`primary` / `secondary` / `no_entry` / `rally` / `supply_priority`）/ `theater_set_objective`。战区是 agent 军事自治的边界。
- **舰队**：`fleet_assign`（阵型 `line` / `vee` / `circle` / `wedge`）、`fleet_attack`（同星系目标）、`fleet_move`（跨相连星系航行）、`fleet_disband`；同星系敌对舰队真实交火。
- **轨道封锁**：`blockade_planet` 以任务群封锁行星；同步 `accepted` 只表示入队，结果看 `/world/systems/{id}/runtime.planet_blockades`。
- **行星前线**：`/world/planets/{id}/runtime` 返回接触、前线和地面任务群。
- **情报分级**：传感器接触按 `unknown_signal` → `classified_contact` → `confirmed_type` → `fully_resolved` 四级给出，来源有视野、雷达、信号塔、侦察单位等。

登陆、轨道平台、轨道打击器已删除（U8），当前没有对应命令或实体。

## 10. 未完成方向（第二阶段及以后）

以下仍是设计方向，未实现；条目化缺口以 [缺失内容清单](../guide/缺失内容清单.md) 为准：

- 跨星远征、返航补给、玩家对玩家的完整太空战；太空黑雾。
- 凝聚度/士气与自动溃退；子系统伤害（失去机动、雷达、拦截）。
- 电子战与隐形对锁定、导弹的实质影响；导弹齐射与点防御拦截结算。
- 量产熟练度、切换蓝图的产线效率损失。
- 以“摧毁主基地 / 切断补给 / 占领工业星 / 持续制轨”为条件的多样胜利路径。
