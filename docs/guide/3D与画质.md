# 3D 与画质

目标：《戴森球计划》式星球工业观感（近景机械细节、自然地表、运行动画、光照、清晰操作）。服务端负责生产、物流、战斗、资源与权威坐标；前端只表现已收到的状态，不增添虚假的建筑、运输任务或情报。

> 2D 平面战术行星视图将在重构 P4 退役（先把 `data-entity-*` 测试钩子迁到 3D）；星图与战场仍用 Pixi。

## 1. 立方体球面网格（服务端与前端共用协议）

行星只有 `cube_sphere` 一种拓扑，配置 `planet.face_size: N`（默认 `map.yaml` 为 816，约 400 万格）。服务端保存六个 N×N 面，二维存储图集为 3N×2N；`map_width` / `map_height` 只是图集尺寸，不是经纬度或平面边界。旧 `planet.width/height` 配置与不含球面拓扑的旧存档直接拒绝加载。

面序号 `face = floor(y/N)*3 + floor(x/N)`，面内坐标 `(x%N, y%N)`：

| face | 法线 | 向右 U | 向下 V |
| --- | --- | --- | --- |
| 0 | +Z | +X | -Y |
| 1 | +X | -Z | -Y |
| 2 | -Z | -X | -Y |
| 3 | -X | +Z | -Y |
| 4 | +Y | +X | +Z |
| 5 | -Y | +X | -Z |

- 权威实现：`server/internal/surface/grid.go`（`frames`、`Step`、`Normal`、`FromVector`）；前端镜像 `shared-client/src/surface.ts`。两端用 `server/internal/surface/cmd/fixtures` 生成的 `shared-client/src/surface-fixtures.json` 做跨语言几何/方向样例对拍。
- 等角投影：面内 u/v 映射到 [-π/4, π/4]，方向 = normalize(N + tan(u)·U + tan(v)·V)。两极位于完整面内部，无经纬汇聚；边角仍有受控形变，不保证所有格子完全等大。
- `FromVector` 主轴并列时依次优先 Z、X、Y，浏览器与地形着色器一致。
- 邻接只由球面四邻接图决定（`Step` 为纯整数图运算）：图集相邻像素不一定是地表邻居，图集外边缘也不是世界边界。客户端禁止对 x/y 取模、夹紧或直接加减代替邻接。范围、寻路、视野、资源团簇、出生区都用服务端球面图。
- 方向：每格有 north/east/south/west 面内方向，跨边后方向随面旋转；传送带出口、分拣器、建筑端口、仓储/电网连接使用同一套方向运输规则。
- 多格建筑按锚点面内偏移运输到相邻面，占据、施工预留、完成、拆除、摧毁、存档恢复都处理全部占地。宽高不得大于面宽；绕立方体角点导致自重叠时拒绝放置。
- 建筑布局蓝图的矩形选区、旋转与粘贴限于单面（跨接缝结构分面建蓝图）；单体建筑、物流、单位可跨面。与战争单位蓝图无关。

### scene 查询与补片

- 状态、行星查询、快照都带 `surface: {topology: "cube_sphere", face_size: N}`。
- `GET /world/planets/{id}/scene` 的 `x/y/width/height` 是图集矩形裁剪；可同时传 `near_x`、`near_y`、`radius`（0..128）获取按球面图距离计算的邻域 `surface_patches`。每片有独立 `bounds/terrain/visible/explored`；主 `buildings/units/resources` 合并补片实体并去重。绘制须按每片 bounds 读坐标与迷雾，未探索补片为 unknown，不得从相邻图集像素推测地表。
- CLI：`scene planet-1-1 0 0 32 32 --near_x 0 --near_y 16 --radius 16`。
- 建造前自动靠近：请求 `/world/planets/{id}/path`，以执行体 `operate_range` 作 `stop_range`，按返回 waypoints 移动；范围内返回空 waypoints；不可达/未知目标不得继续自动建造，每段移动后处理权威失败回执。

## 2. 3D 场景实现

- 操作：行星与恒星系页默认 3D（右上可切平面战术）；拖动旋转、滚轮/按钮缩放、俯仰滑条；全球视角拉远、聚焦基地返回近景；点建筑/单位看详情，建造栏选建筑后点地表放置，选中单位后点地表移动；Esc/右键取消指令模式。
- 代码：`client-web/src/features/planet-map/planet-three-scene.ts`（场景、镜头、输入、快照同步）；`three/` 拆为投影（`projection.ts`）、地表（`local-surface.ts`、`terrain.ts`、`surface-dressing.ts`）、工业资产（`industrial-models.ts`、`industrial-finishes.ts`）、合批（`static-batches.ts`、`dynamic-batches.ts`）、运行表现（`industrial-activity.ts`、`conveyor-geometry.ts`、`sorter-animation.ts`、`logistics-flight.ts`、`combat-effects.ts`）、画质（`render-quality.ts`）与空间（`space.ts`）；恒星系为 `system-three/`。
- 地表：按面独立生成 mesh，overview 降采样 step 整除 N，不跨面混合；点击、选中圈、建筑姿态与尺寸用同一球面映射。未知区域用扫描蒙层；不可建造岩地生成局部岩脊（排除实体占地，最多 4000 个装饰实例）；真实水域有动态水波、按已探索相邻陆地计算的浅滩与泡沫（遵守跨面邻接，未知边界不生成猜测海岸）。
- 合批：工业资产共享模板几何/材质；`StaticBatches` 按图层/几何/材质跨建筑实例化静态部分，`DynamicBatches` 独立合批转子、钻头等动画子树，只更新变化的姿态；生产状态变化与世界旋转不重建静态实例。实例射线拾取映射真实建筑地块。
- 运行表现：`IndustrialActivity` 由真实传送带 buffer、运行状态、生产剩余 tick、物流位移生成货物、火花、热气与尾迹，暂停设备停止机械动画；矿点枯竭不播采矿火花。连续传送带合并为一条运输链（整网约 3 个绘制批次），按服务端 `runtime.params.io_ports` 连接矿机、熔炉、仓库、物流站端口。分拣器仅在 `runtime.state=running` 且收到新 `last_transfer` 时播放机械臂；记录上次观察 tick，慢刷新时两次快照间的新搬运也播放一次，陈旧/重复/未来记录不播放；当前搬运完成后才切换下一条路线。建筑占地内的矿石露头压低为地表矿层（仅表现）。
- 恒星系：`system-three/` 绘制恒星日冕、已发现行星与后端提供的戴森节点/框架/球壳/太阳帆；轨道相位 API 未提供，按态势示意标注；runtime 不可用时隐藏。
- 调试：`?freeze=1` 冻结截图；DEV 下 `window.__planetThree.project(tile)` 只辅助定位画布点击，验收必须核对真实 POST 与后端最终状态。

## 3. 画质档位

3D 视角控制「画面质量」可实时切换，偏好存浏览器本地；`?quality=low|balanced|high` 可覆盖，便于复现验收。

| 档位 | 最大像素比 | MSAA | 阴影 | 辉光 |
| --- | --- | --- | --- | --- |
| 流畅 | 1 | 关闭 | 1024 | 关闭 |
| 均衡（默认） | 桌面 1.75 / 窄屏 1.25 | 桌面 4× / 窄屏 2× | 桌面 2048 / 窄屏 1024 | 开启 |
| 精细 | 2 | 4× | 4096 | 开启 |

宽度 < 768px 用窄屏预算；MSAA 不超过设备支持值，像素比不超过设备像素比。composer 离屏目标显式设置 MSAA；切换时只重建帧缓冲与阴影贴图，保留建筑、镜头和操作状态。大气太阳方向与主光源统一。软件 WebGL 的耗时不代表真实 GPU 帧率。

## 4. 玩家工业入口

行星左上「生产规划」「发展路线」（工作台「生产」「发展」标签同源），3D 与平面共用：

- 生产规划：诊断当前载入区域己方设施（暂停/缺电/未配置/加工中/下一批缺料/原料就绪）；原料缺口以本地 inventory 与 input_buffer 为准，不计 output_buffer。「定位并操作」选中真实建筑并打开详情。配方可按名称/ID/产物搜索，按批次列出原料、产物、副产物、单批时长（仅规划，不排产不发资源）；「建造」带配方进入放置，以服务端结果为准。
- 发展路线：六阶段实时检查清单——①落地与供电 ②自动化工厂 ③矩阵与科研 ④行星物流 ⑤星际工业 ⑥戴森能源。科技前置来自 catalog，完成状态来自玩家状态，设施目标只查当前载入区域；不是成就或奖励系统。

## 5. 素材

- 工业建筑、车辆、飞船、矿簇全部由 `three/industrial-models.ts` 原创程序化建模（金属/陶瓷/玻璃/发光共享材质），不引用《戴森球计划》模型或贴图。
- 表面细节由 `three/industrial-finishes.ts` 运行时确定性生成 9 张 256×256 纹理（陶瓷接缝与紧固点、拉丝合金、格栅；颜色 sRGB、粗糙度/法线线性，启用 mipmap），无外部下载。
- 建造栏缩略图 `client-web/public/assets/buildings/*.png`：同一模型的 256×256 透明渲染，覆盖全部建筑类型。重建：先起 Vite（默认 4173），运行 `node develop_tools/three_assets/render.mjs [vite地址]`，联系表输出 `/tmp/industrial-assets.png`。
- Kenney Space Kit（CC0）GLB 已在 P0 移除（从未被加载），仅保留许可 `client-web/public/assets/space/License.txt`；如需重新引入，以场景代码的类型映射为准，不因素材新增服务端不存在的实体。
- Orbitron 字体随客户端本地提供（`client-web/public/fonts/orbitron/`），不依赖 Google 字体 CDN。

## 6. 运行与验证

隔离战争测试服（仓库根）：

```sh
bash server/scripts/start_official_war_test_server.sh 19481
```

`client-web/`：

```sh
VITE_SW_PROXY_TARGET=http://127.0.0.1:19481 npm run dev -- --host 127.0.0.1 --port 4173
npm test && npm run build
SW_SKIP_WEBSERVER=1 npx playwright test tests/planet-three.spec.ts tests/system-three.spec.ts tests/industrial-development.spec.ts tests/cube-surface.spec.ts --workers=1
SW_TEST_MAP="$PWD/../server/testdata/map-cube-poles.yaml" SW_CUBE_POLES=1 SW_BACKEND_PORT=19482 SW_WEB_PORT=4174 npx playwright test tests/cube-poles.spec.ts --workers=1
```

- 浏览器用例使用真实服务端（p1），核对旋转缩放、详情、建造/移动请求与后端结果、模式退出、平面/3D 切换、画质切换、390px 操作，并检查页面与 WebGL 错误。测试服状态会变，重复验收自动选可用地块。
- 极区用例使用 `map-cube-poles.yaml`（N=48，两名玩家位于北/南极面中心），验证极区建造、移动与局部精细曲面加载。
- 服务端几何：`go test ./internal/surface/...`；并发：`go test -race ./internal/surface ./internal/visibility ./internal/query ./internal/model ./internal/gamecore`。
- 运输可视化回放见 [星球玩法覆盖与验收](星球玩法覆盖与验收.md) §回归脚本。

## 7. 待改进

- 仍为程序化工业模型，近景材质与地景密度有提升空间；未达到原作完整美术水平。
- 未做混合建筑+完整后处理大场景的整帧耗时、距离 LOD 与真实移动端硬件验证（千栋同类工厂的绘制调用对照不能替代）。
- 真实战争服缺少大面积海岸，海岸视觉验收待完成；不得为截图虚构地形。
- 运输船跨星球表现：runtime 按归属星球列船，异星目的站降落/等待的船暂不在当地画面出现。
