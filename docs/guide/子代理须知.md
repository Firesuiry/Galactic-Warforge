# 子代理须知

派给子代理的任务都应先让它读本页。规则来源：第 15 轮开发的实际踩坑。

## 开工

- 先读 `AGENTS.md`、本页、任务指定的设计文档；大文件只读需要的段落，命令输出用 `head`/`tail` 截断。
- 只在自己的 worktree 改代码和提交；**不碰主工作区、不 `git stash`、不合并 main、不 push、不通知用户**（这些归主代理）。
- 基于别的分支开工时用 `git merge <分支>`，**不 reset / 不改写已有提交**（别的分支可能已 merge 过你）。

## 防中断

- 每完成一步就 commit（结尾 `Co-Authored-By: Claude Opus 5.5 (1M context) <noreply@anthropic.com>`），报告草稿随时写盘。
- 接手中断任务：先看 `git log main..HEAD`、`git status`、`git diff` 和已有报告，从断点继续，不重做。

## 环境与端口

- 起停一律用 `bash scripts/playtest-up.sh <N>` / `playtest-down.sh <N>`（见 [试玩速查](试玩速查.md)）；端口 = `N*100` 服务端 / `+1` Web / `+2` 驱动，**每个代理一个独立 N**，不共用长期运行的服务端。
- 避开 8080、18080。结束前 down 掉自己起的进程，只按自己记录的 PID 杀，**不用 `pkill -f` 宽匹配**（会误杀别人或自己的 shell）。
- Go：`/home/firesuiry/sdk/go1.25.0/bin`（或 `/mnt/wsl/data/...`），加 `GOCACHE=/tmp/gw-go-cache GOTOOLCHAIN=local`。
- Write/Edit 工具不能写 worktree 外路径；要写主工作区 `tmp/` 的报告，先写 `/tmp/...` 再 `cp`。

## 试玩

- 测试分两部分：**逻辑测试**由 `checkpointbuild` 按 build 记录用 API 逐层建档（只用玩家命令 + 快进，禁止管理员发料），每层契约即逻辑断言，所有存档点都由它产出；**操作测试**只点 UI，只测本次改动涉及的操作，从逻辑测试建好的存档点读档（`--checkpoint <名>`）起步。
- 操作测试缺起始场景时，先补一层 API build 记录生成存档点，再用 UI 测；不在 UI 里从零手搓场景。
- 等待段用快进 `advance`（调试面板 `Ctrl+Shift+D`）。
- 改动涉及前期（经济/机甲/建造 UI/地图）时，加跑一次纯 UI 从 cp-root 开局。
- 验收步骤只点 UI；只读 API 可用来核对数字。截图放报告指定目录，文件名带步骤前缀。
- 新局配置以 `data/meta.json` 为准：`POST /games/new` 会继承当前局的 battlefield，改 yaml 不一定生效。

## 测试

- 只跑改动相关的定向测试 + `go test ./internal/gamecore/ -short`（约 7 分钟）；整局回归/from-zero 长模拟由主代理合并前统一跑。
- 契约里列出的边界用例（如混合物品的带子）必须有对应测试；多种子长测试用并行子测试。
- 改了 server API 行为或 CLI 命令：更新 `docs/dev/服务端API.md` / `客户端CLI.md`，跑 `python3 scripts/gen_command_docs.py` 与 `command_coverage.py --check`。
- Playwright `--workers=4`，失败先确认是否场景被前一轮污染（换新服重跑），再判断是不是回归。

## 汇报

- 最终回复写：分支、commit 列表、测试原始数字、截图/报告路径、遗留问题（按严重度）。只报事实，测试没跑或失败要明说。
