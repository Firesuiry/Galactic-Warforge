# 对局设计决策（D 系列拍板）

来源：`docs/guide/缺失内容清单.md` 第 1 节。本文档是 M1 开工前拍板的权威记录，后续实现以本文为准。
拍板日期：2026-09-28。

## D1 对局时长与主模式

- **主模式：60–90 分钟对抗遭遇战**（1v1 或 玩家 vs 黑雾+ bot）。配套压缩：遭遇战地图缩小（每面 64–128 格）、工业链走"压缩节奏"（研究/建造/产出数值按主模式配置缩放，不改目录 ID）。
- **辅助模式：长局沙盒 / PvE 生存**，沿用现有大地图与完整 DSP 工业节奏。
- 落地方式：新增"遭遇战"地图与战场配置（map-skirmish.yaml + battlefield 节奏参数），不动默认大图。

## D2 玩家视角与建造

- 机甲保留为**英雄单位**（采集/手搓/战斗/复活），不再承担全部建造。
- 建造改由**建造半径**判定：玩家在己方任一"建造中心"（HQ/前哨类建筑）半径内随手建造，由建造无人机（视觉）执行；机甲 6 格限制仅作为无建造中心时的兜底。
- M1 阶段先落地"建造半径"判定（HQ 半径内可建），建造无人机实体化随 I16 一起做。

## D3 主要对手

- 黑雾 = 地图常驻第三方压力源（PvE，所有模式下存在，强度按难度参数）。
- 遭遇战 bot = 服务端确定性 AI（A1），走与玩家相同命令接口。
- PvP = 同一套规则的多人模式。
- 三者不互斥：遭遇战可同时存在 bot 与黑雾。

## D4 阵营不对称

- **暂缓**。M1–M3 不做阵营；科技分支（外源科技）在 M4 依据届时反馈再议。README 承诺保留，代码不预埋死骨架（符合 U8"实现或删除"原则）。

## D5 AI Agent 定位

- 两者都支持：顾问/托管（现状 agent-gateway）+ 对手（A1 确定性 bot 为基线，A2 LLM 对手为 M4 可选增强）。

## D6 经济双轨

- **保留双轨，划清边界**：
  - `minerals`/`energy`（指挥资源）：仅用于军事生产（军工队列）、防御建筑与建筑抽象建造成本——红警侧。
  - 实物物品：DSP 工业链唯一形态，军事单位不再以"物品"形式进背包（见 U3 合并方案）。
- 矿机溢出照扣矿脉以保 minerals 收入的行为保留（指挥资源的经济来源），不再视为缺陷。

## D7 游戏感觉、弹药与单位经济（2026-09-29 拍板，修订 D6）

### 目标手感
- **只借红警/星际的感觉，不照搬内容**：超武、EVA 播报、英雄/空降、防御墙都不做。
- **大混战，而不是微操**：一局几百个单位同时交战，节奏更接近《横扫千军》《最高指挥官》；兵种职能像星际一样清楚、少而精。玩家主要指挥**军团**，不需要逐个单位点。
- **战斗力 = 产能 × 补给**：工厂产出单位和弹药，补给线把弹药送到前线。缺弹就停火，所以打对方的补给线、弹药厂是正经战术，拼的不只是兵多。
- **星际战争的防御**：靠炮塔、行星护盾、防空和火炮，不做墙。
- **战场阶段**：前期打地面战，后期打舰队战。M2 只做地面大混战；舰队战和跨星战争放到 M3 及以后。

### 拍板
1. **单位造价实物化**：军事单位（以及炮塔等防御建筑）由产线实物造（钢材、电路板、电动机、处理器等），不再花 minerals/energy。D6 的"minerals/energy 用于军事"作废；剩下的建筑抽象成本另议。
2. **弹药三类，类内分档**：
   - 子弹：步兵和轻载具用，对应 DSP 的 `ammo_bullet` → `titanium_ammo` 等；
   - 炮弹：重装甲和炮兵用，对应 `shell_set` → `crystal_shell_set`；
   - 导弹：防空和反装甲用，对应 `ammo_missile` → `supersonic_missile_set` → `gravity_missile`。
   - 高档弹增伤，给产线升级一个战斗上的理由。
   - 蓝图小队原来的 6 维补给精简到这三类。燃料、备件、护盾电池、维修无人机砍掉，维修改由维修单位或维修站负责。
3. **随身补给**：每个作战单位出厂时自带一定量的弹药，每发扣弹，量按兵种在配置里定，大约够持续交战 30–60 秒。用完后如果身边没有补给（补给站光环或补给车），就停火、只能移动；一回到补给范围就自动补满。
4. **前线补给**：
   - 补给站：建筑，从产线或物流取弹，给光环范围内的己方单位自动补弹；
   - 补给车：单位，能跟随军团，自身弹药库存有限，可以被截杀。
   - 两者都是袭扰目标（U9）。
5. **单位主线**：世界单位（`model.Unit`）做主线兵种，职能写死。设计器和蓝图降为后期"改型"。
6. **军团**：单位 → 军团（编组）。军团只是命令容器，不是 HP 池：共享指令（进攻/防守/占领区域/撤退）、共享编队站位、自带补给车。玩家主要操作军团，也可以单独点单位。现有 `CombatSquad` 的 HP 池小队随之重构。
7. **D4 阵营**：继续暂缓。
8. **数据配置化**：所有建筑、兵种、资源（物品）、配方、科技都在配置文件里定义特性，包括血量、造价、产出、射程、伤害、弹种、随身弹药量、解锁条件等。Go 代码只保留类型和逻辑，不再写数值。
   - 格式：YAML，放在 `server/data/`，按类别分文件；用 go:embed 内置为默认数据，`config.yaml` 可以指定 `data_dir` 整套覆盖，方便调平衡。
   - 启动时校验：引用必须能解析（配方里的物品、科技解锁的建筑等），失败则拒绝启动。
   - 初始数据由现有 Go 定义导出生成，不手抄；导出后删掉 Go 里的字面量。黑雾单位、克制系数表也一起进配置。

## 单位系统合并方案（M1 核心架构决策）

现状三套并行：世界单位（`model.Unit`：worker/soldier/mecha/executor）、战争蓝图小队/舰队（`CombatSquad`/`SpaceFleet`）、测试专用 `CombatUnit`。

拍板：

1. **地面战斗统一为 `model.Unit` 一套系统**。
   - `CombatUnit`/`CombatUnitManager`（仅测试使用）删除；其自动索敌、护盾、冷却逻辑并入世界单位 Tick 结算。
   - `model.Unit` 扩展：实时移动（路径+速度逐 tick 推进）、战斗状态（目标/冷却/指令姿态）、护甲/武器类型（R6 用）。
2. **`CombatSquad` 实体化**：获得 `Position` 与移动能力，作为"编组战斗群"参与同一套移动/交战结算；HP 池按伤害减员（Count 下降），全灭移除。可攻击黑雾、敌方单位与建筑（R4）。战争蓝图层（设计器/特遣队/补给）保留，是"高级军工"产线。
3. **`SpaceFleet` 保留太空层**：M1 只补"同星系敌对舰队真实交火"（R4 舰队部分的最小版），跨星航行与补给线属 M3。
4. **生产合一（U3 方向）**：地面军事单位由军工产线产出后**出厂即实体**（单位或小队落到行星表面），不再有"单位物品进背包"和"无坐标小队"两种幽灵形态。制造台的 worker/soldier/mecha 物品配方改为直接产出世界单位（产线成品即单位）。

## 结算顺序约定（M1 起生效）

`settlement_pipeline.go` 的 `planetary_runtime` 阶段（所有已加载行星）新增：
`settleUnitMovement`（单位移动）→ `settleUnitCombat`（单位交战）→ 炮塔（既有）。
`active_world_runtime` 中黑雾相关结算随 E1 改造移入 `planetary_runtime`（配合 F4 方向：所有已加载行星都结算战斗与敌人）。

## 附：M2 大件实现要点（2026-09-29 补）

### A1 遭遇战 bot
- 配置：`players[].bot: easy|normal|hard`（空 = 人类）。bot 走与玩家相同的命令接口（QueuedRequest 入队），天然可重放、可审计。
- 驱动：pipeline 每 N tick（难度 60/30/15）对每个 bot 世界运行决策：采矿（执行体空闲时 mine_resource 最近矿点、低能 refuel）→ 电力（低于阈值建风/光，走建造半径）→ 产线（矿机进矿点、制造台）→ 出兵（produce soldier 到阈值）→ 进攻（兵力 ≥ 阈值（6/10/16）时 attack_move 敌方基地中心）→ 防御（黑雾临近时建炮塔）。
- 确定性：同 tick 同世界状态同决策（无 wall-clock，平局按实体 ID 排序）。
- 验收：新手能打赢 easy；hard 30 分钟压垮不设防玩家；bot 对局可 /replay。

### F1 新局与大厅
- 新增 `POST /games`（新局设置：地图/玩家/AI/难度/胜利规则）与大厅态；服务端进程从"一局一生"改为可多局并存（GameCore 按 game_id 路由）——分两步：M2 先做单局热重置（/games/new 重建 GameCore + 状态清理），多局并存放后。
- 登录保持 YAML 静态 key，新增 role=admin 才可开新局。

### R6 客户端显示
- 单位卡片显示 armor_class/weapon_class 与克制关系（读 /catalog 的系数表或静态映射）。
