# 传送带与分拣器浏览器回归

2026-09-16：验证矿机 → 连续皮带 → 分拣器 → 转弯皮带 → 电弧熔炉 → 仓库。

## 复现与修复

- 矿石露头与建筑共用地块时，原高度会穿入皮带和分拣器底座。建筑占地内矿石现在压低为地表矿层；拆除建筑后恢复露头。只改变表现，不改变矿藏或开采规则。
- 原机械臂只接收距场景快照不超过 20 tick 的搬运。慢刷新时，新搬运也可能超过此期限，导致仓库增长而机械臂静止。现在记录上次观察 tick，两次快照之间发生的新搬运也可播放一次；首次进入时的陈旧记录、重复序号、未来记录及停机不播放。
- 原 CLI 回放先建矿机并等待运行，在当前配置供电不足时卡住。现在先在 `(4,1)`、`(5,1)`、`(6,1)` 补风机，再连接产线。

## 隔离环境

在仓库根目录准备独立配置（已有文件/存档时请换新的目录）：

```bash
mkdir -p /tmp/sw-transport-fix
sed -e 's/port: 18080/port: 19489/' \
    -e 's|data_dir: "data-war"|data_dir: "/tmp/sw-transport-fix/data"|' \
    -e '/        - electromagnetism/i\        - dyson_sphere_program' \
    server/config-war.yaml > /tmp/sw-transport-fix/config.yaml
```

核对 `server.port` 和 `server.data_dir` 后，在 `server/` 启动：

```bash
/home/firesuiry/sdk/go1.25.0/bin/go run ./cmd/server -config /tmp/sw-transport-fix/config.yaml -map-config map-war.yaml
```

在 `client-web/` 启动代理：

```bash
VITE_SW_PROXY_TARGET=http://127.0.0.1:19489 npm run dev -- --host 127.0.0.1 --port 4179
```

在仓库根目录顺序执行：

```bash
SW_SERVER=http://127.0.0.1:19489 SW_TRANSPORT_EVIDENCE=/tmp/sw-transport-fix client-cli/node_modules/.bin/tsx scripts/playtest-transport.ts
SW_TRANSPORT_WEB=http://127.0.0.1:4179 SW_TRANSPORT_EVIDENCE=/tmp/sw-transport-fix node scripts/playtest-transport-browser.mjs
```

产线由 CLI 真实建造，浏览器使用公开服务端数据。回放环境预先解锁科技并发放建造资源；本测试不代表普通新局科技推进验收。分拣器当前验证范围为皮带之间搬运。

- 修复皮带只识别其他皮带的问题：现在按服务端公开的 `runtime.params.io_ports`、端口偏移、所属玩家及进出方向连接矿机、熔炉和仓库，皮带伸入建筑底座接口。矿机侧向出料会自然转弯；无端口、敌方、方向不兼容的建筑不连接。分拣器仍保留真实机械臂搬运间距，不伪造贯穿底座的皮带。
