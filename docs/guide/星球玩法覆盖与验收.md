# 星球玩法覆盖与验收

目标：把《戴森球计划》(DSP) **行星内可完成**的全部设施、生产内容与科技树玩法（含玩家机甲）落地并验证。目录条目、模型、可建造标记、只断言类型存在的单元测试都**不能**单独证明玩法完成。

## 1. 范围与验收口径

### 范围定义（冻结）

"行星内可完成" = 以行星可得原料（矿脉/油苗/水/硫酸海/机甲采集）为种子，仅用可放置在行星表面的机器，经配方闭包可达的全部物品与可研究科技。

- 机器白名单（19 类）：采矿机、大型采矿机、抽水站、原油萃取站、电磁熔炉、位面熔炉、制造台 Mk.I/II/III、化工厂、量子化工厂、原油精炼厂、分馏塔、微型粒子对撞机、矩阵研究站、能量枢纽（蓄电器充放循环）等。
- 排除（太空/黑雾专属）：轨道采集器、射线接收站系 → 临界光子链/反物质/宇宙矩阵/黑雾专属材料行星内不可达（数据保留，状态标 `gated`）。
- 种子资源 18 种：铁/铜/石/煤/硅/钛矿脉；可燃冰、金伯利、分形硅、光栅石、刺笋结晶、单极磁石、有机晶体（稀有矿脉）；原油、水、硫酸（抽取）；木材、植物燃料（机甲采集）。

冻结数字（闭包计算结果，须由测试守住）：

| 项 | 目标 |
| --- | --- |
| 行星内可达物品 | 428 / 486 |
| 行星内生产配方（含建筑合成） | 171 |
| 科技节点 | 304（行星内可研究 270，其余 `gated`） |
| 行星内可制造建筑 | 59 / 62（不可达 3 个为黑雾版机器等） |

数据工具链：`develop_tools/dsp-catalog/`（见其 README）。原始快照为 factoriolab `public/data/dsp`（DSP 0.10.29.21950）+ dsp-wiki TechInfo 哈希；`scope.json`=冻结闭包，`mapping.json`=未匹配清单。用 `go run ./cmd/catalogdump -out current_dump.json`（在 `server/`）导出当前目录后跑 `build_scope.py` 即得差距。

数据结构要点：研究消耗按"矩阵秒"结算——DSP 原始 in=每点消耗物品数、out=总 hash 点数，实现按 `hash = out / in` 折算为每秒消耗速率，测试守住等价折算。

### 验收标准

1. 目录一致性：`server/internal/model/dsp_alignment_test.go` 目前只比对 ID 闭包（物品/配方/科技/建筑在冻结范围内），**不**比对数量。数值级 parity 仍是缺口（约 24 个配方与 `scope.json` 不一致，见 [缺失内容清单](缺失内容清单.md) I1），不得把"ID 对齐"写成"逐项数值一致"。
2. 物品闭包：每个行星内物品都存在从种子资源出发的生产链。
3. 科技闭包：270 个可研究科技前置链完整、矩阵消耗行星内可产。
4. 引擎 e2e：空行星起步，脚本化建设到产出矩阵并解锁科技，全程 Tick 结算无错。
5. 浏览器：client-web 可见可操作（放置、配方生产、科研）。

单项设施完成的判据：**正常新局科技/原料可达 → 公共 API 与玩家操作可达 → Tick 真实结算 → 缺电/缺料/堵塞边界 → 存档/重放 → 浏览器实测**。未验证项一律保持"部分完成/待完成"。

### 关键运行规则

- **通用生产欠压**：按当前电力分配比例积累工作量，`progress_fraction` 保留不足 1 tick 的进度；无电不启动/推进/提交；满仓不积攒下一批进度、不重复吞料；存档保留小数进度。
- **同物料进出的配方**（如精炼）：原料留在库存/输入缓存，产物进输出缓存，完成前不能被输出口抽走；输出满时整批等待。
- **物流站**：PLS 3 槽×200、基础电 1、电池 1000、充电 ≤10/tick；ILS 5 槽×500、基础电 2、电池 10000、充电 ≤30/tick。库存唯一存于 `logistics_station.inventory`，初建无库存/电量/端口/载具。四向皮带口各 6/tick，带剩余喷涂用途的货物在入口背压。载具不免费生成：安装逐件扣真实成品（默认 `--source player` 扣背包，`--source station` 扣站库），无人机上限 10、船上限 5；配方：无人机 2 电动机+2 处理器+5 铁锭/120 tick，运输船 2 电动机+10 处理器+10 钛合金/300 tick。起飞预扣往返能源：无人机 `2*max(1,distance)`，船普通 `10*distance`、曲速 `30*distance` 且扣 2 个 `space_warper`（不足则退为普通）。满仓部分卸货，余货 `waiting_unload/destination_full` 保留；归属站失效则 `stranded/home_unavailable`（尚无回收命令）。删除槽位须无库存、无皮带引用、无在途。
- **玩家机甲（executor）**：`refuel_mecha` 从背包扣有效燃料，余热留存；移动按路径格数耗能、攻击耗能；`mine_resource` 2 格球面距离内 10 tick/件、1 能/tick；`craft_item` 仅限目录 `handcraft_allowed=true` 且科技可用的固体配方，预留原料，`cancel_mecha_job`/死亡只退未完成批次；无线输电塔 6 格内 ≤10/tick、电力感应塔 4 格内 ≤2/tick 用同网真实余电充能。核心、引擎、护盾、研究速度科技在真实结算点生效。

### 已知全局缺口

- 玩家机甲：飞行、冲刺、建造无人机、装备、多格燃料仓仍未实现（死亡重生已有 `gamecore/mecha_respawn.go`）。`mecha` 仍是量产地面战斗单位，不等于玩家机甲。
- 自动集装机已按堆高压缩（`conveyor_settlement.go` 的 `pileHeightFor`），但集装分拣器整堆抓放与真实叠层增运仍待验收。
- 普通 Storage 仍是数量映射：皮带→普通机器会丢喷涂元数据；通用配方额外能耗与喷涂电力倍率未进电网。
- 其余科技效果须逐项核实是否在结算点生效，不能据目录声明认定。
- 土壤/沙土经济、矿机按覆盖脉数产量、昼夜/潮汐锁定、储液罐入管网、射线接收器透镜增益等深化项按需核实后并入 [缺失内容清单](缺失内容清单.md)。2026-09-17 审计的 A（配方物品）/B（能源）批次大部分已落地（钢、金刚石、棱镜、增产剂 Mk.III、引力透镜、曲率器、推进器、戴森组件、蓄电器物品、氘棒、稀有矿、植被物品等均已入目录），原审计全文可从 tag `pre-refactor-2026-10` 找回。

## 3. 回归脚本

浏览器回放都需要**隔离测试服**（独立 `data_dir` 与端口，预解锁科技/预置材料的场景只证明对应闭环，不代表普通新局全链）。脚本头部注释写明所需场景、原料和环境变量。

通用准备（以运输回放为例，在仓库根）：

```bash
mkdir -p /tmp/sw-transport
sed -e 's/port: 18080/port: 19489/' \
    -e 's|data_dir: "data-war"|data_dir: "/tmp/sw-transport/data"|' \
    -e '/        - electromagnetism/i\        - dyson_sphere_program' \
    server/config-war.yaml > /tmp/sw-transport/config.yaml
(cd server && go run ./cmd/server -config /tmp/sw-transport/config.yaml -map-config map-war.yaml)
(cd client-web && VITE_SW_PROXY_TARGET=http://127.0.0.1:19489 npm run dev -- --host 127.0.0.1 --port 4179)
SW_SERVER=http://127.0.0.1:19489 SW_TRANSPORT_EVIDENCE=/tmp/sw-transport npx tsx scripts/playtest-transport.ts
SW_TRANSPORT_WEB=http://127.0.0.1:4179 SW_TRANSPORT_EVIDENCE=/tmp/sw-transport node scripts/playtest-transport-browser.mjs
```

也可用 `bash server/scripts/start_official_war_test_server.sh <port>` 起隔离战争服。
