# 整体规划

更新：2026-09-29。设计拍板见 [对局设计决策](对局设计决策.md)（重点是 D7），逐条缺口见 [缺失内容清单](缺失内容清单.md)，进度见 [缺失内容清单-进度](缺失内容清单-进度.md)。

## 1. 要做成什么样

- **戴森球的工厂 + RTS 的大混战**。只借红警和星际的手感，不照搬内容。
- **战斗力 = 产能 × 补给**。单位和弹药都由产线生产。单位出战自带一定量弹药，用完后身边没有补给就停火，所以补给线本身就是战场。
- **数据驱动**。建筑、兵种、资源、配方、科技的特性全部写在配置文件里，调平衡不改代码。
- **大混战，指挥军团**。几百个单位同时交战，兵种少而精、职能清楚。玩家主要操作军团，需要时也能点单个单位。
- **先地面，后舰队**。前期在行星上打地面战，后期打舰队战、跨星战争。
- **不做**：超级武器、EVA 播报、英雄/空降、防御墙。阵营不对称暂缓（D4）。

## 2. 三个阶段

| 阶段 | 主题 | 完成标志 |
| --- | --- | --- |
| **一：行星内可玩** | 一颗行星上的工业、弹药补给、多兵种地面战、bot 对手 | 新玩家从大厅开一局遭遇战，60–90 分钟内打完：先建产线，再建弹药补给，然后多兵种混战，靠切断补给或正面推平分出胜负，全程不需要看文档 |
| 二：舰队与星际 | 多星系、殖民、舰队战、跨星远征、太空黑雾 | 殖民第二颗行星，组舰队跨星系摧毁对方前哨（S1–S3、E5、G2） |
| 三：终局与打磨 | 戴森球材料化和能量胜利、统计图表、音乐、存档/观战 | 戴森球作为胜利条件打通；音乐和图表齐全（S4–S5、C6–C8 等） |

第二、三阶段先不展开，第一阶段做完再细化。

## 3. 第一阶段：行星内可玩

原则：

- **试玩集中在最后**：各块按顺序实现，每块用自动化测试（服务端单测 + 客户端构建与测试）保证正确；整个第一阶段做完后，再统一在浏览器里对 bot 试玩调试，问题记在第 4 节。
- **可玩性优先于还原度**：DSP 的数值对齐（I1/I2）只在影响手感时才修。

### 3.0 数据配置化（最先做，约 1 个迭代）

3.1 和 3.2 要新增、调整大量单位和建筑。先把数据搬进配置文件，后面新增兵种就只是加配置条目。

- **现状**：物品、配方、科技、建筑、单位全部硬编码在 Go 里，共约 7300 行：
  - `server/internal/model/item.go`、`recipe.go`、`tech.go`
  - `server/internal/model/building_defs.go`、`building_runtime.go`
  - `server/internal/model/entity.go` 的 `UnitStats`/`UnitCost`
- **目标**：`server/data/` 下的 `items.yaml`、`recipes.yaml`、`techs.yaml`、`buildings.yaml`、`units.yaml`、`combat.yaml`（克制系数、弹种分档）。
  - 每个条目定义全部特性：血量、造价、生产时间、产出、射程、伤害、弹种、随身弹药量、视野、移速、解锁科技等。
  - 用 go:embed 内置；`config.yaml` 的 `data_dir` 可以整套覆盖。
- **做法**：
  1. 写导出工具，把现有 Go 定义导出成 YAML；
  2. 写加载器和引用校验；
  3. 让现有代码改读加载后的注册表；
  4. 删掉 Go 里的数值字面量；
  5. 现有 DSP 对齐测试改为针对加载后的数据跑，保证导出前后行为一致。
- **客户端**：继续从 `/catalog` 读，接口不变。补一段配置文件格式说明到 docs。

### 3.2 弹药补给 U10（核心，约 2 个迭代）

依据代码调研，拆成下面几步，每步都能独立测试、合并：

1. **随身弹药**
   - `model.Unit` 增加随身弹药字段：弹药类别、当前量、容量、当前装填的弹种。
   - 每种单位的弹种和随身弹药量写在 `units.yaml`；出厂时带满。
   - 开火扣弹的位置：`unit_combat_settlement.go` 冷却判定之后、`fireAtTarget` 之前，机甲自动开火那条路径同理。打空就停火，状态记为 `no_ammunition`。
   - 黑雾不耗弹。
   - 用完后，如果不在补给站光环或补给车范围内，就停火；回到补给范围后自动补满。
   - `combat_tech_settlement.go` 每 tick 会重算属性，要保证它不覆盖随身弹药。
2. **三类弹药，类内分档**
   - 子弹：`ammo_bullet` / `titanium_ammo`；炮弹：`shell_set` / `crystal_shell_set`；导弹：`ammo_missile` / `supersonic_missile_set` / `gravity_missile`。
   - 高档弹增伤；补弹时优先装高档。
   - `MilitarySupplyFromInventory` 补齐这些物品 ID。小队的 6 维补给精简为三类弹药（燃料、备件、护盾电池、维修无人机删掉）。
   - 聚爆加农炮改为吃炮弹。
   - 子弹科技前移到开局即可制造，炮弹前移到中期，让第一场仗就有补给问题。
3. **单位造价实物化**
   - 单位造价在 `units.yaml` 里写成物品清单（钢材、电路板、电动机等），`execProduce` 从生产建筑自身的库存扣料（皮带、分拣器或手动都能供料），并加生产时间。
   - 删掉 minerals/energy 这条路径，同步改 bot、CLI、API 文档和对应测试。
4. **补给站**（新建筑）
   - 库存由皮带或物流站供给，给光环半径内的己方单位按速率补弹。
   - 现有补给节点（物流站、部署枢纽）不带距离判定，改为只有补给站和补给车负责补弹。
5. **补给车**（新单位）
   - 自带弹药库存，在补给站自动装货，给附近友军补弹，可以跟随军团。
   - 会被优先攻击。
6. **客户端**
   - 单位卡片和选择栏显示弹量条；地图上画出补给站光环。
   - 缺弹时告警（"X 个单位弹药耗尽"）；生产面板显示物品造价。
7. **bot**
   - 目前 bot 只会手搓少量物品，也不给炮塔喂弹。
   - 要学会建子弹产线、补给站，并让部队带补给车出击。

验收：两支部队对打，没有补给的一方打空后停火被歼灭；炸掉对方补给站后，对方前线停火。

- 生产队列可见。
- `df_` 单位物品配方删除。

### 3.4 军团 U11（约 1–2 个迭代）

- 编队：选中单位后编成军团。军团只是命令容器，没有共享血条；现有 HP 池小队 `CombatSquad` 重构为军团。
- 指令：进攻区域、防守区域、撤退、补给优先。按兵种和射程自动站位（炮在后、前排在前），吸收 R5 编队站位。
- 军团可以挂补给车，自动跟随补给。
- 客户端：左侧军团列表，一键选中；地图上显示军团标记和指令箭头。
- 性能：单行星 300 个单位同时交战时，tick 耗时在预算内（需先测基线）。

### 3.5 防御与袭扰 U4/U9（约 1 个迭代）

- 防空炮、远程火炮建筑；炮塔统一走 3.2 的三类弹药。
- bot 和玩家的"攻击移动"会优先打补给站、补给车和弹药厂。
- 物流无人机可以被防空击落。

### 3.6 bot 与对局收口（约 1–2 个迭代）

- A1：bot 会建弹药线、多兵种和军团，会袭扰补给；分 easy/normal/hard。
- F6/G1/G3：完整跑 60–90 分钟对局，调节奏倍率、黑雾威胁、地图争夺区。
- C9：新手引导按"采矿 → 产线 → 弹药 → 出兵 → 补给 → 进攻"串起来。
- F4：统计改为聚合所有行星。
- 最终验收：见第 2 节第一阶段的完成标志，由人实际试玩确认。

### 顺序

```
3.0 数据配置化 ─► 3.1 底座 ─► 3.2 弹药补给 ─► 3.3 兵种/生产 ─► 3.4 军团 ─► 3.5 防御袭扰 ─► 3.6 bot 与收口
                         （全部完成后统一试玩调试）
```

3.1 里的工业修正可以和 3.2 并行。3.5 可以穿插在 3.3 和 3.4 之间。
