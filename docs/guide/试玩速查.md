# 试玩速查（一键环境 + 驱动）

给层代理 / 主代理用的一页速查。流程与测试卡见 [存档点回归测试](存档点回归测试.md) 第 9 节。

## 起停

```bash
# 在任意 worktree 里（脚本自己找主仓库软链 node_modules）
bash scripts/playtest-up.sh 205 --tick-rate 4 [--checkpoint cp-base] \
     [--config server/config-skirmish.yaml] [--map-config server/map-skirmish.yaml]
bash scripts/playtest-down.sh 205
```

**端口规则（基数 N 必须显式给，避免多个 worktree 撞车）**：服务端 `N*100`、Web `N*100+1`、驱动 `N*100+2`。N=205 → 20500/20501/20502。当前已知占用：19900/4400/4199（另一个 worktree）、19630/4196（老环境）。

启动后打印一行汇总（URL、端口、admin/player key、日志路径）。脚本做的事：

- worktree 里缺 `node_modules` 时软链主仓库（根目录逐个包软链，`@gw/shared` 单独指向**本 worktree** 的 `shared-client`，这样改 shared-client 立刻生效）；
- 编译服务端到 `/tmp/sw-play-$N/server-bin`，生成临时配置（端口 / `data_dir` / `checkpoint_dir` 指向主仓库 `.run/checkpoints` / `tick_rate_override`）；
- `vite build` 到 `/tmp/sw-play-$N/web-dist` 再 `vite preview`（生产构建，不用 dev），`VITE_SW_PROXY_TARGET` 指向本环境服务端；
- 起常驻 Playwright 驱动（`DRIVER_PORT` 参数化，真实显卡 ANGLE Vulkan，headless）；
- 全部 `setsid --fork nohup` 后台，PID 写 `/tmp/sw-play-$N/pids`，down 按 PID 精确 kill（进程组 SIGTERM → SIGKILL），不用 `pkill -f`。

产物与日志都在 `/tmp/sw-play-$N/`：`server.log` / `web.log` / `driver.log` / `pt/`（截图 + `actions.log`）。

## 驱动用法

```bash
echo 'return await G.state()' > /tmp/s.js
curl -s -m 180 localhost:20502 --data-binary @/tmp/s.js
```

片段是 async 函数体，作用域里有 `page`、`L`（lib.mjs）、`G`（helpers.mjs）、`S`（`S.errors` 收集页面报错与 HTTP 4xx/5xx）。**单线程**：一个片段卡住后面全排队，长任务用 `curl -m` 设超时。

常用 `L.*`：`get / scene / summary / cmd / shot / tilePos / tileAbs / clickTile / card / focus / buildingsOf / waitFor / open3d / sleep`。
常用 `G.*`：`build / buildOnce / buildNear / withdraw / handcraft / state / look / home / aim / clickTile / rightClickTile / hitCanvas / freeTiles / fb / openDrawer / closeDrawer / selectBuilding / mecha / jobBusy / jobWait / debugShow / ensureBar / resetView`。

`G.state()` 一次拿到 tick / 资源 / 背包 / 电力 / 研究 / 战斗 / 黑雾 / 双方建筑与单位，是最省事的局面快照。截图用 `await L.shot(page, '01-foo')`（写到 `$PT_OUT`）。

## 读档与推进

- 读档：`curl -X POST -H 'Authorization: Bearer key_player_1' localhost:20500/checkpoints/cp-base/load`（`--checkpoint` 参数在起环境时就能读一次）。服务端热加载，不用重启；网页自动发现换局并重连。
- 读档后**等约 50 tick** 再判断现象（bot 重新扫描、客户端重新同步）。
- tick 速率是**运行参数**：`--tick-rate` 写进临时配置的 `server.tick_rate_override`（0 = 不覆盖）。建议：从零开局 / 手搓密集层 **2**，有产线之后 **4**，空等层（等首攻、等黑雾恢复中立）**50–100**，重建快进 **100**（实测 100 稳跑，单 tick p95 ≈ 2 ms，别超 1000）。
- 存档：`checkpoint save <名> --contract docs/guide/checkpoints/<名>.json --replace`（CLI）或 `POST /checkpoints`（body `{name, note, contract, replace}`）。

## 可执行 build 记录（存档点重建）

存档点 `docs/guide/checkpoints/<名>.json` 的 `build` 字段现在是**有序步骤数组**：

```json
{"steps": [
  {"cmd": {"type": "build", "target": {"layer": "planet", "planet_id": "planet-1-1", "position": {"x": 21, "y": 48}}, "payload": {"building_type": "wind_turbine"}}},
  {"advance_to_tick": 4096},
  {"wait_until": {"kind": "building_running_gte", "player": "p1", "type": "wind_turbine", "n": 1}, "timeout_ticks": 600}
]}
```

- `cmd` 原样就是 `POST /commands` 的 body 里那条命令（`{"type","target","payload"}`）。
- `advance_to_tick` 快进到指定 tick；`wait_until` 等契约谓词成立（谓词词表见 [服务端 API 6.9](../dev/服务端API.md)），`timeout_ticks` 超时即报错。
- 重建：`go test ./internal/checkpointbuild/ -run TestRebuildChain -args -from cp-power`（从父层读档 → 逐步执行 → 校验契约 → `checkpoint save --replace`）。
- 每轮至少安排一次**纯 UI 从 cp-root 试玩**，然后用 `checkpointbuild -export`（或 `scripts/checkpoint-export-build.mjs`）把该局审计日志导出成新的 `build` 记录，替代手写步骤。

## 常见坑

- 驱动先于 web 就绪会 `ERR_CONNECTION_REFUSED`；驱动已自带等待 `/lobby`，但手动起驱动时记得先起 web。
- 任何 `page.goto` 之后都要先 `await L.open3d(page)` 再等 2–3 秒（导航会销毁 `window.__planetThree`）。
- 按 Esc 会取消选中；给单位下令的循环里不要按 Esc。机甲站在目标格上时点这格会点到机甲。
- 抽屉 tab（工作台 / 选中对象 / 生产 / 活动流）要在抽屉展开后才能点。
- 传送带、分拣器、电线杆、单位占 1 cell；风机/熔炉/制造台/研究站/兵营 3×3（部分 2×2/5×5）——坐标按**细分网格 cell** 写，不是旧 tile。产线要用传送带，不要用「装入建筑」凑（见 [细分网格与DSP界面](细分网格与DSP界面.md)）。
- 关掉环境要 `playtest-down.sh <N>`（按 PID），别用 `pkill -f node`：会误杀别的 worktree 的驱动与浏览器。
