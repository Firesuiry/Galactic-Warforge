# 实物经济与分拣器（第 16 轮契约）

来源：用户 2026-10-15 决定——去掉「资金」维度，一切消耗都是实物（参考 DSP）；一条传送带经分拣器供给多台机器（参考 DSP）。
本页是前后端并行开工的接口契约，改动以此为准。

## 1. 去掉资金

- 删除玩家级 `minerals`：`Resources.Minerals`、`BuildCost.minerals`、`minerals_kickback`、`MaintenanceCost`、施工预留里的矿物、bootstrap 的 `minerals`、所有「矿物不足」检查与提示。
- `energy` 不再是可花的货币：从 `BuildCost`、升级、火箭发射成本里删除。`Resources.Energy` 只保留为电网结余的只读展示（`power_settlement` 现有写法不变）。
- 建造 / 升级只扣 `build_cost.items`（玩家背包 `PlayerState.Inventory`）。原来没有 `items` 的 4 个建筑补上物品成本（参照 DSP 配方）。拆除按物品原样退还，取消施工按进度比例退还物品。
- 采矿机只产出矿石实物，进自己的输出缓冲。输出缓冲满了就停采，不扣矿脉（fd8e18e 的规则保留）。
- 研究（矩阵）和造兵（物品）本来就是实物消耗，不变。
- API：`/state/summary` 等响应删除 `minerals` 字段；`resources.energy` 保留并标注为电网结余。存档版本 +1（v3 → v4），拒绝读旧档。
- 开局物资包 `bootstrap.minerals/energy` 改为 `bootstrap.items`，直接放进背包。skirmish 两方同一份，数量够建「3 风机 + 2 矿机 + 1 熔炉 + 若干电塔 + 20 传送带 + 4 分拣器」，之后靠机甲采矿 / 手搓 / 熔炉产出续上。midgame / war 按原资金量折算成物品。

## 2. 分拣器（DSP 规则）

- 分拣器（1×1）有朝向，跟随建造时的 `rotation`：背面为取货端，正面为放货端，沿朝向轴向前后各找 `range` 格（mk1=1、mk2=2、mk3=3）。不再默认四向，也不再来回搬。`configure_sorter` 只负责过滤（allow/deny、物品、tag），不改方向。
- 取货端是传送带时，可以从任意路过的带格上取（取该格上的物品，不要求带尾正对分拣器）。放货端是传送带时，从侧面插入（现有逻辑）。端点是建筑时，接占地内任意一格。
- 节拍：每次往返搬 1 件（集装 / 叠层科技提高每次件数）。往返周期 = `cycle_ticks × 端点距离格数`，mk1/mk2/mk3 的 `cycle_ticks` 为 6/3/2。只往机器里放当前配方需要、且输入缓冲还没满的物品。
- 删掉 `sorter_settlement.go` 里「预览与提交不一致时 panic」，改为跳过本次搬运并记日志。

## 3. 建筑与传送带的直连

- 只有带 `direct_belt_io: true` 的建筑保留和相邻传送带的直连 IO（现有 `settleBuildingIO`）：采集类（采矿机、水泵、抽油机等）的输出、物流站、分流器 / 叠层器 / 流速监测器这类带上设备。
- 其余建筑（生产、研究、仓储、发电燃料口、HQ、兵营、炮塔等）一律通过分拣器进出货。运输机器人 / 机甲搬运不受影响。

## 4. 客户端

- 删除所有资金显示：TopNav、建造栏成本、「矿不足」置灰。建造栏改为显示每项物品「背包有 / 需要」，任一不够就置灰，悬停提示缺什么。
- 分拣器放置时显示朝向箭头（取 → 放），R 旋转（与传送带一致）。放下后渲染的机械臂方向和服务端一致；SorterControls 只配过滤，不再有方向选项。
- 分拣器在 hotbar 的物流页，排在传送带后面。

## 5. Bot 与开局脚本

- bot 建造门槛改为「背包物品够不够」。不够时先用机甲手搓，或者从自己建筑的输出缓冲里 `transfer_item` 取。
- bot 的标准产线：矿机 → 传送带 → 分拣器 → 熔炉 → 分拣器 → 传送带 / 仓库。`opening_script.go` 同步改。
- 验收：TestSkirmishFullMatchRegression 6 个种子全绿，bot 在 tick 40000 前开始研究（`TestSkirmishBotTechChainStarts`）。
