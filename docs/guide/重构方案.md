## 1. 原则

- 按风险从低到高分阶段推进。**每个阶段单独开分支、单独验收、单独合 main**，不做一次性大爆炸重构。
- 每个阶段的验收门槛：`go test ./...`、client-web 的 `tsc + vitest`、client-cli 的 `npm test`、`scripts/command_coverage.py --check`；改到 client-web 的阶段还要在浏览器里实测建造、调兵和局势显示。
- 测试合并放在最后做。改生产代码期间，gamecore 那 29k 行测试就是回归防护网。
- 遵循 AGENTS.md 的激进演进原则：不写兼容层，直接改接口和所有调用点。

### P3 服务端重构（核心，约 1–2 周）

1. **统一命令注册表**：一条命令只登记一次，内容为 `{Type, Spec, Routed, Handler, Payload 结构体}`。由它替换以下 5 处，预计 −500~700 行：
   - `model/command.go` 里的常量
   - `command_catalog.go`
   - `core.go` 中约 150 行的 switch
   - `planetRoutedCommand`
   - `commandEntityRefs`

   载荷改为强类型结构体解码，删掉约 12 个零散的 `payload*` 解析函数。
2. **拆 `rules.go`**：按 build / unit / mining / victory / logistics 拆成多个文件。
3. **统一供电判定**：先逐项对比 `rules.go` 里命令期判定与 `model/power_allocation.go` 的语义差异，确认没有刻意的区别后，统一用 model 那一套（约 −300 行）。
4. **bot 独立**：bot 只通过“提交命令”接口和核心交互，先去掉它对 `gc.executeRequest` 的直接调用，再移到 `gamecore/bot` 子包。
5. **拆 model**：
   - 拆成 `model`（纯状态）、`catalog`（YAML 注册表，改为显式加载，不再用 `init()` 副作用）和若干领域逻辑；
   - `terrain`、`model/power` 两个过小的包并入相邻包；
   - gamecore 不再直接依赖 persistence / gamedir，由 startup 注入。
6. **删死代码**：
   - 规划蓝图 `blueprint*.go` 和 `planning.go`（只保留 3 个仍在用的类型；战争蓝图另属一套，继续保留）；
   - 审计列出的约 30 个无调用的函数和类型；
   - 空函数 `ClearDysonSphereStates` / `ClearSolarSailOrbits`；
   - persistence 的 delta 路径和 `snapshot_delta_max_bytes`；
   - `SyncLegacyExecutor`，以及旧 HP 池小队等旧存档兼容代码。
7. **gateway**：约 25 个查询 handler 用同一个 `withPlanet(fn)` 帮手收口（约 −300 行）。
8. **合并配置**：`config-dev.yaml` 并入 `config.yaml`，差异改为命令行覆盖；资源类型→物品的映射改由数据驱动。

预计业务代码减少约 4.5–5k 行（约 10%）。
