# 试玩介绍视频制作指南

本文记录 `siliconworld-试玩介绍.mp4`（片头 + 25 个精华镜头 + 片尾，约 4 分 40 秒，含 BGM 与 TTS 旁白）的完整制作流程。所有游玩画面均为 Playwright 驱动真实 Web UI 的实际录像，非摆拍素材。

全部工具脚本在 `develop_tools/playtest_video/`，中间产物在 `.run/video-playtest/`（未入库）。

## 总览：四步流水线

```
录制（play_session.mjs）→ 挑镜头（pick_highlights.mjs）→ 合成（assemble_video.mjs）→ 配音（dub_video.mjs）
```

## 0. 环境准备

- 本地试玩环境：`bash scripts/start-local-playtest.sh start`（server :5677 / gateway :18180 / web :5678，详见 `docs/dev/本地试玩环境启动.md`）
- Node（>=18，用到内置 fetch）、ffmpeg/ffprobe
- Playwright：脚本直接引用 `client-web/node_modules/playwright`
- 中文字体（烧录字幕用）：`/usr/share/fonts/opentype/noto/NotoSansCJK-Bold.ttc`
- BGM：`docs/remotion/public/audio/bgm/ambient-bed.mp3`

## 1. 录制真实试玩（play_session.mjs）

Playwright 打开真实 Web UI（1600x900），按“导演剧本”自动玩游戏：登录、星图浏览、拍建筑、研究、铺电网矿机、扩张、造兵等。全程**分段录像**（webm）+ **事件时间戳日志**（events.jsonl）+ 里程碑截图。

```bash
node develop_tools/playtest_video/play_session.mjs \
  --minutes 75 --seg-sec 480 --out .run/video-playtest/session
```

参数：

- `--preset full|expansion|industry|finale`：剧本预设。`full` 从零开局；其余为特定阶段补拍（会注入既有存档续录）。
- `--minutes`：总时长；`--seg-sec`：单段录像长度（分段便于 seek）。
- `--start-offset`：续跑时事件日志的时间偏移，保证多 session 时间戳可拼接。

注意：录像总时长要远大于成片需求。本次成片 280 秒，背后录了 200+ 分钟、约 1GB 原始 webm。关键操作（如拍建筑、研究完成）之间要给游戏留足真实运转时间，镜头才有内容。

## 2. 挑选精华镜头（pick_highlights.mjs）

按规则（事件 kind + 正则匹配 + 提前量 + 时长 + 字幕文案）从一个或多个 session 的 `events.jsonl` 里挑高光时刻，生成 `highlights.json`：

```bash
node develop_tools/playtest_video/pick_highlights.mjs \
  .run/video-playtest/session .run/video-playtest/session2 ... \
  --out .run/video-playtest/highlights.json
```

产出的每条 clip 含：`session`（素材目录）、`seg`（分段号）、`t`（事件时间戳）、`offset`（微调）、`dur`（镜头时长）、`caption`（烧录到画面的字幕）。可手工编辑 `highlights.json` 调整选镜和文案。

## 3. 合成无声成片（assemble_video.mjs）

按 `highlights.json` 从各 session 的分段 webm 里切镜头、烧字幕（drawtext），加片头/片尾卡片，concat 成 `assemble/silent.mp4`，最后叠 BGM（音量 0.22，淡入淡出）输出：

```bash
node develop_tools/playtest_video/assemble_video.mjs \
  .run/video-playtest/highlights.json --out siliconworld-试玩介绍.mp4
```

`assemble/` 下的 `clip-000-title.mp4`、`clip-001..NNN.mp4`、`clip-999-end.mp4` 是逐镜头文件，配音脚本会逐个探测它们的实际时长来对轴——**重新合成后无需手工改配音时间**。

## 4. TTS 配音（dub_video.mjs）

配音文案在 `develop_tools/playtest_video/narration.json`：`segments` 数组与上述 clip 文件**按顺序一一对应**（含片头、片尾）。文案长度按镜头时长控制（中文约 4.5 字/秒，预留 0.3s 余量）。

TTS 渠道：cursorai（兼容 MiniMax 协议），端点 `POST https://api.cursorai.art/minimax/v1/t2a_v2`，模型 `speech-2.8-hd`，返回 JSON 中 `data.audio` 为 hex 编码音频。**令牌从环境变量读取，严禁写入仓库**：

```bash
TTS_TOKEN=sk-xxx node develop_tools/playtest_video/dub_video.mjs \
  develop_tools/playtest_video/narration.json \
  --out siliconworld-试玩介绍.mp4
```

脚本行为：

1. 逐段调 TTS，mp3 缓存到 `.run/video-playtest/dub/`（已存在的跳过，可重复跑）；失败自动重试 3 次。
2. 逐段比对音频时长与镜头时长，超长时自动 `atempo` 微压（上限 1.8x，超出会告警）。
3. 用 `adelay` 把每段旁白对齐到镜头起点（+0.25s），旁白先经 `highpass=f=80` 去低频隆隆声；BGM 为低频 drone，用 `aloop` 采样级无缝循环 + `highpass=f=45` 去次声后压到 0.04 垫底（0.10 时安静段会听出电流声底噪），`amix` 混音后经 `alimiter` 防爆音，视频沿用淡入淡出，输出最终 mp4。
4. `--skip-tts` 可跳过合成直接重新混音（改文案对齐参数时用）。

可选音色（voice_id）：`male-qn-qingse`（青涩青年，本片使用）、`female-shaonv`（少女）等；`speed` 0.5~2.0。

## 验收要点

- `ffprobe` 确认总时长与 silent.mp4 一致；音频流存在。
- 用 `ffmpeg -ss <t> -i out.mp4 -t 5 -af volumedetect -f null -` 抽查几个镜头起点处的音量，确认旁白在位。
- 抽帧确认画面字幕与镜头内容匹配（本次用 `check-*.png` 逐镜头核对过）。

## 常见问题

- **下载后提示无法播放**：mp4 的 moov 元数据必须在文件头部（faststart），否则浏览器/微信等播放器无法边下边播甚至直接报错。两个合成脚本的 ffmpeg 输出都已加 `-movflags +faststart`；对已有文件可无损修复：`ffmpeg -i in.mp4 -c copy -movflags +faststart out.mp4`。另外下载后先核对文件大小/md5，排除传输截断。
- **Playwright webm 缺 duration**：assemble 脚本会自动重封装成 mkv 再探测。
- **字幕里英文冒号/引号**：drawtext 对 `:` `'` 敏感，assemble 已做转义，写 caption 时尽量用中文标点。
- **旁白超限**：先改文案再重跑；不要依赖大幅 atempo，会明显变调。
