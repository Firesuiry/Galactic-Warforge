# 缺失内容清单（目标：戴森球计划 + RTS 交战）

## 方向（2026-09-29 调整）

只借红警/星际的**手感**，不照搬内容。两条主线：

1. **多兵种大混战**：兵种少而精、职能清楚，互相克制；几百个单位同时交战，玩家主要指挥军团，不用逐个操作。
2. **弹药补给走产线**：单位开火消耗弹药，弹药是 DSP 产线生产的实物，要运到前线；工厂和补给线就是战斗力，可以被袭扰。

**不做**：超级武器、EVA 播报、英雄/空降、防御墙。阵营不对称暂缓（D4）。

更新：2026-09-29，本轮已落地 R3/E2/U6、R6 卡片、F2 结算页、A1 增强、F6/G1/G3 骨架、C4 小队可见性。

口径：**公共命令/API 可触发 + Tick 真实结算 + 客户端可见可操作**才算“有”。目录条目、模型、只在测试里生成的对象都不算。每条都经过代码核查，证据路径相对仓库根目录。

优先级：**P0** 没有就撑不起上面两条主线；**P1** 构成完整一局；**P2** 后期深度与打磨。规模：S 小 / M 中 / L 大（相对值）。

已完成并移出本清单：R1、R2、R3 余项、R4、R5（主体）、R6（老兵等级未做）、E1–E4、E2 刷屏、U3、U6、U8、F2、F3、F5、C1–C3、C10（主体），以及 D1–D3、D5、D6 拍板。明细见 [缺失内容清单-进度](缺失内容清单-进度.md)，设计拍板见 [对局设计决策](对局设计决策.md)。下文只保留仍缺的部分。

## 8. 戴森侧工业剩余缺口（P1–P2）

目录已按 ID 与 DSP 对齐（`develop_tools/dsp-catalog/mapping.json` 只剩政策豁免的全息信标），下面缺的是数值与玩法接线。

### 8.1 配方与数据

- **I1 配方数值漂移**（P1/M）：约 24 个配方的输入输出与冻结的 DSP 数据（`develop_tools/dsp-catalog/scope.json`）不一致。例如电路板是 1 铁锭 + 1 铜锭 → 1（DSP 为 2 铁 + 1 铜 → 2），电动机缺磁线圈，钛晶石用石墨烯代替有机晶体，火箭在发射井直接合成、不经过戴森球组件，四种高阶矩阵、燃料棒、物流载具也不同（`server/internal/model/recipe.go`）。对齐测试只比对 ID（`server/internal/model/dsp_alignment_test.go:324`）。后果：有机晶体、戴森球组件没有去处，位面过滤器、粒子宽带只出现在建筑成本里。要做：按 scope.json 对齐，并加数值级的 parity 测试。
- **I2 科技成本与研究模型**（P1/S）：早期科技与 DSP 一致，中后期便宜 10–32 倍（例如信息矩阵科技 25+25，DSP 为 800+800）；研究没有 hash 层，每台研究站每 tick 耗 1 个矩阵，多种矩阵按顺序而不是同时消耗（`server/internal/gamecore/research.go`）。按 D1 的节奏决定是否对齐。
- **I3 无用途的物品**（P2/S）：`foundation_supply`、气罐/液罐、蓄电器物品（没有配方能产出，所以蓄电器充放循环在普通新局里用不了）、`accumulator_full`；信号塔没有 runtime 定义；反物质/晶石炮弹、压制胶囊、攻击无人机可以制造但没有消耗方；`df_` 单位物品见 U2。

### 8.2 科技效果

- **I4 无效果的科技**（P1/M）：通讯控制、集装分拣器升级、射线传输效率、物流站集成、黑雾自动重建标记、三项黑雾战斗无人机、地面/太空编队扩充、黑雾行星护盾、`basic_assembling_processes`（空效果）；特殊解锁 `dyson_stress`（结算用全局常量）、`ionosphere_utilization`、`warp_drive`、`satellite_power` 没有读取方（均在 `server/internal/model/tech.go`）。
- **I5 部分生效或错位**（P1/S）：
  - 矿物利用的 +10% 产出被矿点产率上限吃掉：真实矿点产率 2–6，低于矿机的 8（`server/internal/gamecore/rules.go` 采集结算），测试只因用了产率 20 的矿点才通过；
  - 背包容量科技只限制物流请求，玩家背包本身没有上限；
  - 驱动引擎类的无人机加速作用在物流无人机上（DSP 是建造无人机）；宇宙探索只加 1 格机甲视野；
  - 旧的 `mecha_engine`（100 级，每级 +2 移动）与 `drive_engine` 叠加，旧的 `energy_shield` 与 `df_energy_shield` 叠加，应删掉旧条目。

### 8.3 物流

- **I6 分拣器与机器的关系**（P1/M）：机器直接从相邻皮带取放货（`server/internal/gamecore/building_io_settlement.go`），分拣器只做带到带搬运，所以 DSP 最核心的“皮带 → 分拣器 → 机器”布局并不存在；分拣器的过滤和方向在模型里有，但没有命令能设置。
- **I7 集装不增运**（P1/M）：集装机确实能把货物打成 2/4 叠，但普通皮带每次仍只搬 1 件、容量按件计（`server/internal/gamecore/conveyor_settlement.go`、`server/internal/model/conveyor.go`），叠包不提升运量。
- **I8 立体物流**（P2/L）：一格只能有一个建筑，没有皮带高度、立交和跨越。
- **I9 管道**（P2/M）：模型与 Tick 结算都存在，但没有任何入口能创建管道，W2 的储液罐管道只在测试里有效。
- **I10 增产剂进入普通机器即丢失**（P1/M）：机器库存只计数量，喷涂属性一进机器就丢（`server/internal/gamecore/production_settlement.go:135`）；也没有“额外产出/加速”模式的切换命令。
- **I11 物流收尾**（P2/S）：滞留的无人机、运输船、配送机器人无法回收（`server/internal/gamecore/building_jobs.go:153`）；拆除只退 50% 建造成本，并丢弃建筑内全部库存。

### 8.4 采集

- **I12 采集规则**（P1/S）：
  - 矿机不校验资源类型，可以建在任意矿点上，包括水和油（`server/internal/gamecore/rules.go` 建造校验）；
  - 普通矿机只覆盖自己那 1 格；
  - 矿点只有 80–200 单位；油井约 7 tick 就衰减到底；
  - 抽水和硫酸是陆地上的点状矿点，没有海洋或酸海；机器也能采植被。
  - （本地存储满时矿脉照扣、溢出丢弃：D6 已决定保留，不再算缺陷。）

### 8.5 电力

- **I13 燃料机组**（P1/S）：所有燃料发电机每 tick 固定烧 1 件，与负载无关，好燃料提高功率而不是延长燃烧时间（`server/internal/model/power.go:75-101`）；火电缺精炼油、可燃冰、燃烧单元；聚变也接受氢燃料棒（DSP 只接受氘燃料棒）。
- **I14 射线接收站能量重复计算**（P1/S，bug）：每座接收站都读取全部的太阳帆 + 戴森球能量，没有共享池（`server/internal/gamecore/ray_receiver_settlement.go:60`），N 座接收站得到 N 倍能量；缺引力透镜、射线传输效率和电离层。
- **I15 太阳能与地热**（P2/S）：整颗星球共用一条昼夜曲线，面板位置没有影响；地热固定输出 30，不按熔岩覆盖缩放。

### 8.6 机甲与建造

- **I16 玩家机甲**（P1/L）：移动是范围内瞬移、攻击是手动一击（M1 有意保留旧语义至此条），没有飞行；没有建造无人机，建筑 1 tick 完工（`server/internal/gamecore/construction.go` 的 `defaultConstructionDurationTick = 1`）；建造半径（HQ 24 格）之外仍只能建在机甲 6 格内；死亡后单位被删除且不会复活，之后半径外的建造命令全部失败（M1 客户端验证三次重建环境的根因）；没有装备；背包无上限；燃料只有一个缓冲，只能手动补。
- **I17 布局蓝图**（P1/M）：`CaptureBlueprint`、`PlaceBlueprint` 和批量建造/拆除已在 `server/internal/model/blueprint_ops.go`、`blueprint_batch.go` 实现，但没有任何调用方；公开的 `blueprint_*` 命令是战争单位设计，不是建筑布局。
- **I18 建造规则**（P2/M）：升级只是把抽象等级 1–3 放大 HP，不是 DSP 的 Mk.I → Mk.II 替换；地基花 10 minerals、不消耗 `foundation_supply`，没有土壤和矿脉掩埋；只有皮带有方向；没有区域拆除（批量建造只能在一次请求里塞多条单格命令）。

### 8.7 黑雾工业

- **I19 黑雾设施**（P2/S）：三种黑雾机器只是更快的普通机器，而且普通科技就能解锁（`server/internal/model/tech.go`），隐藏的 `dark_fog_matrix` 科技因此多余；没有黑雾专属材料。

## 11. 平台与工程（P2）

- 读档时随机数从种子重建（`server/internal/gamecore/save_state.go:221`），读档后随机序列会重复，确定性重放在读档后失效。
- 没有存档槽；`/replay` 只做摘要校验，不是可以观看的回放。

- 没有账号体系，也不能观战。
- 大地图（每面 816 格）下，软件渲染要降到“流畅”画质才能跑完自动化回放，需要明确性能预算。
- F1 遗留：换局后旧局审计随快照一起重置；`/rollback` 没有走换局互斥锁（目前无害）。
- shared-client 的 `apiFetch` 不透传 HTTP status，C10 的 401 判定靠错误文案匹配；大厅在后台标签页仍每 10 秒轮询，可按页面可见性降级。
