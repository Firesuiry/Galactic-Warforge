# 视觉夹具（3D 行星地图）

画面类改动（传送带 / 分拣器 / 立交 / 建筑模型 / 地表）先在**视觉夹具**里迭代：
Storybook 固定场景 + 固定机位，不起服务端、不读档、不登录，秒级出图；Playwright
截图基线做回归。真机环境只在最后验一次。

> 第 19 轮起只维护 **3D（PlanetMapThree）** 夹具：2D「平面战术」视图已下线。

## 资产

| 路径 | 作用 |
| --- | --- |
| `client-web/src/stories/fixtures/belt-dsp-scene.json` | 夹具数据（cp-belt-dsp 立体交叉物流场景） |
| `client-web/src/features/planet-map/PlanetMapThree.stories.tsx` | 故事：`Planet/BeltDspFixture` |
| `client-web/tests/belt-visual.spec.ts` | Playwright 截图回归（3 张基线） |
| `client-web/tests/belt-visual.spec.ts-snapshots/` | 基线 PNG（`*-skirmish-linux.png`） |
| `scripts/export-scene-fixture.mjs` | 从试玩环境导出夹具数据的脚本 |

夹具数据是**服务端接口的原始返回**（`/scene` + `/catalog` + `/runtime` + `/networks`），
故事直接把它喂给 `PlanetMapThree`，渲染路径与真机完全一致。

## 看故事（迭代用）

```bash
cd client-web
npm run storybook          # 默认 http://localhost:6006
```

打开 `Planet → BeltDspFixture` 下的三个故事：

| 故事 | 机位 | 用途 |
| --- | --- | --- |
| `BeltDspTop` | 俯视全景（tilt 0.15，聚焦 (53,153)） | 看整条立体交叉的布局、带面方向箭头、货物色块 |
| `BeltDspOblique` | 立交斜视（tilt 1.0，zoom 2） | 看高架铁线跨过地面铜带、落坡、支柱 |
| `BeltDspSorter` | 跨格分拣器特写（聚焦 (53,156)，tilt 0.8，zoom 1.8） | 看 (53,157) 隔一格扫货的摆臂与取放端 |

URL 直达（`id` 由标题推导）：

```
http://localhost:6006/iframe.html?id=planet-beltdspfixture--belt-dsp-top&viewMode=story
http://localhost:6006/iframe.html?id=planet-beltdspfixture--belt-dsp-oblique&viewMode=story
http://localhost:6006/iframe.html?id=planet-beltdspfixture--belt-dsp-sorter&viewMode=story
```

**热更新**：Storybook dev server 直接读源码，改 `src/features/planet-map/three/*` 或
`planet-three-scene.ts` 保存后页面自动刷新，不用重启服务端、不用读档。

**动画冻结**：故事壳在首次布局 effect 里把 `?freeze=1` 写进 URL——必须在 3D 场景
构造之前（`PlanetThreeScene` 在构造函数里读一次 `location.search`）。冻结后带面滚动、
分拣器摆臂、水面流光都停在固定相位，画面是时间的纯函数，截图可复现。**新增故事时
不要绕过这个壳自己建场景**，否则截图会漂。

## 比对 / 更新基线

```bash
cd client-web
# 比对（不需要服务端，也不会拉起 playwright.config 里的 webServer）
SW_SKIP_WEBSERVER=1 npx playwright test tests/belt-visual.spec.ts

# 重生成基线（主代理在画法合并后统一跑）
SW_SKIP_WEBSERVER=1 npx playwright test tests/belt-visual.spec.ts --update-snapshots
```

- `SW_SKIP_WEBSERVER=1` 是**必须的**：playwright.config.ts 默认会为 skirmish/war 两个
  场景各起一套服务端 + vite dev。设了它之后配置里没有 `webServer`，本 spec 自己起
  `storybook dev`（端口 `SW_STORYBOOK_PORT`，默认 **24606**；已有实例则复用，
  退出时只杀自己起的那个）。
- 容差与 `tests/visual.spec.ts` 同口径：`maxDiffPixelRatio: 0.001`（0.1%）。GPU 光栅化
  在满载时会有 1 单位亚像素抖动；真实画法回归（带子/高架/分拣器位移）是数万像素级。
- 基线文件名带 project 名：`belt-dsp-top-skirmish-linux.png`。spec 在
  `SW_SKIP_WEBSERVER=1` 下只有一个 project（场景由 `SW_SCENARIO` 推断，默认 skirmish），
  文件名里的 `-skirmish-` 不会变。
- 失败时先确认 Storybook 是**当前分支的源码**：端口上如果残留了别的 worktree 的
  Storybook，`reuseExistingServer` 会复用它（改用 `SW_STORYBOOK_PORT=24607` 或先停掉旧实例）。

## 从试玩环境重新导出夹具数据

夹具数据由 `scripts/export-scene-fixture.mjs` 从试玩环境按窗口导出：

```bash
# 1. 起环境（独立 N，端口 = N*100 / +1 / +2，避开 8080/18080）
bash scripts/playtest-up.sh 247 --tick-rate 4 --checkpoint cp-belt-dsp
#    存档不兼容时先重建：cd server && go run ./cmd/checkpointbuild -root .. -layer cp-belt-dsp

# 2. 让产线走起来（夹具里带子上要有货）：
#    从补给站取出料再放进源站（b-105 铁锭 → b-130；b-97 铜锭 → b-126；
#    侧汇线要铜矿：从 b-59 采矿机取出 → b-126）
curl -s -X POST -H 'Authorization: Bearer key_player_1' -H 'Content-Type: application/json' \
  localhost:24700/commands -d '{"request_id":"fixture-1","issuer_type":"player","issuer_id":"p1",
  "commands":[{"type":"transfer_item","target":{"layer":"planet","planet_id":"planet-1-1"},
  "payload":{"building_id":"b-97","item_id":"copper_ingot","quantity":40,"direction":"to_player"}}]}'
#    …再 to_building 放进 b-126；铁锭同理 b-105 → b-130

# 3. 导出窗口（含右下角；--poll-flow 秒 = 轮询挑带面货物最多的一帧）
node scripts/export-scene-fixture.mjs 247 40 140 63 163 \
  client-web/src/stories/fixtures/belt-dsp-scene.json --poll-flow 60

# 4. 停环境
bash scripts/playtest-down.sh 247
```

脚本只读接口，不需要 admin：`GET /catalog`、`GET /world/planets/{id}/scene?x=&y=&width=&height=`、
`/runtime`、`/networks`。环境变量：`SW_PLAYER_KEY`（默认 `key_player_1`）、
`SW_PLANET_ID`（默认 `planet-1-1`）。

**夹具里必须有的东西**（cp-belt-dsp 场景，改动导出窗口时逐项核对）：

- 铜主线 y=153 x48..56 地面带，带上有货（铜锭）
- 侧汇支带 (48..50,152) → (50,152) 转南汇入 (50,153)
- 铁线 x=53：1 层高架在 (53,152)(53,153)，(53,154) 落坡
- 5 台分拣器，含 (53,157) 隔一空格的跨格分拣器
- 4 座补给站（b-126/b-130/b-128/b-132）、风机、电塔

导出后打开 `BeltDspTop` 核对：三股流向、高架与地面带的交叉、分拣器摆臂都在画面里。

## 新增别的场景夹具

1. 起环境、把场景搭出来（优先从已有存档点读档，避免从零手搓）。
2. 用 `scripts/export-scene-fixture.mjs <N> <x0> <y0> <x1> <y1> <out.json>` 导出到
   `client-web/src/stories/fixtures/<名字>.json`。
3. 在 `PlanetMapThree.stories.tsx` 里复制 `BeltDspStage` 的模式：换 fixture import，
   给每个机位写 `CameraView`（focus / tilt / zoom）。故事标题保持 `Planet/<名字>Fixture`，
   故事 id 即 `planet-<名字>fixture--<kebab-case 导出名>`。
4. 在 `tests/belt-visual.spec.ts` 的 `STORIES` 里加一项（`name` = 导出名的 kebab-case，
   `snapshot` = PNG 文件名），跑 `--update-snapshots` 生成基线。
5. 大夹具注意体积：场景 JSON 只含窗口内的实体，24×24 窗口约 260 KB；窗口越大
   `terrain`/`height` 数组越大，Storybook 首屏会变慢。

## 已知边界

- **纯静态 `storybook build` 产物没有 `window.__planetThree`**（测试钩子只在 dev 构建或
  `VITE_E2E=1` 的生产构建里存在），故事壳的固定机位依赖它。因此夹具回归跑的是
  `storybook dev`，不是静态站。若要接静态站，需要在故事里改用 `PlanetMapThree` 的
  `onCanvasReady` + 一个 story 专用的机位 prop（尚未做）。
- Playwright 的 GPU 参数与 `playwright.config.ts` 一致（`--use-angle=vulkan` 等），
  无 Vulkan 驱动时 Chromium 自动回退 SwiftShader，画面仍可渲染但基线会有差异——
  基线以当前机器为准，跨机器重生成。
