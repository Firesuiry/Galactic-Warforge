## 1. 细分网格（服务端为准）

**做法：网格整体细化，不引入"格中格"第二套坐标。** 原来的 1 格（tile）变成 3×3 个小格（cell），坐标系仍是一套整数 `Position`，只是单位变成 cell。建筑用已有的 `Footprint{Width,Height}`（`building_surface.go` 的 `FootprintTiles` 已支持跨面）真实占多格；传送带、分拣器、电线杆、单位占 1 格。

### 1.1 建筑占地（cell）

| 占地 | 建筑 |
|---|---|
| 1×1 | 传送带 mk1/2/3、分流器、自动集装机、流速监测器、分拣器 mk1/2/3、集装分拣器、电力感应塔、无线输电塔、信号塔、地基（地形层） |
| 2×2 | 风力涡轮机、蓄电器(含满)、各类炮塔（高斯/导弹/激光/等离子/防空/火炮/内爆/超远程）、干扰塔 |
| 3×3 | 采矿机、大型采矿机、抽水站、原油萃取站、各熔炉、各制造台、重组式制造台、原油精炼厂、分馏塔、化工厂、量子化工厂、矩阵研究站、自演化研究站、火力发电厂、太阳能板、地热站、微型聚变电站、能量枢纽、小型/大型储物仓、储液罐、卫星配电站、兵营、补给站、喷涂机、配送器（叠在仓库上，占地同宿主仓库，见下） |
| 5×5 | 战场分析基站（HQ）、行星内/星际物流运输站、重型车间(vehicle_factory)、机场、人造恒星、射线接收站、电磁轨道弹射器、垂直发射井、微型粒子对撞机、行星护盾发生器 |

配送器叠在仓库上：占地取所在仓库的占地（3×3），Z=1 规则不变。

### 1.2 占地带来的规则

- **放置**：`build` 的 position 是占地左上（或现有 FootprintTiles 的锚点约定，保持一种），全部 cell 必须可建造且空闲；旋转对非正方形占地交换宽高。
- **占用表**：`TileBuilding` 为占地每个 cell 都登记；拆除全部清掉。
- **传送带 ↔ 建筑**：建筑的 IO 不再是"本格四邻"，而是**占地外圈一圈相邻 cell**：指向占地内任一 cell 的传送带末端=输入；从占地边缘出发、方向背离建筑的传送带起点=输出。端口容量规则不变。
- **分拣器**：沿方向扫描到的第一个 cell 若属于某建筑占地即连上该建筑（range 以 cell 计；第 19 轮起 `sorter_mk1/mk2/mk3/pile_sorter` 的 `range` 全为 3，最短布局「带|分拣器|机器」两端各 1 步）。
- **采矿**：采矿机覆盖**占地内及外扩 1 格**的资源 cell（DSP 式框选矿脉）；资源节点仍是单个 cell，矿脉在地图生成时按 cell 成簇（原 1 个资源格 → 3×3 左右的一簇 cell，总储量守恒）。
- **单位**：位置是 cell；一 cell 一地面单位 + 一空中单位的占位规则不变；不能进入建筑占地。
- **距离类数值 ×3（一次性改数据，不加运行时倍率常量）**：单位 move_speed、攻击/视野/建造/补给半径、电网覆盖与连接距离、炮塔射程、配送器/无人机航程与速度、黑雾/ bot 各类半径与基地布局偏移、寻路预算（800 → 按实测放大，保证跨基地寻路仍可用）、地图 face_size 与出生点/资源坐标。时间类数值（tick、冷却、生产时长）不变。传送带 throughput 是"每 tick 跨一格的件数"，数值不变（视觉上物料按 cell 走，速度自然变成原来的 1/3 世界距离，合理）。
- **地图**：skirmish 96→288、midgame/war 48→144；默认 map.yaml 816 若放大到 2448 内存不可接受，则保持 816 cell（世界变小但仍远大于可玩范围），实测内存后定。
- **旧存档/存档点**：坐标语义变了，旧存档直接拒绝加载（与当年 cube_sphere 迁移同样处理），不写兼容层。存档点树需要重建，另行安排。

## 2. 运输机器人（transport_robot）

定位：开局就能用的"慢而灵活"的搬运单位，补传送带铺不到/还没解锁时的缺口。**运力必须远小于传送带**：传送带 mk1 = 2 件/tick；机器人一趟 4 件、往返几十 tick，约 0.05 件/tick 量级。

| 项 | 值 |
|---|---|
| id / 名称 | `transport_robot` / 运输机器人 |
| 生产 | 战场分析基站（HQ）生产，无科技门槛 |
| 造价 | 铁块×4、齿轮×2、磁线圈×1，生产 300 tick |
| 属性 | 地面、占 1 cell、HP 60、无武器、视野 12 cell、move_speed 0.9 cell/tick |
| 载量 | 每趟 4 件、单一物品 |
| 上限 | 每玩家 20 台 |

**指令**：并入现有 `unit_order` 体系（新增 order 类型 `haul`，参数 `from_building_id`、`to_building_id`、可选 `item_id`；`stop` 清空路线）。CLI 同名动词、文档同步。

**行为循环**：前往起点建筑占地外圈的相邻空 cell → 装货（从起点产物缓存/仓储取，未指定物品时取"终点当前能接收"的第一种）→ 前往终点相邻 cell → 卸货（遵守与装入建筑相同的接收规则，含给产出留空）→ 回起点。起点无货在起点等，终点满在终点等。任一端建筑消失：路线清空、机器人停下、发一条事件。无能耗。可被敌方攻击；bot 不必使用。

**查询暴露**：单位 JSON 带 `haul: {mode, from_building_id, to_building_id, item_id, phase(to_source|loading|to_target|unloading|waiting_source|waiting_target|idle), cargo, delivered_total, idle_reason?, idle_detail?}`，客户端据此画路线和货物；自动模式空闲时 `idle_reason`（`no_demand` / `cargo_no_destination` / `no_reachable_demand` / `last_aborted`）说明为什么没活干——缺料建筑都由分拣器喂料时是 `no_demand`（`idle_detail` 写明），`no_reachable_demand` 只留给真正到不了/无供给的需求；选中条显示「带着 4 铁矿 待命：没有可送的地方」「上一单中止：…」「自动待命：没有需要机器人送的（缺料机器都由分拣器喂料）」。

### 2.1 全局自动模式（2026-10-14 用户新增，出厂默认）

机器人有三种模式：`auto`（全局自动，**出厂默认**）、`route`（固定路线，即上面的 haul）、`idle`（停止待命）。`unit_order order=auto_haul` 切回自动，`order=haul` 进入固定路线，`order=stop` 进入待命。

**需求（缺料机器）**：本行星上己方、已通电、设了配方的生产建筑（熔炉/制造台/化工等，含研究模式研究站的矩阵、兵营/补给站等按配方或生产队列需要原料的建筑同理），对配方的每种原料计算
`缺口 = 目标库存 − (主库存 + 输入缓冲 + 已被机器人认领在途量)`，目标库存 = 该原料 2 批用量（受产出预留后的可用容量封顶）。缺口 > 0 即为一条需求；建筑当前因缺料停工（state_reason 缺料）的需求优先级高于"只是偏低"。

只服务**己方**建筑：需求、供给、回仓落点、带货改派都按机器人的 `owner_id` 过滤（试玩 1016 严重 1：旧实现会派 p1 的机器人给 p2 的熔炉送料，永久空转）。**已有分拣器喂料的机器不派单**——某座己方运行中分拣器的放货端对着该建筑时，它由分拣器负责供料（DSP 式布局里这类机器本来就被分拣器/带子围死，机器人挤不进去）；拆掉分拣器后自动回到派单范围。这类建筑到不了时静默放弃（记冷却、不发 `haul_unreachable` 告警），不刷告警条。

**供给**：仓储类建筑（小/大型储物仓、储液罐、物流站库存、补给站）的主库存，以及生产/采集建筑的**输出缓冲**（只取成品，绝不从生产建筑主库存里拿它自己的原料，避免来回倒腾）。补给站在目录里是 `production` 类（它不生产任何东西，只放补给），按 `haulIsStorageSink` 的纯仓储判据认作仓储。供给同样按"已被认领量"扣减。

**分配（防止扎堆）**：每 10 tick 给空闲机器人派单。对每台空闲机器人，在所有"未认领缺口 > 0"的需求里打分选一个：`分 = 机器人到需求建筑距离 + 已服务该建筑的机器人数 × 惩罚(30 cell)`，缺料停工的需求距离按 0.5 倍计（优先救停工）；同一建筑同时最多 2 台机器人服务。选中后再为该原料挑"离需求建筑最近、未认领余量 > 0"的供给，**认领**数量 = min(4, 缺口, 供给余量)，需求与供给都登记认领，其他机器人看到的缺口随之减少——缺口被认领满的机器不会再吸引机器人，空出来的去管别的缺料机器。

**执行与收尾**：去供给 → 装货（按实际取到量修正认领）→ 去需求 → 卸货（接收规则同 transfer_item）→ 释放认领 → 回到空闲等下一次派单。中途任一端消失、到达时供给已空或需求已满：释放认领，带着的货优先送给另一台缺同种原料的机器，否则送回最近的仓储，都没有就带着货待命。没有任何需求时原地待命（不乱跑）。

**范围与性能**：只服务本行星己方建筑；派单用球面直线距离打分，寻路只对选中的那一单做；每玩家最多 20 台，派单每 10 tick 一次。

## 3. 界面重排（client-web）

目标：地图占满视口，HUD 都是贴边的半透明浮层，参考戴森球计划——底部居中的快捷建造栏、四角小件、需要时才弹出的面板。

### 3.1 去掉右侧 Outliner

- 删 `src/widgets/Outliner.tsx`、其测试与 `shell.css` 样式；`AppShell` 不再有右栏，所有页面都变宽。
- 原来的去向：焦点行星/恒星系 → 顶栏导航已有；舰队 → 战争页；警报 → §3.3 警报条。

### 3.2 HUD 布局（行星页）

- **顶栏**：变薄（约 44px），在行星页叠在地图上方半透明，不占布局高度；左 logo+导航图标，中间 tick/资源/电力，右侧铃铛/音量/存档/设置。
- **左上**：行星信息收成一行小胶囊（名称 · 电力 · 研究），点开展开原详情与「生产规划」。
- **左侧**：新手引导默认收成一行（当前步骤标题 + 进度 n/9），点开看详情。
- **左下**：镜头控制收成竖排小图标（全球视角/聚焦基地/缩放/画质/图层），设置项用弹出层。
- **底部居中：DSP 式快捷栏**。一行分类页签（电力/采集/运输/生产/研究/仓储/军事…，带数字键 1–9），下面一行方形图标格（约 52px，角标快捷键，缺料格变暗+红角），**详细造价/缺料只在悬停浮层显示**，不再常驻大卡片。选中条贴在快捷栏上方。
- **右下**：小地图（约 180px）。
- **右侧**：工作台抽屉保持右缘滑出，覆盖在地图上，不预留宽度。
- toast 从右下移到右上（顶栏下方），不再跟小地图抢位置。

### 3.3 警报条

顶栏下方居中一条窄条：默认只显示**最新一条**（图标 · 类型 · 建筑 · tick）+ 总数徽标 + 展开箭头；点开下拉列表（最多显示 8 条、可滚动，按建筑+类型合并计数），点某条聚焦到对应建筑。无警报时整条隐藏。数据源沿用 TopNav 的 alert snapshot（含研究站噪声过滤），去掉与 Outliner 共用 query key 导致的 limit 混用。

## 4. 客户端细分网格表现

- 建筑按占地画满 W×H cell（3D 模型按占地缩放），传送带/分拣器/单位是 1 cell 的小件，视觉比例接近 DSP。
- 3D 相机默认距离按新比例调（2D 的按 cell 缩放档已随 2D 视图删除，第 20 轮）。
- 传送带物料：3D 方块滑动（`three/industrial-activity.ts`）按 cell 尺寸，**每格方块要能看清物品颜色**，选中传送带时详情显示带上物品。
- 运输机器人：小型轮式机器人模型，车顶显示货物方块；选中时画起点→终点的虚线路线与阶段文字；选中条提供「设置运输」：依次点起点建筑、终点建筑，可选物品。
