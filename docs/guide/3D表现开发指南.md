# 3D 表现开发指南

## 目标与边界

目标是达到《戴森球计划》式星球工业观感，包含近景机械细节、自然地表、空间尺度、运行动画、光照和清晰操作。后端继续负责生产、物流、战斗、资源与权威坐标；前端仅表现已收到的状态，不增添虚假的建筑、运输任务或可见情报。

当前已完成行星工业表现的一轮重构：原创统一工业资产、材质地表、球面岩地装饰、动态阴影、环境反射、辉光、星空大气、倾斜镜头、建造栏模型缩略图。全球视角与地面视角使用同一个等角立方体球面：六个方格面组成球面拓扑，南北极分别位于完整面内部，不再使用经纬条带投影或按极区短边缩小建筑。服务端与前端共享面序、边界邻接及方向转换；具体坐标约定见 [立方体球面网格](立方体球面网格.md)。地形未知区域使用扫描蒙层，不生成猜测的大陆。

最新画质档位、生产规划和六阶段发展导航见 [工业发展与画质增强](工业发展与画质增强.md)。

## 操作与实现

- 行星和恒星系页默认 3D；右上可切换平面战术。行星右上“恒星系”进入轨道视图，选择星体后可返回行星或打开战术调兵。
- 拖动旋转，滚轮或按钮缩放，俯仰滑条调整镜头；全球视角拉远、聚焦基地返回近景。
- 点击建筑或单位查看详情，建造栏选择建筑后点地表放置；单位选中后点移动，再点目标地表。Esc 和右键取消当前指令模式。
- `planet-three-scene.ts` 负责场景、镜头、输入和后端快照同步，`three/` 分离投影、地表、工业资产与空间表现。
- 工业资产共享模板几何/材质，`StaticBatches` 按图层、几何和材质跨建筑实例化静态部分；`DynamicBatches` 独立合批转子/钻头等动画子树，仅更新变化的姿态；生产状态变化和世界旋转不重建静态实例。实例射线拾取映射真实建筑地块。岩地装饰最多 4000 个实例；Three.js 按需加载。冻结截图使用 `?freeze=1`。
- 已知不可建造岩地生成局部岩脊，排除实体占地；真实水域增加动态水波和岸线，可建造面保持原高度。
- `IndustrialActivity` 用真实传送带 buffer、运行状态、生产剩余 tick 和物流位移生成货物、火花、热气和短尾迹；暂停设备停止机械动画。
- `system-three/` 绘制恒星日冕、已发现行星与后端提供的戴森节点/框架/球壳/太阳帆。轨道相位未由 API 提供，因此采用明确标注的态势示意；runtime 不可用时隐藏相关物体和统计。
- DEV 下 `window.__planetThree.project(tile)` 只辅助定位真实画布点击，验收必须核对真实 POST 与后端最终状态。

## 当前球面协议与接缝处理（2026-09-15）

- `surface.topology` 为 `cube_sphere`，`surface.face_size=N`；服务端 x/y 是 3N×2N 图集中的权威坐标。六面编号和投影公式必须与共享 surface 模块一致。
- 局部地表按面独立生成 mesh；overview 实际 step 整除 N，不能跨面混合降采样。点击、选中圈、建筑姿态和尺寸采用同一个球面映射。
- scene 主窗口保留图集矩形含义，`near_x/near_y/radius` 提供跨接缝 `surface_patches`；每片有独立 bounds 和迷雾。未探索补片地形为 unknown，不得从相邻图集像素推测地表。
- 建造前自动靠近须查询服务端 `/world/planets/{id}/path`，以执行体的操作范围作为 `stop_range`，使用返回的 waypoints 执行移动；浏览器不再按 x/y 曼哈顿距离拆路。范围内返回空 waypoints；不可达或未知目标不得继续自动建造。每段移动后仍须处理权威失败回执。
- 建筑蓝图的矩形选区及旋转粘贴范围须完整位于单个面内；跨接缝结构应分面建立蓝图。该限制针对建筑布局蓝图，不是战争单位蓝图。

## 运行与验证

在仓库根启动隔离战争测试服：

```sh
bash server/scripts/start_official_war_test_server.sh 19481
```

在 `client-web/`：

```sh
VITE_SW_PROXY_TARGET=http://127.0.0.1:19481 npm run dev -- --host 127.0.0.1 --port 4173
npm run build
npm test
SW_SKIP_WEBSERVER=1 npx playwright test tests/planet-three.spec.ts tests/system-three.spec.ts --workers=1
```

浏览器测试使用战争服 p1，验证旋转缩放、详情、建造和移动的请求坐标/响应/后端结果、退出模式、平面与3D切换，并检查页面和 WebGL 错误。测试服状态会改变；重复验收会选择当前可用地块。

## 后续可选改进

本轮通过功能测试不等于达到《戴森球计划》的完整美术水平。当前仍采用程序化工业模型，近景材质和地景密度有提升空间。真实战争服当前只有少量已知岩地和水格，无法展示大范围海岸；不得为了截图虚构地形。后续应继续验证混合建筑与完整后处理的大场景整帧耗时、距离 LOD，以及真实移动硬件表现。千栋同类静态工厂的绘制调用结果不能替代这些验证。

## 历史工业材质与动态实例（2026-09-10）

- `industrial-finishes.ts` 生成共享的陶瓷面板缝/紧固点、拉丝合金和底座格栅贴图；颜色用 sRGB、粗糙度与法线用线性数据，启用 mipmap，纹理随模型库释放。没有新增外部素材或下载依赖。
- 降低陶瓷金属度，提高表面粗糙度；提高辉光阈值并配合设备发光材质，减少白色外壳泛光。62 种透明模型缩略图已重新渲染。
- 动画合批保留原动画对象，仅复制转子姿态；暂停或隐藏不上传实例矩阵，恢复时同步，实例拾取对应原建筑地块。
- Chromium SwiftShader 的 1000 台同类风机诊断：未合批 24000 次绘制、仅静态合批 14010 次、静态与动态合批 16 次；三角形始终 4848000。1000×750、阴影512、无后处理的隔离基准中，8 帧测得平均18.65ms，矩阵更新3.52ms。此数据为该配置的短采样，不代表完整行星混合工业场景或移动硬件 FPS。
- 486 项单测和生产构建通过；真实浏览器4项通过，包含建造(5,0)、移动(2,0)的202与后端核对、系统往返、390px操作、戴森响应增删。页面与WebGL错误为零。
