# SiliconWorld 玩法指南

本文回答：**当前版本玩家实际能玩什么、按什么顺序推进。** 启动方式见 [本地环境与测试](../dev/本地环境与测试.md)，验收路径见 [试玩验收清单](试玩验收清单.md)，命令参数见 [客户端CLI](../dev/客户端CLI.md)，接口见 [服务端API](../dev/服务端API.md)。

## 0. 开局、续档与存档

- `server.data_dir` 是一局游戏的目录，固定包含 `meta.json` 与 `save.json`（gzip 压缩，查看前先 `gunzip`）。
- 目录不存在或为空 → 新开一局；两个文件都在 → 续档；只有一个或目录残缺 → 拒绝启动，需手动清理。
- 自动保存默认每 60 秒；也可 CLI `save` 或 Web 顶栏“保存”。不支持多槽位，多局并存就用多个目录。
- 续档时目录里的 `battlefield`、玩家、地图配置优先于外部配置；端口、限流、自动保存周期等运行参数以本次启动为准。不持久化 RNG。
- 不停服重开：CLI `game_new`（仅 admin）。

| 路线 | 配置 | 适合 |
| --- | --- | --- |
| 普通新局 | `config-dev.yaml + map.yaml` | 从零开荒到中期工业 |
| 官方中后期 | `config-midgame.yaml + map-midgame.yaml` | 直接验证气态行星、戴森、射线接收、高阶建筑（预置中后期科技与物资，故意不预置 `dirac_inversion`） |
| 官方战争 | `config-war.yaml + map-war.yaml` | 直接验证蓝图→量产→舰队→战区→封锁 |
| 遭遇战 | `config-skirmish.yaml + map-skirmish.yaml` | 对 bot 的一局完整对战 |

## 1. 这是什么游戏

以 Tick 驱动的星际工业 + 战争策略游戏：服务端权威结算，玩家通过命令（Web、CLI 或 AI 智能体）操作。

- 主线闭环：**研究 → 解锁建筑/配方 → 建造 → 发电 → 采矿 → 物流/仓储 → 冶炼/生产 → 防御/战斗**。
- 中后期：行星/星际物流、轨道采集、太阳帆、戴森球、射线接收、蓝图军工、舰队与战区。
- 三层世界：银河 → 恒星系 → 行星，逐层扫描发现。
- 默认胜利规则 `hybrid`：摧毁对手 `battlefield_analysis_base`，或率先完成 `mission_complete`（`summary` 返回 `winner` / `victory_reason` / `victory_rule`，并推 `victory_declared`）。

### 球面地格

行星表面是六个方格面拼成的立方体球面，极地也有完整地格。显示的 x/y 是六面存储图集坐标：数值差很大的两格可能相邻，不能靠坐标差估算路程。移动、操作范围、传送带连接都按球面邻接计算；建筑布局复制的选区必须在同一面内（战争蓝图不受影响）。

## 2. 开局拥有什么

- 基地 `battlefield_analysis_base`（本身不发电）、玩家机甲 `executor`（建造效率 1、操作范围 6、并发任务 2）。
- 资源 `minerals = 240`、`energy = 100`；背包为空，**不预置电磁矩阵**。
- 已发现主银河、出生恒星系、出生行星。
- 已完成 `dyson_sphere_program`：直接解锁 `wind_turbine`、`mining_machine`、`arc_smelter`、`tesla_tower`、`conveyor_belt_mk1`、`sorter_mk1`、`assembling_machine_mk1`、`matrix_lab`。
- 出生点保证 `iron_ore` 与 `copper_ore` 在操作距离内。

## 3. 核心概念

### 3.1 玩家机甲

机甲负责建造、升级、拆除，也能移动、攻击、手动采矿、个人制造。受操作范围和并发上限约束，超范围命令以 `OUT_OF_RANGE` 失败；建造可加 `--approach` 让机甲先自动走过去。

- 生命 120、攻击 20、防御 8、射程 4。核心能量初始 100：攻击耗 8，每走一格耗 1，能量不足整条操作失败。
- 补能：`refuel_mecha <executor_id> <fuel_item_id> <quantity>`（煤 25，其他燃料见 `/catalog.items[].mecha_fuel_energy`；溢出部分作余能，每 tick 最多转入 10）。靠近运行中的自有电力感应塔（4 格，≤2/tick）或无线输电塔（6 格，≤10/tick）自动充电，只用同网剩余供电。
- 科技：“机甲核心”每级 +10 容量，“驱动引擎”每级 +2 移动范围，“能量护盾”每级 +20 护盾。护盾优先吸伤，受击 10 tick 后每 tick 耗 1 能量恢复至多 2 护盾。
- 手动采矿：`mine_resource`，需在矿点 2 格内，每件 10 tick、耗 10 能量，只能采有限固体矿点。
- 个人制造：`craft_item`，只限 `handcraft_allowed` 配方（铁锭、铜锭、石砖、磁铁、高能石墨、齿轮、电路板、磁线圈），启动时预留全部原料，quantity 为批数。
- 同时只能有一个采矿或制造任务；`cancel_mecha_job` 退回未完成批次原料。
- 机甲物流：可设物品下限/上限，由仓库配送器自动补给与回收（`configure_mecha_logistics`）。

### 3.2 资源两层

- `minerals` / `energy`：全局资源池。采集建筑**实际挖出**的矿会按比例直充 minerals（矿机本地满仓也不停）。
- `inventory`：玩家背包物品。生产建筑的产物进入建筑自己的存储。
- `transfer <building_id> <item_id> <quantity>` 把背包物品装进建筑；加 `--take` 从建筑取回。发射太阳帆、火箭等命令读的是建筑本地存储。

### 3.3 研究

- 研究随 Tick 推进，可排队；至少需要 1 个 `running` 的研究站（`matrix_lab` 不设配方即研究模式）。
- 所需矩阵必须已在研究站本地库存，推进时真实消耗。
- `summary` 的 `tech.current_research.blocked_reason`：`waiting_lab` / `waiting_matrix` / `low_power`；`speed_multiplier` 与 `estimated_ticks_remaining` 反映供电降速。
- Web 行星页“研究与装料”页签：分“当前可研究 / 已完成 / 尚未满足前置”，新局有开局引导。
- `/catalog.techs[].leads_to` 标出桥接科技通向哪里；没有收益的死胡同科技已从公开目录移除。

### 3.4 发现、加载与焦点

- **已发现**：星图可见；**已加载 runtime**：可查 `runtime` / `networks`；**焦点行星**：不带 `--planet` 的建造默认落点。
- `switch_active_planet` 只改自己的焦点，只能切到已加载且自己有 foothold 的行星；所有已加载行星始终结算。

### 3.5 战争迷雾

只能看到自己建筑和单位视野内的内容，靠扩建、炮塔、单位移动拓展视野。

### 3.6 一切皆命令

所有操作都是 `POST /commands` 里的命令，入队后在后续 Tick 执行；同步返回只表示受理，结果看事件流 `command_result`。

## 4. 推荐推进路线

### 阶段 A：看清位置

先查 `summary`、行星详情、迷雾，确认基地、矿点、水域、油井位置；再 `scan_galaxy` → `scan_system` → `scan_planet` 建立全局地图观。

### 阶段 B：供电 + 采矿

1. 基地正交相邻格建 `wind_turbine`。
2. 确认目标矿点在操作范围内，否则先移动机甲。
3. 用 `tesla_tower` 把电网接过去。
4. `mining_machine` 必须压在矿点上，只采压住的那条矿脉；`advanced_mining_machine` 覆盖自身 2 格（约 5×5）内全部矿脉。
5. 没电的建筑进入 `no_power`。`veins_utilization` 每级 +10% 产出、-6% 矿脉消耗（最高 6 级）。

目标：让资源由负增长转为自增长。

### 阶段 C：自产第一批电磁矩阵

`electromagnetism` 需要 10 个 `electromagnetic_matrix`，只能靠产线：

1. `arc_smelter`：铁矿 → 磁铁（`smelt_magnet`）/ 铁块（`smelt_iron`）；铜矿 → 铜块（`smelt_copper`）。
2. `assembling_machine_mk1`：2 磁铁 + 1 铜块 → 2 磁线圈；1 铁块 + 1 铜块 → 电路板。
3. 1 磁线圈 + 1 电路板 → 电磁矩阵（制造台或 `matrix_lab --recipe electromagnetic_matrix`）。

最低原料账：20 铁矿 + 15 铜矿，配方全部无需研究。之后建空 `matrix_lab` 并通电，装入 10 个矩阵，`start_research electromagnetism`，完成后解锁 `depot_mk1`。

Web：行星页“研究与装料”→ 选 `electromagnetism` → 给研究站装矩阵 → 开始研究。

### 阶段 D：早期科技与产线骨架

- `basic_logistics_system`：`splitter` / `sorter_mk2` / `traffic_monitor`。
- `automatic_metallurgy`：玻璃配方；`basic_assembling_processes`：通往热电、太阳能、半导体。
- 传送带连续运输，分拣器在建筑与皮带间装卸，仓库做缓冲。
- 配方可建造时用 `--recipe` 指定，也可 `set_recipe <entity_id> [recipe_id]` 原地切换（进度清零、库存保留；省略配方时研究站回研究模式、生产建筑空闲）。研究站要留空配方才做科研。

**垂直叠层**：研究 `vertical_construction` 后，在同类研究站/生产建筑上再 `build` 同类建筑会叠层（`position.z` 递增），上限 = 1 + 已完成级数。研究站叠层共享底层库存、吞吐线性叠加；拆下层会级联拆上层。

**四向分流器**：默认西入、东南北出，缓存 24 件，每 tick 收发各 6 件。Web 详情“四向分流器”里给四个端口选输入/输出/关闭、设优先口与出口过滤；CLI 用 `configure_splitter`（每次完整替换，省略即清除）。过滤口堵塞时匹配物品会等待，不会钻进只收别的物品的出口；想要旁路就留一个“所有物品”出口。

**流速监测器**：绑定相邻自有传送带，按真实流出量统计窗口吞吐；完整窗口积货无流出显示堵塞，可开低流量告警。

### 阶段 E：电力、液体、化工

- 方向：`solar_panel`、`thermal_power_plant`、`water_pump`/`storage_tank`、`oil_extractor`/`oil_refinery`、`chemical_plant`/`quantum_chemical_plant`、`fractionator`、`spray_coater`。
- `water_pump` 必须压在 `water` 上，`oil_extractor` 必须压在 `crude_oil` 上，产物先进自身存储再外运。
- 原油精炼 `oil_fractionation`：2 原油 → 2 精炼油 + 1 氢（60 tick），给两种产物都接出料带。X 射线裂解：1 精炼油 + 2 氢 → 3 氢 + 1 高能石墨；重整精炼：2 精炼油 + 1 氢 + 1 煤 → 3 精炼油。
- 生产建筑只缓冲有限批次输入，停线先查缺料、缺电、副产物去向。混线时下游会优先补不同物料，两路合流可稳定供料。
- 化工建筑预留一条出货边；晚期酸线要接出货带或仓库，否则会被反压。
- 燃料发电：`thermal_power_plant` 吃 `coal`，`mini_fusion_power_plant` 吃 `hydrogen_fuel_rod`，`artificial_star` 吃 `antimatter_fuel_rod`，每 tick 耗 1；燃料耗尽的那个 tick 仍计发电。
- 普通加工设施按实际获配电力减速（半电 = 双倍时间），断电保留进度。

**蓄电器**：`energy_exchanger` 用 `set_energy_exchanger_mode <id> charge|discharge|standby` 在空/满蓄电池间转换（每件 100 能量、每 tick 1 件），经 `acc-in`/`acc-out` 端口进出，满电池可运到别的电网放电；自带 400 容量直接蓄电模块。

**分馏与增产剂**：`fractionator`（需 `deuterium_fractionation`，6 能量/tick）西入氢、东出未转化氢、南出氘，方向固定。每件氢每次通过 1% 变氘，把东侧氢绕回西侧形成回流。`spray_coater`（需 `proliferator_mk1`）西入东出、北侧补增产剂，也可 `transfer` 装增产剂；缺剂时货物原样通过。

| 增产剂 | 每份可喷 | 每件氢可用分馏次数 | 单次分馏概率 | 配方（制造台） |
| --- | --- | --- | --- | --- |
| Mk.I | 12 | 4 | 1.25% | 2 煤 → 1，20 tick |
| Mk.II | 24 | 6 | 1.5% | 2 Mk.I + 1 金刚石 → 1，40 tick |
| Mk.III | 60 | 8 | 2% | 1 碳纳米管 + 2 Mk.II → 1，60 tick |

喷涂增益目前只接入分馏；普通制造台的增产效果尚未贯通（见 [known-issues](known-issues.md)）。

**微型粒子对撞机**（`miniature_collider`，24 能量/tick，建造时 `--recipe`）：

| 配方 | 投入 | 产出 | 周期 | 科技 |
| --- | --- | --- | --- | --- |
| `deuterium_collision` | 10 氢 | 5 氘 | 300 | `miniature_collider` |
| `strange_matter` | 2 粒子容器 + 10 氘 + 2 铁锭 | 1 奇异物质 | 480 | `strange_matter` |
| `antimatter` | 2 临界光子 | 2 反物质 + 2 氢 | 120 | `dirac_inversion` |

### 阶段 F：防御与军队

**地面单位**：用 `produce <building_id> <unit>` 在对应建筑生产，造价为实物，从生产建筑自身库存扣（`transfer` 或皮带供料），排队有时长、停电暂停；`set_rally_point` 设集结点。

| 生产建筑 | 单位 |
| --- | --- |
| 兵营 | `worker` 工程兵、`soldier` 步兵、`scout` 侦察车 |
| 战车工厂 | `mecha` 重装机甲、`artillery` 火炮、`missile_vehicle` 导弹车、`repair_vehicle` 维修车、`supply_truck` 补给车 |
| 机场 | `attack_drone` 攻击无人机 |

- 单位实时移动、自动交战；`order` 支持攻击移动/巡逻/守卫/坚守/跟随/撤退/停止，可逗号批量。
- 军团：`form_squad` 编成（可含补给车），`squad_order attack|defend|retreat|resupply`，`dissolve_squad` 解散。
- 弹药：单位打空后停火；进入 `supply_station`（半径 10）或 `supply_truck`（半径 5）范围自动补满。
- 炮塔：`gauss_turret`、`missile_turret`（`ammo_missile`）、`implosion_cannon`（`gravity_missile`）、`laser_turret`（电力）、`plasma_turret`（`plasma_capsule`）、`artillery_turret`（`shell_set`）、`anti_air_turret`（`ammo_missile`，可击落敌方物流无人机）。缺弹缺电停火，补弹恢复。
- 地基 `foundation` 可铺在水面/熔岩/阻挡地形上变为可建，拆除恢复原地形。

**蓝图单位**（`prototype`、`precision_drone`、`corvette`、`destroyer` 及玩家定型蓝图）：

1. 以公开蓝图为父本 `blueprint_variant`，或 `blueprint_create` + `blueprint_set_component`。
2. `blueprint_validate` → `blueprint_finalize`。
3. `queue_military_production` 在军工设施排产（成本从背包扣），`war_industry` 看部署枢纽 `ready_payloads`。
4. `deploy_squad`（地面小队）或 `commission_fleet`（舰队）进入运行态。部署枢纽默认是 `battlefield_analysis_base`，必须通电。
5. 舰队：`fleet_assign` 阵型、`fleet_attack`（同星系）、`fleet_move`（直达航线，10 tick）、`fleet_disband`。
6. 指挥：`task_force_*` 任务群、`theater_*` 战区（区域内有敌情推 `theater_zone_alert`）、`blockade_planet` 封锁。
7. 观察：`fleet_status`、`system_runtime`、`planet_runtime`、`task_forces`、`theaters`。

Web `/war` 页面可全程完成蓝图、军工、部署、任务群、战区和封锁。

### 阶段 G：大工业网络与物流

设施：Mk.II/III 传送带与分拣器、`splitter`、`traffic_monitor`、`depot_mk2`、`planetary_logistics_station`、`interstellar_logistics_station`、`logistics_distributor`。

物流站一条铁矿跨站线：

1. 研究 `planetary_logistics`，建两座行星站并接电。PLS：160 矿/80 能，3 槽×200，最多充 10/tick 至 1000，基础用电 1。ILS（`interstellar_logistics`）：280 矿/140 能，5 槽×500，最多充 30/tick 至 10000，基础用电 2。
2. 制造运输器：无人机 = 2 电动机 + 2 处理器 + 5 铁块（120 tick）；货船 = 2 电动机 + 10 处理器 + 10 钛合金（300 tick）。`install_logistics_vehicle <站> logistics_drone 1`（背包）或加 `--source station`（站库）。每站最多 10 无人机、ILS 另 5 船，建站不送运输器。
3. 源站 `configure_logistics_slot <源站> planetary iron_ore supply 0`，目标站 `... demand 100`。`none` 是本地存储槽；同物品跨 scope 只占一槽。
4. 皮带口：`configure_logistics_station <站> --belt-ports west:input:iron_ore`，每口 6 件/tick，每次完整替换全部端口。
5. 无人机起飞预扣往返 `2×max(1,距离)` 电量，真实去程、装卸、返航。目标同物品满仓时显示 `waiting_unload` / `destination_full`。

星际运输需两端开启星际、runtime 已加载；曲速需开关、距离阈值、起飞站至少 2 个 `space_warper`（配 `none` 槽装料）和往返能源，默认每航次耗 `30×距离`。删除槽用 `--remove`（先清库存、端口和在途）。站库不保留喷涂属性。

Web：“工作台 → 物流”配置站点与槽位；选中站点后“详情 → 物流站运行与接线”看库存、电池、运输器并安装载具。

**仓库配送器**：建在 `depot_mk1/mk2` 原点，配置供给/需求与保有量，安装配送机器人（`install_logistics_bot`）；供电且航程能量足够才派遣，机器人真实飞行。

### 阶段 H：星图扩张

扫描更远星系，筛选资源型星球和气态行星，规划戴森与星际物流目标。已加载且有 foothold 的星球可切过去继续经营。

### 阶段 I：太阳帆、射线接收与戴森球

- `em_rail_ejector` 装 `solar_sail` 后 `launch_solar_sail`；`vertical_launching_silo` 默认配方 `small_carrier_rocket`，装好后 `launch_rocket <silo> <system> --layer N`，目标层需已有 `build_dyson_*` 结构。
- `build_dyson_node/frame/shell` 直接搭戴森结构（材料门槛尚未全部硬约束，偏实验性），`demolish_dyson` 拆除。
- `ray_receiver`：`set_ray_receiver_mode power|photon|hybrid`（`photon` 需 `dirac_inversion`）。没有太阳帆/戴森供能时不产电；`power`/`hybrid` 下 `summary.resources.energy`、`stats.energy_stats.generation` 与 `/world/planets/{id}/networks` 的 `supply` 同步上涨。切到 `power` 后不再新增 `critical_photon`，但旧库存不清零。
- 火箭成功发射会提高目标层 `construction_bonus`。
- `orbital_collector` 只能建在气态行星上（官方 midgame 的 `planet-1-2`）。

**全矩阵**（除电磁矩阵外都需同名科技）：

| 矩阵 | 投入 | 周期 | 建筑 |
| --- | --- | --- | --- |
| `electromagnetic_matrix` | 1 磁线圈 + 1 电路板 | 60 | 制造台 / 研究站 |
| `energy_matrix` | 1 高能石墨 + 1 氢 | 80 | 制造台 / 研究站 |
| `structure_matrix` | 1 钛块 + 1 塑料 | 90 | 制造台 / 研究站 |
| `information_matrix` | 2 处理器 + 1 量子芯片 + 1 碳纳米管 | 120 | 研究站 / 重组制造台 |
| `gravity_matrix` | 2 量子芯片 + 1 奇异物质 | 150 | 研究站 / 重组制造台 |
| `universe_matrix` | 五种矩阵各 1 + 1 反物质 | 150 | 研究站 |

中后期建筑 `jammer_tower`（减速场）、`sr_plasma_turret`、`planetary_shield_generator`（给建筑充能吸伤）、`self_evolution_lab`（空配方为高级研究站）适合在官方 midgame 验证。制造台 Mk.II/III 加工速度分别为 Mk.I 的 2/3 倍（齿轮 Mk.I/II/III 为 20/10/7 tick），耗电更高。

## 6. AI 委派

需启动 agent-gateway（Web `/agents` 页或 CLI `agent_*`）。

- 先用玩家命令建好 `task_force` / `theater`，再 `agent_update --theater-ids ... --task-force-ids ...` 显式委派。
- 只给 `combat` 类别不够，战争命令还需命中 `--military-command-ids`；`blockade_planet` / `queue_military_production` 另受 `--allow-blockade` / `--allow-military-production` 和排产上限约束。
- `agent_thread` 与 `/agents` 页可看到智能体做了什么、为什么、是否需要批准。
