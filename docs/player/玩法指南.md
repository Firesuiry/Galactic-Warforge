# SiliconWorld 玩法指南

> 本文基于当前 `server/` 已实现代码与 `docs/` 现有文档整理，目标不是描述“理想中的完整设计”，而是回答：**现在这版服务端，玩家实际上能玩什么，应该怎么一步一步向外扩张。**
>
> 如果你已经看过 `docs/player/上手与验证.md` 或 `docs/dev/服务端API.md`，这份文档可以理解为它们的“玩法版总纲”。

## 0. 如何开始新游戏 / 继续上一局 / 存档在哪里

- 服务端现在把 `server.data_dir` 当成“一局游戏的工作目录”。
- 想开始新游戏：把 `server.data_dir` 指向一个不存在或空目录后启动服务端。
- 2026-09-15 起行星改用六面球面网格；旧经纬/平面地图存档不能续用，请保留原目录并新建一局。新配置使用 `planet.face_size`，不再使用 `planet.width/height`。
- 想继续上一局：下次启动时继续使用同一个目录；只要里面同时有 `meta.json` 和 `save.json`，服务端就会直接续档。
- 如果目录里只有一个文件，或者目录非空但不是完整存档，服务端会拒绝启动；这类 partial 目录需要你手动清理或重建，避免把坏状态当成新局继续跑。
- 当前一局游戏的持久化文件固定就是：`<data_dir>/meta.json` 和 `<data_dir>/save.json`。
- `save.json` 以 gzip 压缩存储（文件名不变，不再是明文 JSON）；同一球面拓扑版本写出的未压缩 `save.json` 启动时会自动识别并正常续档，下次保存自动转为压缩格式。如需查看内容，先 `gunzip` 再按 JSON 阅读。
- 自动保存默认每 `60` 秒刷新一次 `save.json`；也可以用 CLI `save` 或 Web 顶栏的“保存”按钮手动落盘。
- 第一版不持久化 RNG 状态，所以续档后未来随机事件不保证和“不停服一直玩下去”完全一致；保证的是当前世界状态能继续玩。
- 续档时，目录内部保存的 `battlefield`、玩家列表、地图配置优先于外部配置；端口、限流、历史窗口、自动保存周期等纯运行参数仍按本次启动配置覆盖。
- 当前不做多槽位或命名存档点。如果你想并行保留多局游戏，做法是准备多个不同的 `data_dir`。

当前推荐有两条启动路线：

- 普通新局：`config-dev.yaml + map.yaml`，适合从开局一路推进到中期工业化。
- 官方中后期场景：`config-midgame.yaml + map-midgame.yaml`，会直接把 active planet 固定到气态行星，并预置 `vertical_launching`、`gas_giants`、`solar_sail_orbit`、`ray_receiver`、`signal_tower`、`plasma_turret`、`gravity_matrix`、`planetary_shield`、`self_evolution`、`integrated_logistics`、`photon_mining`、`annihilation` 等中后期科技与测试物资；因此 `jammer_tower`、`sr_plasma_turret`、`planetary_shield_generator`、`self_evolution_lab`、`advanced_mining_machine`、`pile_sorter`、`recomposing_assembler` 都能在官方 midgame 直接验证。`dirac_inversion` 则故意不预置，用来保留 `photon` 模式的门禁验证。

## 1. 当前版本是什么类型的游戏

当前 `server` 最适合被理解成一款：

- 以 **Tick 驱动** 为核心的工业经营游戏；
- 以 **active planet 为当前操作焦点，但允许在多个已加载行星之间切换经营** 的经营/建设游戏；
- 带有 **银河 -> 恒星系 -> 行星** 逐层发现机制的外层探索游戏；
- 带有 **战争迷雾、基础单位战斗、防御塔、敌对势力、太阳帆、戴森球框架** 的中后期扩展游戏。

已经打通的主线闭环大致是：

**研究 -> 解锁建筑/配方 -> 建造 -> 发电 -> 采矿 -> 物流/仓储 -> 冶炼/生产 -> 防御/战斗**

中后期还有：

- 行星物流 / 星际物流调度
- 同星系已加载行星之间的最小跨星球物流
- 轨道采集器
- 太阳帆发射
- 戴森球节点 / 框架 / 壳面
- 射线接收

但其中一部分目前更像“系统已存在、玩家入口还不够完整”的阶段，本文会在后面明确指出。

### 行星上的地格、移动与建造

地表由六个方格面拼成球面，极地也有完整地格。经过面边缘仍可继续移动、铺设传送带和连接网络，方向会随地表转换。界面或 CLI 显示的 x/y 是六面存储图集坐标：数值相差很远的两格可能相邻，数值紧挨的两格也可能分属不相接的边，不能靠坐标差估计路程。

执行体操作范围与移动范围均按球面地格距离计算。移动还需要可走路径，建筑或不可通行地形会阻挡；一次命令不得超过单位移动范围。自动靠近建造时，路径规划让执行体停在操作范围内即可，不必站到建造目标上。目标未探索、路径不通或局势变化导致移动失败时，先处理探索或移动问题，再建造。

复制建筑布局时，矩形选区及旋转后的放置范围必须完整位于同一面。需要跨接缝的工厂可以分面复制，再连接接缝两侧；这条限制不影响战争蓝图的组件配置和军工流程。

## 2. 开局你拥有什么

每个玩家开局默认拥有：

- 一座基地：`battlefield_analysis_base`
- 一个执行体单位：`executor`
- 基础资源：
  - `minerals = 240`
  - `energy = 100`
- 初始背包：
  - 空；默认新局**不再预置电磁矩阵**，第一门研究的矩阵必须靠自己的产线生产
- 执行体默认能力：
  - 建造效率 `1.0`
  - 操作范围 `6`
  - 并发任务数 `2`
- 已发现内容：
  - 主银河
  - 出生恒星系
  - 出生行星
- 初始已完成科技：
  - `dyson_sphere_program`
    - 直接提供整套基础工业建造权限：`wind_turbine`、`mining_machine`、`arc_smelter`、`tesla_tower`、`conveyor_belt_mk1`、`sorter_mk1`、`assembling_machine_mk1`、`matrix_lab`

这意味着默认新局的第一段目标已经固定下来——先铺一条小型产业链，自产第一批电磁矩阵：

- 基地本身不发电，所以第一步要先在基地正交相邻格补一台 `wind_turbine`
- 用 `tesla_tower` 把电网接到资源点，拍下 `mining_machine` 开始采铁矿 / 铜矿
- 用 `arc_smelter` 冶炼：铁矿 -> 磁铁 / 铁块，铜矿 -> 铜块
- 用 `assembling_machine_mk1` 加工：磁铁 + 铜块 -> 磁线圈，铁块 + 铜块 -> 电路板，磁线圈 + 电路板 -> 电磁矩阵
- 把自产的 `electromagnetic_matrix` 装进空 `matrix_lab`（不设置 `recipe_id` 即为研究站），才能合法启动第一门 `electromagnetism`

当前默认胜利条件是 `hybrid`：

- **摧毁对手的 `battlefield_analysis_base`**
- 或者率先完成终局科技 `mission_complete`
- 当 `mission_complete` 研究完成后，会立即触发 `game_win`；`summary` 会返回 `winner` / `victory_reason` / `victory_rule`，事件流里会追加 `victory_declared`

## 3. 先懂这 6 个核心概念

### 3.1 玩家机甲与建设指令

玩家机甲 `executor` 可以在地图上移动、攻击、手动采矿、个人制造，并通过背包燃料或附近电塔补能，还承担建设操作：

- 建造
- 升级
- 拆除
- 生产单位
- 研究推进辅助

执行体有操作范围和并发上限，所以你不能无限同时施工。

### 3.2 资源有两层：`minerals/energy` 和 `inventory`

当前服务端里，玩家资源至少分成两层：

- `minerals` / `energy`：更像全局基础资源池，许多建造和单位生产直接消耗它
- `inventory`：玩家物品库存，用于部分物品型消耗与返还

同时，建筑本身还有自己的存储/输出缓存。也就是说：

- **矿机产矿** 主要先变成玩家的 `minerals`
- **生产建筑做出来的物品** 主要进入建筑自己的存储
- 像 `launch_solar_sail` 这样的中后期命令，会直接读取目标建筑本地已经装载的物品，而不是默认读玩家背包
- 现在玩家已经有公开装填入口：`transfer <building_id> <item_id> <quantity>`，可把背包物品直接装到建筑本地存储

这点会直接影响部分高级玩法，后文会专门提醒。

### 3.3 研究是按 Tick 自动推进的

当前研究系统已经可用，但实现方式要特别注意：

- 研究可以排队
- 研究会随 Tick 自动推进
- 至少需要 1 个处于 `running` 的研究站
- `matrix_lab` 不设置 `recipe_id` 时会作为研究站；设置了 `recipe_id` 时则按普通生产建筑运行
- `start_research` 时，所需每种矩阵都必须已经出现在研究站本地库存中
- **研究推进会真实消耗研究站本地库存中的矩阵，不再是抽象研究点**
- 缺研究站或缺矩阵时，`summary` 里的 `tech.current_research.blocked_reason` 会显示 `waiting_lab` / `waiting_matrix`；研究站供电不足时显示 `low_power`，并可通过 `speed_multiplier`（供电速度倍率）和 `estimated_ticks_remaining`（预估剩余 tick）确认降速程度

如果你走 `client-web` 的行星页，`研究与装料` 页签现在已经按这套真实规则做成阶段化研究工作台：

- 顶部直接展示当前研究进度，以及 `waiting_lab` / `waiting_matrix` 这类阻塞原因
- 中部会分成 `当前可研究` / `已完成` / `尚未满足前置`
- 默认新局在 `electromagnetism` 完成前会给出开局引导；自产矩阵的产业链铺好后，按引导把矩阵装入研究站即可开研

所以当前版本的研究体验更接近：

**满足前置 -> 摆研究站并保持通电 -> 把矩阵装进研究站 -> 开始研究 -> 随 Tick 消耗真实矩阵 -> 获得解锁**

### 3.4 “发现世界” 和 “实际经营” 不是一回事

当前支持扫描：

- `scan_galaxy`
- `scan_system`
- `scan_planet`

扫描后你能逐步看到更多星图信息，但这不等于你已经能像经营出生星球那样去完整建设所有星球。

当前要区分三层状态：

- **已发现**：可以在星图里看到
- **已加载 runtime**：可以查询该星球的 `runtime / networks`
- **当前 active planet**：新命令默认落到这颗星球上执行

也就是说：

- 外层探索可用
- 跨星图信息发现可用
- 已加载且你已有 foothold 的星球，可以通过 `switch_active_planet` 切过去继续经营
- 同一恒星系、已加载行星之间的星际物流最小闭环已经接通

### 3.5 战争迷雾是真实存在的

玩家只能看到自己视野内的内容，主要来自：

- 自己的建筑视野
- 自己单位的视野

你可以查行星迷雾图，也可以利用扩建、防御塔、单位移动去拓视野。

### 3.6 所有操作本质上都是“命令驱动”

当前玩家可用操作，本质都走命令系统。比较核心的有：

- 建造 / 升级 / 拆除
- 配置物流站 / 物流槽位
- 生产单位
- 移动 / 攻击
- 扫描银河 / 星系 / 行星
- 开始 / 取消研究
- 取消 / 恢复施工
- 切换当前 active planet
- 把玩家背包物品装填到建筑本地存储
- 切换 `ray_receiver` 模式
- 发射太阳帆
- 建造 / 拆除戴森球结构

命令进入队列后，会在后续 Tick 执行。

## 4. 推荐的扩张路线：从出生点一路推到外层世界

这一节是最重要的“玩法顺序”。

### 阶段 A：先看清你在哪，别急着乱造

开局第一件事，不是立刻铺建筑，而是先确认：

- 当前 Tick
- 当前 active planet 是哪颗星球
- 基地附近有哪些可建地块
- 附近矿点、水域、油井、危险区域分布
- 当前迷雾覆盖范围

建议先做的查询：

- 世界摘要
- 当前行星详情
- 当前行星迷雾
- 银河 / 恒星系总览

如果你想把“外层世界”也点亮，推荐顺序是：

1. `scan_galaxy`
2. `scan_system`
3. `scan_planet`

这一步的意义是：先建立全局地图观，再决定后续目标。

### 阶段 B：第一优先级永远是“拿到稳定供电 + 采矿”

开局科技 `dyson_sphere_program` 已经直接提供整套基础工业建筑，**不需要先研究任何东西**就能开始工业化：

- `wind_turbine` / `tesla_tower`：发电与输电
- `mining_machine`：采矿
- `arc_smelter`：冶炼
- `assembling_machine_mk1`：基础制造
- `conveyor_belt_mk1` / `sorter_mk1`：基础物流
- `matrix_lab`：研究站 / 矩阵生产

推荐顺序：

1. 先在基地正交相邻格建第一台 `wind_turbine`
2. **先确认执行体到目标矿点是否在操作范围内；超出范围就先移动执行体**
3. 视距离补 `tesla_tower`，把电网接出去
4. 把 `mining_machine` 直接压到铁矿 / 铜矿资源点上

当前默认图里，基地附近已经有一处能直接接通的 starter 矿点，公开验证顺序就是：

1. `build 4 2 tesla_tower`
2. `build 5 1 mining_machine`

如果你后续想接更远的矿点，再去考虑移动执行体和继续延长电网；但默认新局的第一条采矿闭环本身已经不需要拆研究站，也不需要先走位绕路。

这里有两个硬规则：

- `mining_machine` **必须建在资源点上**，且只采它压住的那一条矿脉；`advanced_mining_machine` 则以自身为中心覆盖 2 格（切比雪夫距离，约 5x5）内的全部矿脉、多脉同采，单条脉都不在范围内时不产出
- `veins_utilization`（矿物利用）每级 +10% 采矿产出、-6% 矿脉消耗，最高 6 级，按脉分别生效
- 建造、拆除、生产等执行体操作都受 **操作范围** 限制；超范围命令会在后续 tick 以 `OUT_OF_RANGE` 失败
- 建筑没电会进入 `no_power`，电力是所有后续系统的前提

你可以把这一阶段的目标理解成：

**先把“资源是负增长”变成“资源开始自己涨”**

### 阶段 C：铺冶炼 + 制造，自产第一批电磁矩阵

默认新局不再发启动矩阵。第一门科技 `electromagnetism` 需要 `10` 个 `electromagnetic_matrix`，而这只能靠产业链生产：

1. 铁矿 --`arc_smelter`(smelt_magnet)--> 磁铁；铁矿 --(smelt_iron)--> 铁块
2. 铜矿 --`arc_smelter`(smelt_copper)--> 铜块
3. 磁铁 x2 + 铜块 x1 --`assembling_machine_mk1`(magnetic_coil)--> 磁线圈 x2
4. 铁块 x1 + 铜块 x1 --`assembling_machine_mk1`(circuit_board)--> 电路板
5. 磁线圈 x1 + 电路板 x1 --`assembling_machine_mk1` 或 `matrix_lab`(electromagnetic_matrix)--> 电磁矩阵

10 个电磁矩阵的最低原料账：`20` 铁矿 + `15` 铜矿。

这些配方**全部无需研究**，矩阵配方对 `assembling_machine_mk1` / `matrix_lab` / `self_evolution_lab` 都可用；给生产建筑指定配方的方式是在建造时传 `--recipe <recipe_id>`。

产够 10 个矩阵后：

1. 建一台空 `matrix_lab`（不传 `recipe_id`，保持研究站模式）并保证通电
2. 把 `10` 个 `electromagnetic_matrix` 装进这台研究站
3. `start_research electromagnetism`

`electromagnetism` 完成后解锁 `depot_mk1`（小型仓库），并打开后续全部 2 级科技的前置。

如果你走 Web，这一段对应的最短操作路径是：

1. 打开行星页 `研究与装料`
2. 选中 `electromagnetism`
3. 给 `matrix_lab` 装入 `10` 个 `electromagnetic_matrix`
4. 点击 `开始研究`

### 阶段 D：补齐早期科技与产线骨架

推荐继续推进以下早期核心科技：

- `basic_logistics_system`：解锁 `splitter` / `sorter_mk2` / `traffic_monitor`，把“采出来”变成“送得动”
- `automatic_metallurgy`：解锁 `smelt_stone`（玻璃）配方
- `basic_assembling_processes`：通向 `thermal_power` / `solar_collection` / `semiconductor` 等制造科技的桥梁

这一阶段你要做的，不是堆高级建筑，而是把物料流真正串起来：

- 传送带负责连续运输
- 分拣器负责建筑和传送带之间的装卸
- 仓库负责缓冲

同时保留第一台空 `matrix_lab` 继续滚科技，再补第二台 `matrix_lab --recipe electromagnetic_matrix` 扩大矩阵生产。

这里有一个当前版本非常重要的实现细节：

- **生产建筑的 `recipe_id` 可以在建造时一起指定，也可以事后用 `set_recipe <entity_id> [recipe_id]` 原地切换，不必拆了重建**
- `set_recipe` 省略 `recipe_id` 时，研究站（`matrix_lab` / `self_evolution_lab`）切回研究模式、普通生产建筑转为空闲；切换后生产进度清零、建筑库存保留；配方必须是该建筑类型支持且已研究解锁的，校验失败原子拒绝、原状态不变
- **研究站要留空 `recipe_id` 才会进入科研模式；如果你给 `matrix_lab` 指定了配方，它就不会再当研究站**

所以你在造生产建筑时最好先想清楚用途，但改线现在只需要一条命令。

### 垂直叠层：向上要产能

研究 `vertical_construction` 后，对已被同类型研究站/生产建筑占据的格子再次 `build` 同类型建筑，会作为叠层放在上一层（`position.z` 递增），不重复占地。叠层上限 = 1 + `vertical_construction` 已完成级数（未研究不能叠层）。研究站叠层共享底层库存、研究吞吐按层线性叠加；拆除任一叠层时同格更高叠层会级联拆除，并按各自建筑类型/等级以同一返还率退款。

### 四向分流器：分线、合流与过滤

解锁 `basic_logistics_system` 后可以建造 `splitter`。默认从西侧收货，向东、南、北三侧出货；缓存最多 24 件、每 tick 最多收/发各 6 件，刚收到的物品要到后续 tick 才能继续出货。接入朝向匹配的相邻传送带，保持建筑处于运行状态。

选中分流器，在建筑详情的“四向分流器”里给北、东、南、西四个端口选择“输入”“输出”或“关闭”，至少保留一个输入和一个输出。同一口不能同时进出；也可以设多个入口合流。配置“优先输入”“优先输出”时，优先口没有货或无法输出会尝试其它可用口；选择“轮流输入/输出”则在合格口之间轮换。

每个出口可选择一种过滤物品，也可选“所有物品”。例如东口只收铁矿、南口只收铜矿，就能将混线分开；若东口堵塞，铁矿会等待，不能钻进只允许铜矿的南口。若要堵塞旁路，将南口设为“所有物品”、东口仍过滤铁矿并设东口优先：东口可用时先出铁矿，堵塞后铁矿可走南口，铜矿也可以从南口出。未过滤口能接受任何物品，过滤不会自动把匹配物品保留给某个专用出口。

点击“应用分流设置”提交服务器，修改端口角色会同步清掉不再适用的优先级/过滤；“还原当前配置”放弃未提交编辑。详情还显示带内缓存、缓存物品、累计搬运件数和最近搬运 tick。累计数只统计实际从分流器送出的件数；配置重置轮询起点，但不清货物或搬运统计。

CLI 示例（`b-splitter` 换为真实建筑 ID）：

```text
configure_splitter b-splitter --inputs west --outputs east,south --output-priority east --filters east:iron_ore
```

CLI 每次完整替换配置，省略优先级/过滤选项会清除旧设置，不表示保留。要清空过滤和优先级，可执行 `configure_splitter b-splitter --inputs west --outputs east,south`。跨星球面边界的方向由球面邻接计算，实际连线以地图为准。

这些是当前四向分流器的可配置行为；流速监测器、配送器和完整集装物流仍需各自的实现与验收。

### 阶段 E：把电力、液体、化工链拉起来

当你已经有了稳定的早期采矿 + 冶炼 + 制造之后，就该进入能源升级和液体化工阶段。

建议重点关注这些方向：

- `solar_panel` 对应的太阳能路线
- `thermal_power_plant` 对应的燃料发电路线
- `water_pump` / `storage_tank` 对应的液体基础设施
- `oil_extractor` / `oil_refinery` 对应的石油链入口
- `chemical_plant` / `quantum_chemical_plant` 对应的化工升级
- `fractionator` 对应的氢/氘相关链条
- `spray_coater` 对应的喷涂增益路线

这一阶段的核心目标是：

- 把“只靠矿和简单电力”的基地，升级成“有油、有化工、有高级能源”的工业基地

这里有一个当前版本已经验证过的硬约束：

- `water_pump` 必须直接建在 `water` 资源点上
- `oil_extractor` 必须直接建在 `crude_oil` 资源点上
- 这两类采集建筑会先把产物写进自己的本地存储，再由相邻传送带/仓储继续外运
- `oil_fractionation` 在原油精炼厂执行：2 原油 → 2 精炼油 + 1 氢，60 tick/批；给精炼油和氢分别接出料传送带，防止副产堵塞。研究 X 射线裂解后可用 1 精炼油 + 2 氢生产 3 氢 + 1 高能石墨；重整精炼则用 2 精炼油 + 1 氢 + 1 煤生产 3 精炼油。裂解的氢、重整的精炼油需经外部回流或玩家补料作为下一批原料。
- 生产建筑当前只会为配方输入保留有限批次缓冲，不会再无限吸料把库存塞满；如果高级链路停住，优先检查缺料、缺电、输出/副产物去向
- 当前传送带混线在下游半满时会优先补入不同物料，不再因为固定源顺序把后一种原料长期饿死；像 `water + stone_ore` 这种两路合流现在可以稳定驱动 `sulfuric_acid`
- 真实地图里资源点旁边经常夹着 `water` 或其他不可建地，晚期液体/化工链不要只按“资源坐标差一格”纸面排布，先确认中间带位和建筑位真的可建
- 化工/制造建筑最好从一开始就给成品预留一条可出货边；如果四周全封成输入，虽然本地存储还能积货，但下一段产线会很难自然接上
- 晚期酸线如果要持续往后喂石墨烯，别只让成品停在一格输出带上；至少补一段北侧传送带或一座相邻 `depot_mk1`，否则 `sulfuric_acid` 很快会被出货侧反压

燃料型发电建筑的当前 authoritative 口径也已经固定：

- `thermal_power_plant` 消耗 `coal`
- `mini_fusion_power_plant` 消耗 `hydrogen_fuel_rod`
- `artificial_star` 消耗 `antimatter_fuel_rod`
- 这三类建筑都按 `consume_per_tick = 1` 逐 tick 消耗燃料
- 如果最后一根燃料在当前 tick 被消耗完，`inspect` / `scene` 在该 tick 结束时仍会显示 `running`，而 `/world/planets/{planet_id}/networks` 与 `stats.energy_stats` 也会继续保留这个 tick 的真实供电收益
- 只有下一 tick 仍然没有新燃料时，它们才会回到 `no_power / no_fuel`

你会开始真正感受到：

- 不同建筑需要更稳定的供电
- 物流拥堵会影响产线
- 仓储、流量监控、喷涂都会开始有意义

### 蓄电器充放：电力的时间与空间转移

`energy_exchanger`（蓄电器能量枢纽）接入电网后，用 `set_energy_exchanger_mode <building_id> <charge|discharge|standby>` 控制蓄电池物品循环：

- `charge`：用电网盈余把空蓄电池（`accumulator`）充成满蓄电池（`accumulator_full`），每件 100 能量、每 tick 最多转换 1 件
- `discharge`：把满蓄电池放电回电网，并返还空蓄电池
- `standby`：不做物品转换（新建建筑的默认模式）

空/满蓄电池经建筑的 `acc-in` / `acc-out` 端口用传送带或分拣器进出，满蓄电池可以运到另一片电网甚至另一颗星球放电，实现间接输电。建筑本身还带 400 容量的直接蓄电模块（充/放 80 每 tick、效率 95%），不依赖物品循环也能平抑电网波动。非法模式、非蓄电器目标或非己方建筑都会被拒绝且不改变当前模式。

### 氢回流、增产剂与对撞机

研究 `deuterium_fractionation` 后建造 `fractionator`，不必选择配方。它需要 6 能量/tick：西侧进氢，东侧出未转化的氢，南侧出氘。三个方向固定，当前不能旋转，也不接受管道或直接装料；入口和出口都接方向匹配的自有传送带。每 tick 最多处理 6 件，输入、回流氢和氘缓存各容纳 24 件。

把东侧氢通过外部传送带绕回西侧，再把南侧氘送入仓库或后续产线。每件氢每次通过有 1% 概率变成 1 氘；失败仍是同一件氢，留在机器里不会自动再抽一次。氢出口或氘缓存堵满会停止新尝试；停电不会消耗氢或刷新随机结果，存档继续原有缓存、计数和随机序列。短时间没有氘不一定是故障，先看累计尝试、回流是否通畅和两路出口容量。

研究 `proliferator_mk1` 后可以在氢回流线上加 `spray_coater`，供电 2/tick。喷涂机西侧进货、东侧出货、北侧补增产剂，每 tick 最多处理 6 件。增产剂也可用 `transfer <喷涂机ID> proliferator_mk1 <数量>` 从背包装入；不能用 transfer 往喷涂机装氢，氢必须走西侧皮带。缺剂时原料原样通过，不会锁住整条线；停电或输出缓存满则停止处理。

默认增产剂效果如下；增产剂必须来自真实库存，表中的喷涂余量会保留到后续货物使用：

| 增产剂 | 每份可喷货物数 | 每件氢可用分馏次数 | 有效喷涂时的单次分馏概率 |
| --- | --- | --- | --- |
| Mk.I | 12 | 4 | 1.25% |
| Mk.II | 24 | 6 | 1.5% |
| Mk.III | 60 | 8 | 2% |

增产剂本身按 Mk.I → Mk.II → Mk.III 逐级升级，全部在制造台（Mk.I/II/III）生产、由同名科技解锁：

| 配方 | 每批投入 | 每批产出 | 基础周期 | 需要完成的科技 |
| --- | --- | --- | --- | --- |
| `proliferator_mk1` | 2 煤 | 1 增产剂 Mk.I | 20 tick | `proliferator_mk1`（前置 `semiconductor` + `plasma_control`） |
| `proliferator_mk2` | 2 增产剂 Mk.I + 1 金刚石 | 1 增产剂 Mk.II | 40 tick | `proliferator_mk2`（前置 `processor`） |
| `proliferator_mk3` | 1 碳纳米管 + 2 增产剂 Mk.II | 1 增产剂 Mk.III | 60 tick | `proliferator_mk3`（前置 `high_strength_material`，成本含结构矩阵） |

Mk.III 是明显的后期产线：碳纳米管要化工链，科技本身还要消耗结构矩阵。

分馏每尝试一次就消耗该件氢的一次效果，失败回流仍保留余量；余量耗尽后恢复 1%。把氢绕回喷涂机时，尚有余量的氢直接通过，不重复消耗增产剂，耗尽后才重新喷涂。机器优先用完已开封那份剂量，再优先选库存中的高等级增产剂。这条喷涂增益当前已接入分馏，不能据此认为普通制造台的全配方增产已完成。

进入后期，研究 `miniature_collider` 可建造 `miniature_particle_collider`。它每 tick 需要 24 能量，建造时用 `--recipe` 选择下列配方；反物质还需要更晚的 `dirac_inversion`，仅研究对撞机并不能生产反物质。

| `--recipe` | 每批投入 | 每批产出 | 基础周期 | 需要完成的科技 |
| --- | --- | --- | --- | --- |
| `deuterium_collision` | 10 氢 | 5 氘 | 300 tick | `miniature_collider` |
| `strange_matter` | 2 粒子容器 + 10 氘 + 2 铁锭 | 1 奇异物质 | 480 tick | `strange_matter` |
| `antimatter` | 2 临界光子 | 2 反物质 + 2 氢 | 120 tick | `dirac_inversion` |

建造命令格式为 `build <x> <y> miniature_particle_collider --recipe <配方ID>`，实际坐标须可建且在机甲操作范围内。原料通过皮带或 `transfer` 装入；反物质线必须同时给氢安排出路。对撞机每批先消耗原料，断电保留进度，满仓保留整批待输出且不会吞掉下一批原料，清空出口后恢复；存档也保留这些批次。

目前已具备分馏回流、喷涂消耗和这三种对撞配方的实际结算，但端口旋转、普通新局全科技及原料获取路线、普通制造台喷涂效果仍需补齐或验收。不要把这些局部产线当成全套星球加工设施已经完成。

### 阶段 F：从“能生产”走向“能守住”

当前服务端已经有较明确的战斗与防御框架，所以中期一定要补防御。

可建造的防御/战斗相关建筑包括：

- `gauss_turret`
- `missile_turret`
- `implosion_cannon`
- `laser_turret`
- `plasma_turret`
- `signal_tower`

这一阶段建议做两件事：

1. 在基地、矿区、关键产线附近补炮塔
2. 用单位做侦查和压制

单位生产方面，当前最重要的现实细节是：

- 玩家可以用 `produce` 生产单位
- `/catalog.world_units` 当前只公开世界单位；当前版本实际可直接 `produce` 的还是：
  - `worker`
  - `soldier`
- `/catalog.warfare.public_blueprints` 当前公开战争预置蓝图；现阶段已经开放：
  - `prototype` / `precision_drone`
  - `corvette` / `destroyer`
- `/catalog.warfare.public_blueprints` 只代表“公开蓝图目录”，不代表可以跳过军工流程直接落 runtime
- 当前真实高阶单位闭环是：
  1. 以公开预置蓝图为父本，或自己 `blueprint_create` 一份玩家蓝图草案
  2. `blueprint_set_component` / `blueprint_validate` / `blueprint_finalize`
  3. 用 `queue_military_production` 在军工设施排产
  4. 用 `war_industry` 观察 `deployment_hubs[].ready_payloads`
  5. 再用 `deploy_squad` / `commission_fleet` 把载荷变成 runtime 实体
- `battlefield_analysis_base` 现在就是默认部署枢纽；在官方战争验证局里，它已经和 `recomposing_assembler`、物流站、补给节点一起预置完毕
- 当前公开高阶单位线已经打通：
  - `prototype` / `precision_drone`
    - 通过 `deploy_squad` 进入 `planet runtime` 的 `combat_squad`
  - `corvette` / `destroyer`
    - 通过 `commission_fleet` 进入 `system runtime` 的 `fleet`
- 高阶舰队线的后续控制也已经公开：
  - `task_force_create` / `task_force_assign` / `task_force_set_stance` / `task_force_deploy`
  - `theater_create` / `theater_define_zone` / `theater_set_objective`
  - `fleet_assign` / `fleet_attack` / `fleet_disband`
  - `fleet_status` / `system_runtime` / `planet_runtime` / `war_industry` / `task_forces` / `theaters`
  - `blockade_planet` / `landing_start`

如果你不是想从普通新局慢慢推到战争，而是想直接验证战争系统，当前最稳的路径其实不是 midgame，而是专用的官方战争验证局：

- 启动 `config-war.yaml + map-war.yaml`
- 以 `p1 / key_player_1` 登录
- 先确认 `war_industry` 里能看到 `Orbital Supply Port`、`Planetary Logistics Station`、`Interstellar Logistics Station`
- 再走 `blueprint_variant -> blueprint_validate -> blueprint_finalize -> queue_military_production -> commission_fleet`
- 接着走 `task_force_*` 与 `theater_*`
- 最后用 `system_runtime` / `planet_runtime` / `fleet_status` 观察补给、contacts、battle_reports、planet_blockades、landing_operations`

也就是说，中后期的部队体系现在分成两层：

- 出门侦查
- 与敌方单位/建筑交火
- 配合炮塔进行区域控制
- 基地载荷部署
- 同星系舰队编队与轨道打击

### 阶段 G：把基地做成“更大的工业网络”

继续扩张时，你会逐渐进入“大产线”和“广域物流”的思路。

当前已经能摆出来的相关基础设施包括：

- 更高阶传送带：`conveyor_belt_mk2`、`conveyor_belt_mk3`
- 更高阶分拣器：`sorter_mk2`、`sorter_mk3`
- `splitter`
- `traffic_monitor`
- `depot_mk2`
- `planetary_logistics_station`
- `interstellar_logistics_station`
- `logistics_distributor`

科技树这一区间还有一个需要知道的公开语义变化：

- 当前玩家可见科技树会保留“桥接科技”
- 如果某个科技暂时没有直接 `unlock` / `effect`，但它仍然通向后续真实可玩的公开科技，`/catalog.techs[].leads_to` 会明确告诉你它把路线引向哪里
- 真正研究后没有直接收益、也不会导向公开收益的死胡同科技，当前版本已经从公开科技目录里移除

这一阶段可以建立有成本、有库存上限的物流线，先做一条铁矿跨站线：

1. 研究 `planetary_logistics` 并建两座行星站，接到有余量的电网。每站160矿/80能，3个物品槽、每项200；初建空电池，最多10能/tick充到1000，基础用电1。星际站需 `interstellar_logistics`、280矿/140能，5槽、每项500，基础用电2、最多充30/tick至10000。
2. 制造运输器成品：无人机2电动机+2处理器+5铁块，基础120tick；船2电动机+10处理器+10钛合金，基础300tick。给站点配置运输器物品的 `none` 本地槽和皮带入口，把制造台产物经皮带送入站库，再用 `install_logistics_vehicle <站ID> logistics_drone 1 --source station` 安装；若成品在玩家背包，省略source即可。星际站可改用 `logistics_vessel`。每站最多10架无人机，星际站另最多5艘船；建站和调整容量不会赠送运输器。
3. `configure_logistics_slot <源站> planetary iron_ore supply 0` 配供给，目标站配置 `planetary iron_ore demand 100`。`local_storage` 是保留/目标数量，必须不超过单项上限；`none` 是本地储存槽，同物品在本地/星际两种设置中只占一个槽。
4. 源站配西侧入口 `configure_logistics_station <源站> --belt-ports west:input:iron_ore`，目标站配东侧出口 `--belt-ports east:output:iron_ore`，再建设相邻且流向正确的皮带。也可用 `transfer <源站> iron_ore 100` 从背包装料。每口最多6件/tick，停电停IO；`--belt-ports` 每次完整替换全部端口，`none` 清空，省略才保持原配置。
5. 观察库存、电量和真实航次。供给站有车会送货，需求站有车也能空载过去取货；取货到达时才装货，回家才进入需求站库存。无人机每次起飞预扣往返 `2×max(1,球面距离)` 电量，船默认普通航行 `10×距离`；随后真实去程、卸货、返航，回家后才可再次派遣。

Web 中在“工作台 → 物流”配置站点与物品槽；选中己方物流站后，在“详情 → 物流站运行与接线”查看库存、容量、电池和运输器，并安装载具、配置皮带端口。对应浏览器回放的验收状态见[星球玩法覆盖与验收](../guide/星球玩法覆盖与验收.md)。

堵车时先查看目标站的**同种物品**是否已满：运输器会保留余货并显示 `waiting_unload` / `destination_full`，接出口腾出空间后继续卸货。删除物品槽用 `configure_logistics_slot <站ID> <scope> <物品> --remove`；必须先清库存、解除端口，并等相关运输/取货预约结束。目标被拆或变敌会带货返航，归属站失效则 `stranded` 保货，当前没有回收滞留运输器的命令。

星际运输还需启用星际配置，两端星球runtime已加载。曲速要求开关开启、距离达到阈值、起飞站有至少2个 `space_warper` 和往返能源；给曲速器配一个 `none` 槽并装料，默认曲速每航次耗 `30×距离` 电量，不满足时尝试普通航行。电量起飞已预扣，在途断电仍继续，供给站被动取货与目标卸货可在断电时发生。

当前站库只记录物品数量，带剩余喷涂用途的货物停在入口皮带；物流配送器、完整殖民和跨星系长期发展仍未完成，不能把本段站际闭环当成全部DSP物流已验收。

### 阶段 H：从行星经营走向星图扩张

当你基地变稳以后，就该做两件外扩动作：

1. 扫描更远的星系和行星
2. 评估中后期目标星体

当前探索链路非常清晰：

- 先看银河
- 再看系统
- 再看行星

你可以利用它做：

- 提前筛选资源型星球
- 判断哪里有气态行星
- 规划后续的戴森与星际物流目标

但是要记住：

- 当前服务端仍然把 active planet 当成主要操作焦点
- 但只要目标星球 runtime 已加载、你也已经在那里建立 foothold，它就不再只是“只可侦察”的信息点，而是可以切过去继续经营

### 阶段 I：进入太阳帆、射线接收和戴森球阶段

当前代码里，这部分系统已经有真实入口：

- `em_rail_ejector`
- `vertical_launching_silo`
- `ray_receiver`
- `launch_solar_sail`
- `launch_rocket`
- `build_dyson_node`
- `build_dyson_frame`
- `build_dyson_shell`
- `demolish_dyson`

玩家视角下可以这样理解：

- `EM-Rail Ejector`：装载并发射太阳帆
- `Vertical Launching Silo`：默认配方就是 `small_carrier_rocket`
- `launch_solar_sail`：把电磁发射器中已装载的太阳帆送入轨道
- `launch_rocket`：把垂直发射井中已装载的 `small_carrier_rocket` 送进指定戴森层
- `ray_receiver`：接戴森能量，甚至产出临界光子
- `build_dyson_*`：直接搭戴森球结构

当前这套玩法的关键前提是：

1. `launch_solar_sail` 当前只接受 `em_rail_ejector`
2. `launch_rocket` 当前只接受 `vertical_launching_silo`
3. 发射前要先把对应载荷通过传送带/建筑 IO 装进发射器本地存储
4. `launch_rocket` 目标层必须至少已有一个 `build_dyson_*` 脚手架
5. `set_ray_receiver_mode` 可把 `ray_receiver` 切到 `power` / `photon` / `hybrid`；其中 `photon` 需要先解锁 `dirac_inversion`

这意味着：

- **太阳帆发射链路已经接入正常建筑存储/装载流程**
- **火箭发射链路也已经可玩，但仍需要你自己把原料/火箭喂进 silo**
- **玩家不需要再把太阳帆转进个人 `inventory` 才能发射**
- **`ray_receiver` 本身不会白送基础能量；没有太阳帆/戴森供能时，它不会凭空产电或产临界光子**
- **火箭成功发射后会直接提高目标戴森层的 `construction_bonus`，后续 `ray_receiver` 能吃到更多可用输出**
- **当前真实供能会同时计入太阳帆轨道能和已建戴森球结构总产能，`ray_receiver` 最终吃到的仍受自身 `input_per_tick` 上限约束**
- **当 `ray_receiver` 切到 `power` / `hybrid` 且已存在太阳帆或戴森结构产能时，同一轮真实 tick 会同时抬高 `summary.players[pid].resources.energy`、`stats.energy_stats.generation` 与 `/world/planets/{planet_id}/networks.power_networks[].supply`**
- **当前公开 `inspect planet-1-2 building <ray_receiver_id>` 主要用于确认 `runtime.functions.ray_receiver.mode` 与建筑运行态；真正的 authoritative 电力回灌结果请看 `summary`、`stats` 与 `GET /world/planets/{planet_id}/networks`**
- **`power` 模式的验收口径是“切换后不再新增 `critical_photon`”而不是“把旧光子库存清零”；切模式前已经存在于 `inventory / output_buffer` 的历史光子会保留**
- **如果 `/world/planets/{planet_id}/networks.power_coverage` 已显示 `connected = true` 且网络 `shortage = true`，那么 `inspect` / `scene` / SSE 里的缺电原因应读作 `under_power`，不再是 `power_out_of_range`**

如果你走 Web，这一阶段现在也有对应的上下文提示：

- 把 `solar_sail` 装进 `em_rail_ejector` 后，命令账本会直接提示“下一步可发射太阳帆扩展戴森云”
- 把 `small_carrier_rocket` 装进 `vertical_launching_silo` 后，会提示“下一步可发射火箭构建戴森球结构”
- `set_ray_receiver_mode` 成功后，会按 `power / photon / hybrid` 三种模式分别提示应该观察电网回灌、光子产出或两者并行结果

同时，`build_dyson_node/frame/shell` 当前更偏“系统验证型入口”：

- 命令可用
- 结构会创建
- 但它不像传统主线玩法那样，已经把完整科技/材料门槛全部做成硬约束

所以这一阶段的正确认知是：

- 戴森球系统已经能体验
- 但更偏中后期实验性玩法，而不是完全成熟的最终主线
- 官方 midgame 现在也已经预置 `integrated_logistics`、`photon_mining`、`annihilation`，所以 `advanced_mining_machine`、`pile_sorter`、`recomposing_assembler` 不再需要玩家先手动补科研才能验证
- `recomposing_assembler` 现在已经补齐两条终局弹药配方：
  - `build <x> <y> recomposing_assembler --recipe antimatter_capsule`
  - `build <x> <y> recomposing_assembler --recipe gravity_missile`
- `prototype`、`precision_drone`、`corvette`、`destroyer` 这条高阶舰队线现在已经进入公开主线，但语义明确分流：
  - `produce` 仍只负责 `worker` / `soldier`
  - 高阶单位必须先做成载荷 item，再通过 `deploy_squad` / `commission_fleet` 进入 runtime
  - `fleet_attack` 当前只支持同一恒星系目标
  - 部署枢纽必须通电，否则会被 authoritative 校验以 `deployment hub is not operational: ...` 拒绝

## 6. 当前版本最值得玩家注意的现实边界

这一节非常重要，直接决定你玩的时候会不会“以为自己操作错了”。

### 6.1 当前主经营舞台基本还是 active planet

你可以扫描很多星球，而当前命令默认仍然会落到 active planet 上执行。

所以正确玩法是：

- 把 active planet 当当前施工与操作焦点
- 把已加载且有 foothold 的其他星球当成可切换的分基地
- 把还没加载或还没 foothold 的外层星球当作后续规划信息

### 6.2 研究已经是“矩阵实物消耗版”

当前研究会真实消耗研究站本地库存中的矩阵。

所以：

- 研究站必须处于 `running`
- 所需矩阵必须先进入研究站本地库存
- 如果 `start_research` 成功后又缺矩阵，研究会卡在 `blocked_reason = waiting_matrix`；电网供电不足时则为 `blocked_reason = low_power`，研究速度按 `speed_multiplier` 降倍

全矩阵产线现在已经贯通，五种基础矩阵都能在 `matrix_lab`（或同级建筑）量产，`universe_matrix` 再汇总五种矩阵加反物质：

| 矩阵 | 每批投入 | 基础周期 | 生产建筑 |
| --- | --- | --- | --- |
| `electromagnetic_matrix` | 1 磁线圈 + 1 电路板 | 60 tick | 制造台 / 研究站 |
| `energy_matrix` | 1 高能石墨 + 1 氢 | 80 tick | 制造台 / 研究站 |
| `structure_matrix` | 1 钛块 + 1 塑料 | 90 tick | 制造台 / 研究站 |
| `information_matrix` | 2 处理器 + 1 量子芯片 + 1 碳纳米管 | 120 tick | 研究站 / 重组制造台 |
| `gravity_matrix` | 2 量子芯片 + 1 奇异物质 | 150 tick | 研究站 / 重组制造台 |
| `universe_matrix` | 五种矩阵各 1 + 1 反物质 | 150 tick | 研究站 |

除电磁矩阵外，每种矩阵配方都要先完成同名科技；产矩阵的研究站和搞研究的研究站可以用 `set_recipe` 互相转换，不必各建一套。

### 6.3 生产建筑最好建造时就带上配方

`set_recipe` 已经可以原地改配方，但切换会清空当前生产进度（库存保留）。

所以建议：

- 一条线一个用途
- 一台机一个配方
- 少做频繁切换，每次切换都损失在制品进度

### 6.4 物流系统已经能玩，并且接入了最小多星球闭环

现在玩家已经可以直接使用：

- `configure_logistics_station`
- `configure_logistics_slot`
- `install_logistics_vehicle`

核心流程为 `造站 -> 接电充电 -> 配槽/端口 -> 制造成品并安装运输器 -> 真实往返配送`。供方送货与需方空载取货均消耗归属站往返电量；满仓保货、停电禁止新起飞。具体前提和命令见阶段 G。

但它仍有明确边界：

- 当前支持的是同一恒星系、已加载行星之间的最小星际物流
- 开放给玩家的物流参数还是收敛版，不是 DSP 全量面板
- 更广义的殖民、跨恒星系长期调度仍未打通

### 6.5 太阳帆 / 戴森球可体验，但部分链路偏实验性

特别是：

- `launch_solar_sail` 依赖 `em_rail_ejector` 本地已装载的 `solar_sail`
- `vertical_launching_silo` 现在能默认生产 `small_carrier_rocket`，但你仍需要自行完成供料或直接用 `transfer` 装填成品火箭
- `launch_rocket` 需要目标层已有 `build_dyson_*` 脚手架
- `build_dyson_*` 命令本身仍更偏系统直连入口

如果你是普通玩家，建议把戴森部分理解为：

- **能体验**
- **能验证系统**
- **但脚手架规划入口仍然比中前期工业闭环更偏实验性**

### 6.6 `orbital_collector` 已有官方验证路线，但不属于普通新局主线

它依赖：

- 当前 active planet 是气态行星

因此：

- 在普通新局里，它仍然未必会自然进入主线
- 但现在已经可以通过官方 midgame 场景稳定验证：启动后 active planet 会直接落在 `planet-1-2` 这颗气态行星上

### 6.7 AI 军事委派已可用，但不是“无限权限自动打仗”

当前 AI 军事委派是真实链路，不再只是设计稿；但它的边界也很明确：

- 真实入口在 `agent-gateway + client-cli runtime`，不是直接把 `/war` 页面变成全自动战争面板
- 你必须先有现成的 `task_force` / `theater`，再通过 `agent_update` 把 `--theater-ids` / `--task-force-ids` 显式委派给 agent
- 只给 `combat` 类别不够；战争命令还必须命中 `--military-command-ids`
- `landing_start` / `blockade_planet` / `queue_military_production` 还会继续受 `--allow-landing` / `--allow-blockade` / `--allow-military-production` 和量产上限约束
- 当前 agent 查询到的 `war_industry` / `task_forces` / `theaters` 仍是玩家全量可见视图；真正的硬限制主要落在“能否对范围内对象下命令”
- `/agents` 页面和 `agent_thread` 现在可以看到 agent 做了什么、为什么这么做、当前战区状态和是否需要玩家批准更高风险动作

## 7. 最实用的三条验证路径

如果你只想知道“第一局大概怎么玩”，可以直接按下面走：

1. 先查当前星球、迷雾、资源点分布
2. `build 3 2 wind_turbine`
3. `build 4 2 tesla_tower`
4. `build 5 1 mining_machine`（压到铁矿 / 铜矿资源点上，初始科技已解锁）

### 机甲

拥有可运行的生产建筑后，在生产指令中选择 `mecha` 可制造星球机甲。机甲会作为星球单位出现，支持移动和攻击，基础属性为 240 生命、28 攻击、12 防御、4 格射程；生产消耗 180 矿物和 80 能量。选中机甲后使用“移动”或“攻击”模式即可操作。


### 玩家机甲核心与护盾

玩家出生时的 `executor` 现在在地图显示为“玩家机甲”，生命 120、攻击 20、防御 8、射程 4 格。核心初始能量 100，每次攻击消耗 8，每移动一格可走路径消耗 1；能源不足时整条操作失败，不会移动或造成伤害。

选中机甲后点“机甲详情”，可查看核心能量、护盾和燃料余能。选择背包中持有的燃料，点“消耗 1 个燃料补能”。CLI 对应 `refuel_mecha <executor_id> <fuel_item_id> <quantity>`。煤提供 25 能量，其他燃料热值由 `/catalog.items[].mecha_fuel_energy` 给出。没有燃料库存会失败；高热值燃料溢出的能量保留为余能，每 tick 最多向核心转入 10。核心已满或还有燃料余能时不用再添加。

研究“机甲核心”每级增加 10 容量，“驱动引擎”每级增加 2 单次移动范围，“能量护盾”每级提供 20 护盾。科技不会直接填满新增容量。护盾优先吸收攻击，最后受击 10 tick 后，每 tick 消耗 1 核心能量恢复至多 2 护盾；能量耗尽则暂停恢复。“研究速度”科技也实际增加研究站矩阵吞吐。

本节描述已实现的核心闭环。飞行、建造无人机、独立燃料仓管理、装备和死亡恢复仍待开发；量产战斗单位 `mecha` 与玩家机甲 `executor` 是不同单位。


### 高级制造与地面防御（2026-09-16 回归）

- 制造台 Mk.II/Mk.III 可生产低级制造台配方，基础加工速度分别为 Mk.I 的 2/3 倍（按整数 tick 向上取整）；齿轮基础加工周期分别为 20/10/7 ticks。升级不会凭空增加物料，只缩短每批时间；高级设施也需要更多电力。
- 导弹塔使用 ammo_missile，聚爆加农炮目前使用 gravity_missile，等离子塔使用 plasma_capsule；激光塔使用电力。使用 transfer_item 装弹或连接输入传送带；缺弹、缺电时停止攻击，补弹后恢复。等离子胶囊由等离子塔科技解锁，三个制造台均能用钛合金1、粒子容器1、氢2生产1个。
- 在水面/熔岩/阻挡地形铺地基后可建厂；界面先选中地基上的工厂。拆工厂后再拆地基会恢复原地形。禁止重复铺地基，地基上有建筑或施工任务时不能拆除；地基本身正在拆除时也不能在其上开工。土壤、批量铺设和矿藏掩埋仍待实现。


### 玩家手动采矿、个人制造与电网充电

选中附近固体矿点，使用“手动采集”把原料送入玩家背包。机甲必须在矿点 2 格球面距离内；每件耗时 10 tick、共耗 10 核心能量。离开范围或能量不足会暂停，回到范围或补能后继续。只可采有限固体矿点，不能手采原油、水或无限资源；请求数量不能超过启动时矿点余量。采出的煤进入背包后即可作为燃料使用，每件煤补充 25 能量。探索和往返也耗能，低电量时先确保有煤或可供电的充电塔。

在“机甲详情”的“个人制造”中选择配方、填写批数并开始。菜单来自服务端 `handcraft_allowed` 标记，目前支持铁锭、铜锭、石砖、磁铁、高能石墨、齿轮、电路板、磁线圈这八种配方；其中受科技限制的配方仍要先研究。启动时会从背包预留全部原料，不会自动制造缺少的中间件。每批耗时见配方，每 tick 消耗 1 核心能量，完成后产物进入背包。“批数”不是件数，例如磁线圈配方每批产出 2 个。

机甲一次只能采矿或制造一个任务。详情显示当前批进度、剩余批数和缺能/超距提示。“取消机甲任务”会退回所有未完成批次的原料，包括尚在加工的那一批；已经完成的产物保留，已耗能量不返还。死亡也会返还未完成制造原料，但尚未实现机甲死亡后的恢复玩法。

CLI 对应：

```text
mine_resource <executor_id> <resource_id> 2
craft_item <executor_id> smelt_iron 1
cancel_mecha_job <executor_id>
```

等待采矿完成或先取消任务后才能启动制造。`resource_id` 是地图返回的矿点 ID；制造使用配方 ID。以上命令的数量必须为正整数。

靠近运行中的自有电塔会自动给核心充电：电力感应塔覆盖 4 格，最高 2 能量/tick；无线输电塔覆盖 6 格，最高 10 能量/tick，自身用电 1/tick。只能使用该连通电网在建筑运行、蓄电器充电后剩余的供电；远处独立发电网和玩家能源余额不能替代塔的电源。比如同网只有 1 台每 tick 发 10 电的风机和无线塔，最多能给机甲充 9。缺电、停塔、离开范围或核心已满时不充；燃料余能仍优先补核心，不会与电网重复填充。

上述功能已有代码与专项测试，默认新局的移动到煤矿、采出煤再补能已通过服务端命令链测试；从寻找矿点、解锁科技到持续供能和制造的完整玩家推进仍需验收。

### 传送带流速与欠压生产

建造流速监测器并接入电网，在详情中绑定相邻自有传送带、设置采样窗口和最低流量。它统计皮带真正流出的物料，完整窗口都积货且没有流出时显示堵塞。低流量可开启告警；停电或拆除目标后会停止采样，恢复后重新积累窗口。关闭告警不会停止监测，重新应用配置会清统计。

普通加工设施按实际获配电力减速：一半供电需要两倍加工时间；对撞机需求24、仅两台各供10的风机时，一批基础120tick反物质需要144加工tick（开批另占一tick）。断电保留当前整数及小数进度，续档后继续。详情里的“标准生产tick”表示剩余工作量，缺电时实际等待更长。

### 仓库配送器与机甲物流

在 `depot_mk1/mk2` 原点建造配送器，配置供给或需求、保有量并安装制造的配送机器人。配送器供电且航程能量足够时才派遣；机器人真实飞行，满仓等待卸货，基地失效保货。行星页可设置机甲补给下限和回收上限，打开对应开关即可自动补给与回收。
