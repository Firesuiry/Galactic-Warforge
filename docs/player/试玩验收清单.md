# 试玩验收清单

> 大版本 / 品质冲刺后的**人类试玩脚本**。目标不是替代自动化测试，而是用固定路径回答：
> **从没看过代码的人，能不能用 GUI 打通开局与一场仗？**
>
> 配套：
> - 启动：[本地环境与测试](../dev/本地环境与测试.md) / `scripts/start-local-playtest.sh`
> - 玩法说明：[玩法指南](玩法指南.md)
> - CLI 对照：本文 §F
> - 命令覆盖：`python3 scripts/command_coverage.py --check`
> - 问题记录：[known-issues.md](known-issues.md)

## 0. 每次开跑前

| # | 检查 | 通过标准 | ☐ |
|---|---|---|---|
| 0.1 | 环境 | `scripts/start-local-playtest.sh` 或等价方式拉起；`/health` 返回 `status=ok` 且 tick 前进 | |
| 0.2 | 登录 | Web 用 `p1 / key_player_1` 登录成功，顶栏出现 tick / minerals / energy | |

| 0.4 | 自动化基线（可选） | `client-web` vitest 绿；`client-cli` npm test 绿 | |

## A. 新局 30 分钟体验路径（`config-dev` + `map.yaml`）

> 全程**优先纯 Web**。CLI 仅在 Web 明确卡住时作对照（§F1），并立刻记入 known-issues。

### A1. 登录与态势可读（≤3 min）

| # | 步骤 | 通过标准 | ☐ |
|---|---|---|---|
| A1.1 | 打开 `/overview` | 能看到 tick、活跃行星、资源摘要；「下一步」类引导可点 | |
| A1.2 | 打开 `/galaxy` | 星图画布可见；可平移/缩放；能进入恒星系 | |
| A1.3 | 打开 `/planet/planet-1-1` | 地图可见基地/迷雾；初始视角能找到基地 | |
| A1.4 | 顶栏资源 | minerals / energy 数字可见且与 summary 一致 | |

### A2. 基建与采矿闭环（≤10 min）

| # | 步骤 | 通过标准 | ☐ |
|---|---|---|---|
| A2.1 | 建造 `wind_turbine`（基地邻格） | 建造卡可选中；点击放置成功；电力 generation > 0 | |
| A2.2 | 电网到矿点 | `tesla_tower` 连到资源带；能选中并放置 `mining_machine` **到资源格** | |
| A2.3 | 矿物产出 | 等待若干 tick 后 minerals 或矿机本地存储上升 | |
| A2.4 | 选中建筑信息 | 侧栏能看到本地存储/运行态，无裸开发者堆栈 | |

### A3. 矩阵产线与科研起步（≤12 min）

| # | 步骤 | 通过标准 | ☐ |
|---|---|---|---|
| A3.1 | 铺矩阵产线 | 冶炼/组装链路可建：磁铁→磁线圈、铁/铜→电路板→电磁矩阵 | |
| A3.2 | 建空 `matrix_lab` | 研究站模式（无 recipe） | |
| A3.3 | 未装料开研 | 「研究与装料」里直接开始研究 → 明确失败反馈（缺矩阵），**不**误报成功 | |
| A3.4 | 装料 | 同一面板把矩阵转入研究站本地存储（`transfer_item`） | |
| A3.5 | 再开研 | `electromagnetism` 进入研究 / 完成后解锁（如 `depot_mk1`） | |
| A3.6 | 产线告警 | 空研究站/空转建筑不持续刷英文噪音 | |

### A4. 中后期入口可发现（≤5 min，有科技再验）

| # | 步骤 | 通过标准 | ☐ |
|---|---|---|---|
| A4.1 | 物流 | 物流站/槽位配置入口在行星命令面可发现 | |
| A4.2 | 戴森相关 | 发射井 / 弹射器 / 戴森脚手架入口在解锁后可发现（不必本局打完） | |
| A4.3 | 切星 | `switch_active_planet` 在多行星可用时有入口 | |

**路径 A 出口标准**：A1–A3 全勾；A4 有科技则勾，否则记「未解锁跳过」。

## D. 失败时怎么记

1. **先复现**：同一场景、同一账号、记下 tick 与操作序列。
2. **记问题**：在 [known-issues.md](known-issues.md) 追加一节（标题 = 短描述；状态、现象、相关代码、修复方向）。一个问题一节，修复后直接删掉。
3. **不要**在清单里堆长讨论；清单只勾选。

## F. CLI 对照路径

坐标随 seed 变化，用 Web 行星页或 `scene` 找位置；`<..._id>` 换成本次实际 ID（`scene` / `inspect` / Web 详情侧栏可查）。

### F1. 新局开荒（对应 A2–A3）

```text
summary                                   # 找基地与附近 iron_ore / copper_ore
build <x> <y> wind_turbine                # 基地正交相邻格
build <x> <y> tesla_tower                 # 把电接到矿格
build <ore_x> <ore_y> mining_machine      # 必须压在资源格上
# 若干 tick 后 minerals 应严格增长；矿机满仓也不停 kickback
# 铺 arc_smelter / assembling_machine_mk1：铁矿→磁铁→磁线圈；铁/铜→电路板；磁线圈+电路板→电磁矩阵
build <x> <y> matrix_lab                  # 不带 --recipe，保持研究站模式
start_research electromagnetism           # 缺矩阵 → 应失败（见 known-issues：当前只进审计日志）
transfer <matrix_lab_id> electromagnetic_matrix 10
start_research electromagnetism           # 成功 → 解锁 depot_mk1
```

- 出生点保证 `iron_ore` + `copper_ore` 在 `operate_range-2`（默认 4）曼哈顿距离内。
- 默认新局只给 `minerals=240`、`energy=100`，不预置矩阵；10 个电磁矩阵必须自产。
- 矿石送去冶炼仍需传送带 / 分拣器 / 仓库。

### F2. 官方 midgame（`config-midgame` + `map-midgame.yaml`）

1. `summary` 确认 `active_planet_id = planet-1-2`；`system sys-1` 确认 `planet-1-2.kind = gas_giant`。
2. `switch_active_planet planet-1-1` 再切回 `planet-1-2`。
3. 补 `tesla_tower` 和 `wind_turbine`，直到 `stats.energy_stats.generation >= 84`（官方 seed 实测：基地 + 1 塔 + 8 风机）。
4. 建 `orbital_collector`、`vertical_launching_silo`、`em_rail_ejector`，用 `inspect planet-1-2 building <id>` 确认 `running`。
5. `transfer <silo_id> small_carrier_rocket 1`、`transfer <ejector_id> solar_sail 3`；用 `build_dyson_node/frame/shell` 建至少一层脚手架。
6. `launch_solar_sail <ejector_id> --count 1`、`launch_rocket <silo_id> sys-1 --layer 0`，事件流应出现 `rocket_launched`。
7. 建 `jammer_tower`、`sr_plasma_turret`、`planetary_shield_generator`、空配方 `self_evolution_lab` 及 `self_evolution_lab --recipe electromagnetic_matrix`；执行体移到 `(7,4)` 附近再建 `recomposing_assembler`(8,6)、`pile_sorter`(8,7)、`advanced_mining_machine`(10,7)。
8. `inspect` 护盾发生器，`runtime.functions.shield.current_charge` 持续上升；`damage_applied` 事件带 `shield_absorbed` / `shield_remaining`。
9. `set_ray_receiver_mode <receiver_id> power`（或 `hybrid`），对照 `summary` / `stats` / `/world/planets/{planet_id}/networks`：`energy`、`generation`、`supply` 同步上涨，`critical_photon` 不再增长（旧库存不清零）。`photon` 需 `dirac_inversion`，场景故意不预置。

### F3. 官方战争局（对应路径 B）

```text
summary                                   # active_planet_id = planet-1-1
war_industry                              # 部署枢纽与补给节点可见
blueprint_variant corvette corvette_verify utility --name 官方回归舰
blueprint_validate corvette_verify
blueprint_finalize corvette_verify --target-state prototype
queue_military_production <recomposing_assembler_id> <battlefield_analysis_base_id> corvette_verify --count 1
war_industry                              # ready_payloads 出现 corvette_verify
commission_fleet <battlefield_analysis_base_id> corvette_verify sys-1 --fleet-id fleet-verify
task_force_create tf-verify --name 官方验证群 --stance escort
task_force_assign tf-verify fleet fleet-verify --system sys-1 --planet planet-1-1
task_force_deploy tf-verify --system sys-1 --planet planet-1-1
theater_create theater-verify --name 官方战区
theater_define_zone theater-verify primary --system sys-1 --planet planet-1-1 --x 10 --y 10 --radius 8
theater_set_objective theater-verify secure_planet --system sys-1 --planet planet-1-1 --description 官方战争闭环
fleet_status fleet-verify
task_forces
theaters                                  # 区域有敌方实体时 hostile_count / alerted，并推 theater_zone_alert
blockade_planet tf-verify planet-1-1
system_runtime sys-1                      # planet_blockades 进入运行态
planet_runtime planet-1-1
```

场景预置科技、军工底座和补给节点，但不会替你创建舰队、任务群和战区。`blockade_planet` 的同步返回只表示入队。

### F4. AI 军事委派（需 agent-gateway，先完成 F3）

```text
agent_update agent-war-director --command-categories observe,combat,management \
  --theater-ids theater-verify --task-force-ids tf-verify \
  --military-command-ids system_runtime,task_force_set_stance,task_force_deploy \
  --allow-blockade false --allow-military-production false --military-production-limit 0
agent_message agent-war-director 接管 theater-verify，并让 tf-verify 在战区内维持巡逻，汇报当前局势。
agent_thread agent-war-director           # 看实际动作、理由、是否需要批准
```

再用 `task_forces`、`theaters`、`system_runtime` 对账结果。

### F5. Case1 委派建造（需可用 provider）

```text
agent_create 李斯 --id agent-lisi --provider provider-case1 --role director --can-create-agents true \
  --command-categories observe,build,combat,research,management --planet-ids planet-1-1
agent_message agent-lisi 创建胡景，并赋予其建筑权限
agent_list                                # 出现 agent-hujing
agent_message agent-lisi 新建一个矿场
agent_thread agent-lisi                   # 有 agent.create / conversation.send_message 等真实 tool 证据
```

实际 `build` 应由胡景经 `agent-gateway -> client-cli runtime -> /commands` 发出，而不是李斯直接建造。
